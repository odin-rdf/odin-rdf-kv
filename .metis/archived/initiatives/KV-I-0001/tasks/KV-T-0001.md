# Types, platform layer and on-disk structs

## Parent Initiative

[[KV-I-0001]]

## Objective

Lay the foundation of the `kv` package: the shared types, the on-disk struct layouts (page header, leaf and branch node headers, meta page) with the xxHash64 meta checksum, and a small platform layer for macOS and Linux that the rest of the code calls instead of using `core:sys/posix` directly.

## Acceptance Criteria

- [x] The `kv/` package directory exists and builds with `odin build kv -build-mode:lib` (or `odin check kv`) on macOS.
- [x] `types.odin` defines:
  - `Pgno :: distinct u64` and `Txn_Id :: distinct u64`;
  - the `Error` enum: `None`, `Not_Found`, `Map_Full`, `Key_Too_Large`, `Corrupted`, `Io`, `Txn_Read_Only`, `Locked`;
  - `MAGIC`, `VERSION`, page flags (`BRANCH`, `LEAF`, `OVERFLOW`, `META`) and node flags (`BIGDATA`).
- [x] The on-disk structs (`Page_Header`, `Leaf_Node_Header`, `Branch_Node_Header`, `Meta`) use only `u16le`, `u32le` and `u64le` fields. `#assert`s pin their sizes and field offsets.
- [x] `meta_checksum(^Meta) -> u64` uses `xxhash.XXH64` over every byte before the `checksum` field.
- [x] The platform layer provides:
  - `os_open(path, create) -> (fd, Error)`, including an exclusive non-blocking `flock`; failure to lock returns `Locked`;
  - `os_close`, `os_file_size`, `os_truncate`, `os_pread`, `os_pwrite`;
  - `os_sync`: `F_FULLFSYNC` on Darwin, falling back to `fsync` if the filesystem returns `ENOTSUP`; `fdatasync` on Linux;
  - `os_map_reserve(fd, map_size) -> (base, Error)`: `PROT_READ`, `MAP_SHARED`;
  - `os_unmap`, and `os_advise_random` (`MADV_RANDOM`).
- [x] A smoke test in `tests/` maps a temporary file, `pwrite`s a page, and reads the same bytes back through the map. This proves the map stays coherent with `pwrite`.

## Implementation Notes

### Technical Approach
- **Platform split:** use `os_darwin.odin` and `os_linux.odin` with file-name build tags, and a shared `os_posix.odin` for the calls that are identical on both.
- **Missing constants:** where `core:sys/posix` lacks something (`F_FULLFSYNC`, `MADV_RANDOM` versus `POSIX_MADV_RANDOM`), use `core:sys/darwin` or `core:sys/linux`, or declare it locally with a comment.
- **Default page size is 4096 bytes,** whatever the OS page size (Apple Silicon uses 16 KiB OS pages).
  - Valid page sizes are powers of two from 4 KiB to 32 KiB, because slot offsets and `upper` are `u16`.
  - The page size is stored in the meta page, and only the map base needs OS-page alignment.
- **Page header layout:** `pgno: u64le`, `flags: u16le`, 2 reserved bytes, then a `#raw_union` of `lower: u16le` + `upper: u16le` with `overflow_count: u32le` (16 bytes in total). The reserved bytes come before `lower`/`upper` so that the union starts at a 4-byte-aligned offset (12).
- **Meta:** stored in a page with a `Page_Header` (flags `META`), followed by the `Meta` struct.

### Dependencies
None. This is the first task.

### Risk Considerations
- **`F_FULLFSYNC` availability:** it is only honoured by some filesystems. Fall back to `fsync` and note it in the code.
- **Coherence between `pwrite` and the mmap:** this is assumed by the whole design. The smoke test verifies it early on the development platform.

## Status Updates

### 2026-09-24: completed
- **Files added:** `kv/types.odin`, `kv/page.odin`, `kv/meta.odin`, `kv/os_posix.odin`, `kv/os_darwin.odin`, `kv/os_linux.odin`; tests in `tests/` (package `kv_tests`, importing `../kv`).
- **Verification:**
  - `odin check kv -no-entry-point -vet -strict-style` is clean for `darwin_arm64`, `darwin_amd64`, `linux_arm64` and `linux_amd64`, and `odin build kv -build-mode:lib` succeeds.
  - `odin test tests -vet -strict-style` passes all 7 tests on macOS (arm64) with `-debug`, `-o:speed` and `-debug -sanitize:address`.
  - The test package also type-checks for `linux_arm64`. Running the tests on Linux is left to the KV-T-0009 build matrix.
- **The coherence smoke test confirms, on macOS,** that data written with `pwrite` is visible through the read-only `MAP_SHARED` mapping in three cases: a fresh page, a rewrite of a page already read through the map, and a page beyond the end of the file at the time it was mapped (after `ftruncate`).
- **Decisions and deviations:**
  - Page header field order changed: see Technical Approach. The initiative's Detailed Design was updated to match.
  - **Locking:** `flock(LOCK_EX | LOCK_NB)` is bound directly from libc, since `core:sys/posix` doesn't provide it. It was chosen over `fcntl` record locks because those are per-process: a second open in the same process wouldn't conflict, and closing any descriptor would release the lock.
  - **`os_sync` on Darwin** falls back to `fsync` on *any* `F_FULLFSYNC` failure, not only `ENOTSUP`, because filesystems report other errors (such as `EINVAL` and `ENOTTY`). A real I/O error still surfaces through `fsync`. `F_FULLFSYNC` (51) is declared locally.
  - **Readahead** is turned off with `posix_madvise(POSIX_MADV_RANDOM)`, which is equivalent to `MADV_RANDOM` on both platforms.
  - **Missing file:** `os_open(create = false)` on a missing file returns `Io`.
  - **Internal visibility:** internal procedures (`os_*`, `page_header`, `page_meta`, `meta_checksum`) are exported so the separate test package can reach them. Revisit visibility once the public API exists.

### 2026-09-24: alignment follow-up
- **64-bit only:** added `#assert(size_of(int) == 8)` in `types.odin`. `odin check -target:linux_i386` now fails with "kv requires a 64-bit target".
- **Debug alignment asserts:** `page_header` and `page_meta` assert buffer alignment in debug builds, which means they are no longer `"contextless"`. A throwaway program in the scratchpad confirmed that a misaligned buffer triggers the assert.
- **Test buffers:** added `Page_Buf` (`#align(16)`) to `tests/helpers.odin`. `test_page_accessors` uses it; a plain `[N]byte` is only 1-byte aligned, so casting it was undefined behaviour.
- **Unpadded values:** decided with the user. Inline values stay unpadded and have no alignment guarantee. Recorded in the initiative's "Byte order and alignment" section.
- **Re-verified:** checks for all four 64-bit targets are clean, and the 7 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address`.
