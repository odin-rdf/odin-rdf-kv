# Write path: write transactions, copy-on-write touch, insert and splits

## Parent Initiative

[[KV-I-0001]]

## Objective

Implement write transactions up to, but not including, commit: the writer mutex, dirty-page storage behind a small interface, page allocation, top-down copy-on-write touching, and `put` with insert, overwrite, and leaf, branch and root splits.

## Acceptance Criteria

- [x] **`txn_begin(env, read_only = false)`:** takes the writer mutex and copies the snapshot. `txn_abort` on a write transaction frees the dirty state and releases the mutex.
- [x] **Dirty storage interface:** `dirty_get(txn, pgno) -> ([]byte, bool)`, `dirty_put(txn, pgno, buf)` and `dirty_reset(txn)`, backed by a `map[Pgno][]byte` plus a per-transaction `virtual.Arena`. No other code touches the map or the arena directly.
- [x] **`page_ptr` in write transactions** checks `dirty_get` first.
- [x] **`page_alloc(txn, n) -> (Pgno, Error)`:**
  - returns `last_pgno + 1` and advances `last_pgno` by `n`;
  - returns `Map_Full` if `(last_pgno + n + 1) * page_size > map_size`;
  - the new page is registered as dirty.
- [x] **`page_touch(txn, path, level)`:**
  - if the page is already dirty, do nothing;
  - otherwise allocate a page number, copy the page, fix up the parent's child pointer (the parent was touched first), and update `path`.
- [x] **`put(txn, key, val) -> Error`:**
  - returns `Txn_Read_Only` on a read-only transaction and `Key_Too_Large` above `max_key_size`;
  - an empty tree creates the root leaf;
  - an existing key is overwritten, in place if the size is the same, otherwise by remove and insert;
  - a full leaf splits, cascading to branches and to a new root;
  - `entries` is updated;
  - values at or above the overflow threshold return an error until KV-T-0006 lands.
- [x] **`get` inside a write transaction** sees the transaction's own changes.
- [x] **Tests (all inside a single write transaction, since commit is KV-T-0007):**
  - 50k ascending, descending and random inserts, then every key read back with `get`;
  - the tree depth grows as expected;
  - overwrites with larger, smaller and equal-size values;
  - maximum-size keys force splits with 4 keys per branch;
  - a zero-length key works;
  - after `txn_abort`, the env snapshot is unchanged and a new read transaction sees the old tree;
  - with a tiny `map_size`, `put` returns `Map_Full`;
  - debug `page_check` passes on every dirty page after each operation.

## Implementation Notes

### Technical Approach
- **Split procedure:**
  1. Allocate the right sibling and choose the split point by bytes (`split_point`).
  2. Move the upper half of the nodes across.
  3. Insert the pending node into whichever half it belongs to.
  4. Insert the separator (the right page's first key) into the parent, and recurse if the parent is full.
  - **Branch split:** the middle node moves up; its child becomes the right page's slot 0, stored with an empty key.
  - **Root split:** allocate a new branch root `[−∞ → left, sep → right]` and increment the depth.
- **Copy-on-write:** pages replaced by copy-on-write are simply abandoned; the free list arrives in step 5. Keep a `freed: [dynamic]Pgno` in the transaction anyway, filled but not yet used, so step 5 only has to consume it.
- **Dirty page alignment:** allocate dirty page buffers from the arena with page-size alignment (`virtual.arena_alloc(&arena, size, page_size)`), not the default 16-byte alignment. The debug assert in `page_header` checks this.
- **Rule for write-transaction slices:** a slice returned by `get` in a write transaction is invalidated by the next `put`. Document this in the `get` doc comment.

### Dependencies
- KV-T-0004 (`Txn`, `page_ptr`, tree search and `Path`).

### Risk Considerations
- **Splits are the most bug-prone code in the project.** Mitigate with the `page_check` invariant checker after every change, and a debug `tree_check(txn)` that walks the whole tree. It verifies key order across pages, that branch separators bound their subtrees, that all leaves sit at the same depth, and that the `entries` count matches.

### 2026-09-24: completed
- **Files:**
  - `kv/write.odin` (new): `page_alloc`, `page_touch`, `put`, split and insert;
  - `kv/check.odin` (new): `tree_check`;
  - `kv/txn.odin` reworked for write transactions;
  - `MAX_KEY_SIZE_ANY` added in `page.odin` and `Error.Out_Of_Memory` in `types.odin`;
  - `tests/write_test.odin` (10 new tests).
- **Verification:**
  - All 49 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64; checks for the other targets are clean.
  - Four deliberate bugs were each caught: separator inserted before the left child, branch split keeping slot 0's key, touch not repointing the parent, and no up-front map check.
  - A fifth change, always moving from `split` rather than `split − 1`, is *not* a bug: the new node's half keeps one extra node, which still fits because every node is at most a quarter of a page. It merely changes the balance.
- **Design decisions and deviations:**
  - **Write state on the heap:** `Write_State { arena, dirty, freed }` is allocated with `env.allocator` in `txn_begin`, not embedded in `Txn`. `Txn` is returned by value, and the dirty map's allocator points at the arena, so an embedded arena would dangle once `txn_begin` returned. `Txn.write` is non-nil exactly for write transactions.
  - **Dirty storage** is a `map[Pgno][]byte` plus a `[dynamic]Pgno` freed list, both allocated from the arena. It is accessed directly (`txn.write.dirty`) rather than through the `dirty_get`/`dirty_put`/`dirty_reset` wrappers from the task text. The whole write state is private to `write.odin` and `txn.odin`, which is where step 6 will make its changes.
  - **Dirty page alignment:** buffers are allocated page-aligned with `virtual.arena_alloc(&arena, n * ps, ps)`, as the alignment decision requires (tested).
  - **`Map_Full` is checked up front:** before changing anything, `put` checks that `2 × depth + 1` more pages fit (worst case: copy every page on the path, split every level, add a new root). So `Map_Full` always leaves the transaction unchanged and usable (tested). The check is conservative: a put that would have fitted can still get `Map_Full` near the limit.
  - **Poisoning:** any failure after `put` has started changing the tree (`Out_Of_Memory`, or `Corrupted` from `tree_search`) is stored in `txn.err`. Every later `put` returns it, and KV-T-0007's commit must refuse to commit a poisoned transaction. Argument errors (`Key_Too_Large`, `Invalid_Argument`, `Txn_Read_Only`) don't poison.
  - **New error** `Out_Of_Memory`, for arena allocation failure (added to the vision's error list).
  - **Values needing overflow pages** return `Invalid_Argument` until KV-T-0006. `len(value) > max(u32)` also returns `Invalid_Argument`.
  - **Aliasing restriction:** the key and value passed to `put` must not point into this transaction's dirty pages, for example a slice returned by `get` in the same write transaction, because inserting moves bytes within those pages. This is documented on `put`. LMDB has a similar caveat; there's no cheap check.
  - **Splits cascade in a loop**, not by recursion, with one `[MAX_KEY_SIZE_ANY]byte` stack buffer (8170 bytes) for the separator. After a split the separator is always the right page's first key. On branch pages that node is then re-keyed to −∞ (`node_remove` plus `branch_insert` with a nil key), following KV-T-0003's split protocol.
  - **`Txn` gained** `mods` (bumped on every put, for KV-T-0008's cursor invalidation) and `err`.
- **Test finding:** only the copy-on-write test (a committed base tree from `build_tree_file`, then puts) exercises `page_touch` copying committed pages. Tests that start from an empty tree inside one transaction only ever touch pages that are already dirty. Keep a committed-base case in any future write-path test.
