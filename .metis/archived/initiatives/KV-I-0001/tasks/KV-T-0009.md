# Model-check, snapshot-isolation and zero-allocation tests

## Parent Initiative

[[KV-I-0001]]

## Objective

Verify the initiative end to end. Compare the store against an in-memory oracle over randomized workloads with reopens in between, verify snapshot isolation between readers and a concurrent writer, and prove that reads are zero-copy and allocate nothing. Close out the initiative's exit criteria on macOS and Linux.

## Acceptance Criteria

- [x] **Model check:** a seeded random workload of at least 10⁵ operations against a `map[string][]byte` oracle.
  - Mix: `put` with small, maximum-size and overflow values; overwrites; `get` hits and misses; `seek` and `next` range scans; full forward and backward scans.
  - Commit every k operations (k chosen at random); abort some transactions; close and reopen periodically.
  - After each commit or reopen, compare every key and value plus both full scans against the oracle.
  - On failure, print the seed.
- [x] **Snapshot isolation:**
  - open reader R1, then have the writer commit N transactions;
  - R1's `get`s and scans still match the oracle state from when R1 began;
  - a new reader R2 sees the latest state;
  - also run with readers on separate threads during the commits (no data races under `-sanitize:thread` where supported).
- [x] **Zero-copy and zero allocation:** under a `mem.Tracking_Allocator`, `get` and every cursor operation in a read transaction allocate nothing. Every returned slice lies within `[map_base, map_base + map_size)`.
- [x] **Map full:** covered end to end: fill, hit `Map_Full`, abort, reopen, verify against the oracle.
- [x] **Build matrix:** the whole suite passes with `-debug`, `-o:speed` and `-sanitize:address` on macOS, and with `-debug` and `-o:speed` on Linux (in a container or a CI job).
- [x] **Initiative exit criteria** are checked off in KV-I-0001: REQ-001 to REQ-009 and NFR-001 to NFR-005.

## Test Cases

### Test Case 1: Randomized model check with reopen
- **Test ID:** TC-001
- **Preconditions:** a fresh temporary database with `map_size` of 1 GiB.
- **Steps:**
  1. Run 10⁵ random operations with random commit and abort boundaries, and reopen every 10⁴ operations.
  2. After each commit or reopen, compare the full contents and both scan directions with the oracle.
- **Expected results:** no mismatches; `tree_check` passes after every commit.

### Test Case 2: Snapshot isolation across threads
- **Test ID:** TC-002
- **Preconditions:** a database with 10⁴ keys committed.
- **Steps:**
  1. Start 4 reader threads, each holding one read transaction and repeatedly scanning.
  2. The writer commits 100 transactions that modify and add keys.
  3. Readers compare what they see against the frozen oracle copy from when they started.
- **Expected results:** every reader always sees its own snapshot; a new reader after the writer finishes sees the final state.

### Test Case 3: Reads allocate nothing
- **Test ID:** TC-003
- **Preconditions:** a populated, committed database.
- **Steps:**
  1. Install a tracking allocator as `context.allocator` and `context.temp_allocator`.
  2. Run 10⁴ `get`s and a full cursor scan.
- **Expected results:** zero allocations recorded; every slice lies inside the map range.

## Implementation Notes

### Technical Approach
- **Where the tests live:** in `tests/model_test.odin`, `tests/isolation_test.odin` and `tests/alloc_test.odin`. Use `core:math/rand` with an explicit seed that can be overridden through an `-define:SEED=` build flag, so failures can be reproduced.
- **Structural check:** reuse `tree_check` from KV-T-0005 after every commit in the model check.

### Dependencies
- KV-T-0006, KV-T-0007 and KV-T-0008. Everything else in the initiative must be complete.

### Risk Considerations
- **Randomized tests can hide rare failures.** Run the model check with several fixed seeds in CI, plus one random seed that is printed on every run.

## Status Updates

*To be added during implementation*

### 2026-09-24: completed
- **Files:**
  - `tests/model.odin`: the model infrastructure;
  - `tests/model_test.odin`: TC-001 plus a variant that runs until the map fills;
  - `tests/isolation_test.odin`: TC-002;
  - `tests/alloc_test.odin`: TC-003.
  - That brings the suite to 79 tests.
- **Model design:**
  - The key space is fixed (ids `0..<n`). Key bytes are derived from the id: 5% maximum-size (1002 bytes), 15% medium (100–300 bytes), the rest 8 bytes in scrambled order.
  - Keys are precomputed and sorted once. The model stores only `(present, version, size)` per id, and values are regenerated from `(id, version, size)`. So the model holds no bytes, and a transaction boundary just copies a small array.
  - `model_diff` (usable from any thread) checks the entry count, `get` for every id (present and absent), full forward and backward cursor scans, and `tree_check`. `model_compare` wraps it for the test thread.
- **Run statistics for TC-001** (one seed): 44,932 puts, 4,410 of them overflow; 29,925 gets; 25,143 range scans; 346 commits; 63 aborts; 9 reopens; about 10 s in a debug build.
  - The test asserts minimums (puts, overflow puts, commits, aborts, reopens) so it can't silently stop covering these.
- **Map full, end to end:** `test_model_until_map_full` runs the model workload with an 8 MiB map until `Map_Full`, then aborts, reopens and compares with the last committed model state. It hit `Map_Full` after 19 commits.
- **TC-002:** each of the 4 reader threads did 21 full scans (8 under ThreadSanitizer) while the writer made 100 commits. None saw a change. A new reader afterwards matches the final model.
- **TC-003:** 10,000 gets, full scans in both directions and 1,000 seek/next/prev rounds over 3,000 keys (10% overflow values) made 0 allocations, and every slice lies inside the map.
- **Build matrix (all 79 tests pass everywhere):**

  | Platform | Builds |
  |---|---|
  | macOS arm64 | `-debug`, `-o:speed`, `-debug -sanitize:address` |
  | macOS arm64, isolation test only | `-sanitize:thread`: no reports. A deliberate race in a scratch program confirmed ThreadSanitizer is active. |
  | Linux arm64 (Ubuntu 24.04 container, Odin `dev-2026-09`, same commit `a2fb372`) | `-debug`, `-o:speed` |
  | Linux amd64 (same, emulated) | `-debug`, `-o:speed` |

  - The model and isolation tests also passed with `ODIN_TEST_RANDOM_SEED` set to 11, 222 and 3333.

  - **Kill-during-commit crash testing** remains out of scope (step 7), as planned.
- **Checking the model test catches bugs:** a planted bug (overwrite in place ignoring an old overflow value) was caught by the model test, the isolation test and a targeted overflow test.
