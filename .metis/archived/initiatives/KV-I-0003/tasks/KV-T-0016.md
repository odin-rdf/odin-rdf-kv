# Page-level merge primitives and page_free

## Parent Initiative

[[KV-I-0003]]

## Objective

Give the page layer what `del` needs to merge and drop pages (KV-I-0003 D2, D4, D6, D8), so that KV-T-0017 only has to decide *when* to merge, not how. Nothing calls these from `del` yet.

## Acceptance Criteria

- [x] A merge primitive in `page.odin` moves all of `src`'s nodes into `dst`, either after `dst`'s nodes (a right sibling) or before them (a left sibling), and leaves `dst` compacted. `src` is not modified (the caller frees it). It rebuilds through a stack `Page_Scratch`, as `page_move_upper` does, and allocates nothing.
- [x] For branch pages, the merge takes the separator key for the right-hand page's slot-0 node (−∞ until now), and that node gets the key on the way (D6). The caller passes a copy of the key, not a slice into the parent.
- [x] A procedure makes a branch page's slot 0 −∞ after its first node was removed: the new first node keeps its child and loses its key.
- [x] `page_underfull(page)`: `page_used < (page_size − PAGE_HEADER_SIZE) / 4` (D4).
- [x] A fit test: whether two pages (plus the separator a branch merge brings down) fit in one page, exact at the boundary. The merge asserts it.
- [x] `page_free(txn, pgno)` (D8): a dirty page leaves `dirty` and goes to `loose`, any other goes to `freed`. `overflow_free` uses the same rule through it, or a shared helper, and its behaviour doesn't change.
- [x] Tests in `tests/page_test.odin`, each followed by `page_check`:
  - leaf merge from the right and from the left, keys in order, values intact (inline and `BIGDATA` nodes);
  - branch merge from the right and from the left, with the separator brought down onto the right page's first node and the children intact;
  - making slot 0 −∞;
  - the fit test one byte either side of the boundary, for leaves and branches;
  - `page_underfull` either side of the threshold.
- [x] Deliberate-bug check: bring no separator down in a branch merge, or skip clearing slot 0's key, and a test fails. Record it here.
- [x] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- The merged sequence is `left ++ right` in both directions. Only which buffer is the destination differs, so one procedure with a side flag (or two thin wrappers) over a shared rebuild should do.
- A branch's slot-0 node is stored with an empty key, so bringing the separator down changes that node's size: rebuild it with `branch_insert` semantics rather than copying its raw bytes.
- Clearing slot 0: `node_remove` then `branch_insert(page, 0, nil, child)`, as the split code already does for the right page.
- Whether `del` lives in `write.odin` or a new `delete.odin` is decided in KV-T-0017; these primitives belong in `page.odin` (the page ones) and next to `page_alloc` (`page_free`).

### Dependencies
None. First task of KV-I-0003.

### Risk Considerations
- Clone before modifying: the separator is a key in the parent, and the parent changes right after the merge. The primitive takes a caller-owned copy.
- The fit test must count the separator's full node size (`branch_node_size(len(sep)) − branch_node_size(0)`), not just its bytes, or a merge could overflow the page.

## Status Updates

### 2026-09-24: done

**What was built:**
- `page.odin`: `page_underfull`, `page_merge_fits(a, b, sep_len)`, `page_merge(dst, src, src_left, sep)` and `branch_clear_first_key`, all exported like the split helpers, and allocation-free (the merge rebuilds through a stack `Page_Scratch`, like `page_move_upper`).
- `write.odin`: `page_free(txn, pgno, count := 1)`, private, next to `page_alloc`. `overflow_free` now calls it with the run's length; its behaviour is unchanged (the whole suite passes, including the overflow and reuse tests).

**Decisions:**
- One `page_merge` with a `src_left` flag rather than two wrappers: the merged sequence is always left then right, and only which buffer receives it differs.
- The fit test takes the separator's length and ignores it for leaves, so `del` can call it the same way at every level. For a branch the right page's slot-0 node grows from `branch_node_size(0)` to `branch_node_size(len)`, which is exactly `len` bytes, so the test is `used(a) + used(b) + sep_len ≤ usable`.
- `page_merge` asserts the fit; it doesn't return a bool. Callers check `page_merge_fits` first, as the rebalance loop must decide before it touches anything.
- `src` is only read, never written, so it can be a page in the read-only map: `del` frees the sibling without copying it (D2).
- `page_free` stays private: it's tested through `overflow_free` now and through `del` in KV-T-0017.

**Tests** (`tests/page_test.odin`, five new, 114 in the suite): `test_page_merge_leaf` (both directions, a `BIGDATA` node carried over, source page byte-identical afterwards, an empty source), `test_page_merge_branch` (both directions, separator brought down, children in order), `test_branch_clear_first_key` (page_check fails before the clear and passes after), `test_page_merge_fits_boundary` (two leaves filling exactly one page merge to zero free space; one byte more doesn't fit; leaves ignore the separator; a branch separator exactly filling the gap fits and one byte longer doesn't), `test_page_underfull` (empty; one byte under a quarter; exactly a quarter).

**Deliberate-bug checks**, each failing a test, then restored:
- no separator brought down in a branch merge → `test_page_merge_branch` (page_check: keys not strictly increasing);
- `branch_clear_first_key` doing nothing → `test_branch_clear_first_key` (page_check: branch slot 0 must have an empty key);
- the fit test ignoring the separator → `test_page_merge_fits_boundary`;
- the threshold as `≤` instead of `<` → `test_page_underfull`.

`scripts/test.sh` passes (debug, speed, ASan, the four cross-checks).
