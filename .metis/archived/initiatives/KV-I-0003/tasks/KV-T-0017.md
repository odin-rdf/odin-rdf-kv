# del: removal, rebalancing and root collapse

## Parent Initiative

[[KV-I-0003]]

## Objective

Implement `del(txn, key) -> Error` as designed in KV-I-0003 (REQ-001 to REQ-008, D1 to D8): search, check `Map_Full`, touch the path, remove the node and its overflow run, rebalance upwards, collapse the root.

## Acceptance Criteria

- [x] `del` exists with a contract comment covering the lifetime rules (REQ-007, REQ-008), `Map_Full` at a full map, and the two iteration patterns (delete everything with `cursor_first`, delete a range by copy + `del` + `cursor_seek`).
- [x] REQ-001: a missing key returns `Not_Found` with no page touched, `txn.mods` unchanged, `txn.err` unset.
- [x] REQ-002: `Txn_Read_Only`; an earlier `txn.err` is returned; a failure after changes starts sets `txn.err`.
- [x] REQ-003: an overflow value's run is freed, to `loose` if this transaction wrote it, else to `freed`.
- [x] REQ-004/D4/D5: the rebalance loop from the leaf to level 1: drop an empty page (making the parent's slot 0 −∞ when needed), else stop unless underfull, else merge with the right sibling, then the left, if they fit; stop at the first level with no change.
- [x] REQ-005: a root branch with one child collapses (repeatedly); deleting the last key gives `root = 0`, `depth = 0`, `entries = 0`; `entries` drops by one per delete.
- [x] REQ-006/D2: `Map_Full` up front unless `depth` single pages are available; merges allocate no page.
- [x] Shape tests in a new `tests/delete_test.odin`, on committed trees from `build_tree_file`, with `tree_check` and `space_check` after each commit:
  - delete leaving the leaf above the threshold;
  - merge with the right sibling; with the left sibling (rightmost child);
  - underfull page whose siblings are too full (no merge);
  - branch merge with the separator brought down;
  - empty leaf under a single-child parent (cascade);
  - cascade to a root collapse, and collapse over several single-child levels;
  - delete the last key;
  - an overflow value from a committed tree and one written in the same transaction.
- [x] Semantics tests: `Not_Found` changes nothing and a cursor stays valid; `Txn_Read_Only`; `Map_Full` at a full map with no free pages and success with some; deleting a key obtained from `get` and from a cursor in the same transaction; delete-everything through `cursor_first`; abort after deletes leaves the database and `Env.free` unchanged; reopen after deletes.
- [x] Deliberate-bug checks, each failing a test (record which): forget to free the merged sibling; no separator brought down; skip clearing slot 0; skip dropping an empty page without a sibling; forget `entries -= 1`; skip freeing the overflow run; touch the path before the search on a miss.
- [x] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- Mirror `put`: a public `del` with the checks, and a private `del_unchecked` whose error is stored in `txn.err`.
- The path from `tree_search` already has the parent slot index at every level, so a sibling is `branch_child(parent, idx ± 1)`. After merging with a left sibling, point the left slot at the path page and remove the path page's slot; after a right sibling, remove the right slot.
- Keep a stack buffer (`MAX_KEY_SIZE_ANY`) for the separator, copied from the parent before the parent changes.
- The sibling is read through `page_ptr` (committed or dirty) and freed with `page_free`; it is never touched.
- Decide here whether `del` goes in `write.odin` or a new `delete.odin`, and update the code map in `CLAUDE.md`.

### Dependencies
KV-T-0016 (merge primitives, `page_free`).

### Risk Considerations
- A sibling that is dirty must go to `loose`, not `freed`, or `space_check` finds it owned twice.
- Collapsing the root frees a dirty page (the root was touched), so it goes to `loose`.
- An empty root leaf must become `root = 0`; `put` already handles an empty tree by allocating a new root.

## Status Updates

### 2026-09-24: implemented, 16 tests green; mutation checks next

- `del` is in a new `kv/delete.odin` (`del`, `del_unchecked`, `rebalance`, `sibling`, `parent_remove`, `root_collapse`). `pages_available` became `@(private)` so it can call it.
- `tests/tree_helpers.odin` gained `build_tree_shape(leaves, levels)`: every leaf's entries and the grouping of each level are given, so underfull pages and single-child branches can be built. `build_tree_file` shares its file-writing code (`tree_file_write`).
- **Bug found in `txn_commit`:** it treated "no dirty pages" as "changed nothing". A delete that empties the tree frees every page it copied (dirty pages go to `loose`), so it leaves nothing dirty, and that commit was silently dropped (`test_del_last_key`: the last batch's snapshot never published). The commit is now skipped only when `mods == 0` and nothing is dirty.

### 2026-09-24: done

**Decisions and deviations from the design:**
- **The separator is read in place, not copied to a stack buffer** (D6 said it would be). `page_merge` only reads the parent, and the parent changes only after the merge, so there is nothing to protect. Clone-before-modify still holds: nothing reads `sep` after the parent changes.
- **`txn_commit` counts changes, not dirty pages** (the bug recorded above). The skip condition is `mods == 0 && len(dirty) == 0`.
- **At a full map, reusable pages only go so far.** Each delete copies its path out of the reusable pages, and the pages it frees wait for later commits (KV-I-0002 D1). So a transaction at a full map deletes until those run out, then gets `Map_Full` with the transaction still usable. `test_del_map_full` shows it (44 deletes in its setup). This follows from the design; it's recorded here because "a full map with free pages still accepts deletes" (REQ-006) means *some* deletes per transaction.
- **`del` doesn't set `txn.err` when the search itself fails** (`Corrupted`): nothing has changed yet. `put` does set it, because its search runs inside `put_unchecked`.
- A sibling is checked on the way in like a page `tree_search` reaches (`page_check_header`, page number in range), returning `Corrupted` otherwise.
- **Test helpers:** `build_tree_shape` (above), and the builders' page buffers are now 16-aligned (`page_buf_make`). A byte slice from the temp allocator isn't, and the debug build's `page_header` assert caught it in two shape tests. `build_tree_file` had the same latent problem and was only saved by what happened to be allocated before it.

**Tests** (`tests/delete_test.odin`, 16 tests, 130 in the suite):
- shapes: `no_merge`, `merges_right_sibling` (a middle page prefers its right sibling; the left one isn't touched), `merges_left_sibling` (the rightmost page; the left slot keeps its separator and points at the merged page), `no_merge_when_siblings_full`, `branch_merge` (the root's separator brought down; three children to two, depth unchanged), `branch_merge_left_collapses_root`, `drops_empty_first_leaf` (the root's new slot 0 becomes −∞; the next leaf isn't copied), `drops_empty_leaf_under_single_child_parent`, `collapses_several_levels` (depth 4 → 2), `last_key` (3,000 keys with overflow values, deleted in random order over 10 commits, then regrowth), `overflow_value` (freed vs. loose);
- semantics: `not_found_changes_nothing` (no dirty page, `mods` unchanged, the cursor still valid; stale after a real delete), `read_only`, `map_full`, `key_from_same_txn` (a value from `get` used as a key; the range and delete-everything patterns from `del`'s comment), `abort_and_reopen`.
- `tree_check` and `space_check` run on every transaction before commit, and on a new reader after it.
