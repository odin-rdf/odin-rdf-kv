# Dirty-page pool with a fixed budget

## Parent Initiative

[[KV-I-0004]]

## Objective

Replace the write transaction's per-transaction arena for dirty pages with a pool of page slots, fixed at open and owned by the `Env` (KV-I-0004 D1). This task gives the pool and its limit; spilling (KV-T-0021) makes the limit invisible to callers. Until then, a transaction needing more slots than the pool has returns `Out_Of_Memory`.

## Acceptance Criteria

- [x] `Options.dirty_budget` in bytes: 0 means the default, `DEFAULT_DIRTY_BUDGET` = 4 MiB. Rounded up to whole pages. Less than `(2 × MAX_DEPTH + 1)` pages returns `Invalid_Argument` from `env_open`.
- [x] `env_open` reserves the pool's address space once (no physical memory); `env_close` releases it.
- [x] A slot is committed when first used. When the write transaction ends (commit or abort), every committed slot is released with the method KV-T-0019 found to drop the resident size at once (expected: `MADV_DONTNEED` on Linux; on macOS an anonymous `MAP_FIXED` remap or `MADV_FREE_REUSABLE`). Not `virtual.decommit`, which uses the lazy `MADV_FREE`.
- [x] `Write_State.dirty` maps a page number to a slot. An overflow run (still a dirty buffer until KV-T-0021) takes consecutive slots, so the pool hands out contiguous ranges.
- [x] `page_ptr`, `page_touch`, `page_alloc`, `page_free`, `overflow_value` and `txn_commit` work through slots; behaviour is otherwise unchanged. `Write_State.arena` keeps the page lists (`freed`, `loose`, `taken`) and the dirty map.
- [x] Pages stay page-aligned (16-aligned at least), as the overflow alignment guarantee needs.
- [x] `Stats` gains `dirty_budget`, `dirty_pages` (slots in use by the current writer) and `dirty_committed` (bytes committed), live atomics readable during a write transaction. The `Stats` doc comment is updated for that exception.
- [x] Tests: the budget's validation and rounding; `dirty_pages` rises during a transaction and is 0 after commit and after abort; the resident size of the pool drops after the transaction (checked with the OS figure from KV-T-0019's measurement where available); a transaction exceeding the pool returns `Out_Of_Memory` and can be aborted cleanly; the whole existing suite passes with the default budget.
- [x] Deliberate-bug check: skip releasing the slots at transaction end, and a test fails. Record it here.
- [x] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- The pool is `dirty_budget / page_size` slots with a bitmap or free stack of slot indices; contiguous ranges for overflow runs can be found by a linear scan (runs go away from the pool in KV-T-0021, so this is temporary).
- Committed/uncommitted tracking per slot, so a slot is committed once per transaction and released at the end in one call per contiguous committed range.
- The pool belongs to the `Env` and is used only with `writer_mutex` held.

### Dependencies
None in code. KV-T-0019 decides the release method; if it isn't done yet, use `MADV_DONTNEED` on Linux and leave the macOS method behind one procedure so it can change.

### Risk Considerations
- Every place that holds a `[]byte` into a dirty buffer today must keep working with slot-backed buffers; since slots don't move within a transaction, this should be a local change.
- A per-commit release adds page faults to the next transaction; measure it in passing (expected: microseconds against a synced commit's milliseconds).

## Status Updates

### 2026-09-24: done

**What was built.**
- `kv/pool.odin` (new): `Dirty_Pool`, owned by the `Env` and used only under `writer_mutex`. `pool_init` (from `env_open`, against the database's own page size) reserves the address space once with `mmap(PROT_NONE, MAP_PRIVATE | MAP_ANONYMOUS)`; `pool_destroy` (from `env_close`) unmaps it. Bookkeeping: a `used` bitmap per slot, a `committed` bitmap per granule, a `touched` stamp per slot (the transaction's `mods` at the last `page_alloc` or `page_touch`, for D3's LRU in KV-T-0021), and `in_use` / `committed_bytes`, stored atomically by the writer and loaded atomically by `env_stats`. `pool_alloc(n)` takes the lowest run of `n` free slots (linear bitmap scan, skipping full words) and commits whatever of it isn't (`mprotect(READ | WRITE)`, one call per contiguous uncommitted range); `pool_free` returns slots for reuse within the transaction; `pool_release` (from `write_state_free`, so on commit and abort) frees every slot and releases every committed range in one call each.
- Release (`os_pool_release` in `kv/os_darwin.odin` / `kv/os_linux.odin`), as KV-T-0019 decided: **macOS** `mmap(MAP_FIXED | MAP_PRIVATE | MAP_ANONYMOUS, PROT_NONE)` over the range; **Linux** `madvise(MADV_DONTNEED)`, bound directly (not `posix_madvise`), then `mprotect(PROT_NONE)`. Both leave the range reserved and inaccessible again, so a stale slice into a released slot faults instead of reading zeros. `virtual.decommit` is not used. `os_page_size`, `os_pool_reserve` and `os_pool_commit` are in `kv/os_posix.odin`.
- `Write_State.dirty` is `map[Pgno]Dirty_Page` (`slot`, `pages: u32`); a run is stored under its first page number in consecutive slots. `page_ptr`, `page_touch`, `page_alloc`/`page_alloc_end` (through the new `dirty_add`, replacing `dirty_buf_alloc`), `page_free` (frees the slots of a dirty page it drops), `overflow_value`, `freelist_place` and `txn_commit` (pwrite from the slots) all go through the pool. `Write_State.arena` keeps the dirty map and the page lists.
- `Options.dirty_budget`, `DEFAULT_DIRTY_BUDGET` (4 MiB), `MIN_DIRTY_PAGES` (`2 × MAX_DEPTH + 1` = 49). Negative, or fewer than 49 pages after rounding up, is `Invalid_Argument`.
- `Stats.dirty_budget`, `dirty_pages`, `dirty_committed`; the `Stats` and `env_stats` doc comments say the two dirty figures are live. `Error.Out_Of_Memory`'s comment names the pool.
- `tests/pool_test.odin` (4 tests): `test_dirty_budget_options` (default, rounding, the minimum, negative, the budget counted in an existing 16 KiB-page database's pages, nothing committed or resident after open, reservation OS-page aligned); `test_dirty_pages_live` (`dirty_pages` equals the slots in the dirty map after each step, slots page-aligned, an overflow run in consecutive slots and 16-aligned, a replaced run's slots given back, the root's `touched` stamp, 0 and 0 after commit and after abort); `test_dirty_pool_released` (3 MiB value: the OS reports ≥ 3 MiB of the pool resident during the transaction and **0 bytes** after commit and after abort, `/proc/self/pagemap` present bits on Linux and `mach_vm_region` on macOS, which is exact for anonymous memory; the released pool is usable again); `test_dirty_pool_exceeded` (a value larger than the pool, and puts into the 49-page pool until one doesn't fit: `Out_Of_Memory`, `txn.err` stays `None`, `dirty_pages` never above the pool, abort leaves the database as it was, a transaction that fits commits).
- Test helpers: `dirty_buf` (a dirty page's pool buffer) and `BIG_DIRTY_BUDGET` in `tests/helpers.odin`. `CLAUDE.md`'s code map updated.

**Decisions and deviations.**
- **Commit and release are per granule, not per slot:** a granule is `max(page size, OS page size)`, because `mprotect` and the remap only work on whole OS pages. With 4 KiB pages on Apple Silicon (16 KiB OS pages) a granule is 4 slots; on Linux (4 KiB) it is one. The reservation is rounded up to whole granules and `dirty_committed` counts whole granules, so it can exceed `dirty_pages × page_size`. The implementation notes said per slot; this is the same thing wherever the OS allows it.
- **Lowest-first allocation:** every allocation takes the lowest free run, so the committed slots form a prefix in practice and the release is usually one call.
- **`Out_Of_Memory` is checked up front, like `Map_Full`:** `put` checks `pool_available(2·depth + 1, run)` and `del` `pool_available(depth)` right after `pages_available`, and return `Out_Of_Memory` without changing anything; the transaction stays usable (it can go on, commit or abort). The run is searched past the lowest `singles` free slots, the same argument as `pages_available`. This is where D2's spill goes in KV-T-0021. The only other place the pool can run out is the free-list run at commit (`freelist_place`), which fails the commit with `Out_Of_Memory`; D6 removes it.
- **Slots of a page dropped within the transaction are reused at once** (the arena never reused a buffer). Nothing reads a page after `page_free` (checked in `delete.odin`'s rebalance and root collapse, and `put`'s overflow replace); noted as an invariant in `CLAUDE.md`. `test_reuse_loose_and_touched_pages`' check that a reused loose page got a buffer "other than the old run's" is replaced by: it is in the pool and registered as dirty.
- **Three existing tests write more than 4 MiB in one transaction** and now open with `dirty_budget = BIG_DIRTY_BUDGET` (64 MiB): `test_overflow_10mb_value` (one 10 MB value), `test_reads_allocate_nothing` (3,000 keys, 300 of them 3-page runs, in one commit) and `test_snapshot_isolation_across_threads` (16,000 puts in its first commit). Without spilling they can't fit a 4 MiB pool; KV-T-0021 should put them back on the default (or a small) budget. `test_env_stats` compares the dirty figures separately while the write transaction is open, since they are live. Every other test passes on the default budget.
- A range whose release fails stays marked committed (its memory is kept until the next transaction's release); `txn_abort` can't return an error.

**Measurements** (`test_dirty_pool_released`, 3 MiB in the pool). Aborting, which releases the pool (plus the arena): macOS 37 µs (`-o:speed`), Linux arm64 27 µs (`-o:speed`) / 38 µs (debug). A 3 MiB put into the released pool, page faults included: macOS 347 µs, Linux arm64 183 µs. So the refault a release costs the next transaction is about 0.1 µs per KiB written, against a synced commit's milliseconds; a small transaction touching a few pages pays a few µs.

**Deliberate-bug checks.**
- Skipping `pool_release` in `write_state_free`: 12 tests fail, including `test_dirty_pages_live` ("pool in use after the abort"), `test_dirty_pool_released`, `test_env_stats` ("dirty pages reported after the commit"), `test_dirty_pool_exceeded` and several reuse/model tests (running out of slots).
- Keeping the bookkeeping but skipping the OS call (`os_pool_release`): `test_dirty_pool_released` fails, "3162112 bytes of the pool still resident after commit" (and after abort).
- Removing `put`'s `pool_available` check: `test_dirty_pool_exceeded` fails (`txn.err` set to `Out_Of_Memory` part-way, the commit refused, the database emptied by the abort).
All restored.
