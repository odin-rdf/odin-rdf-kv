# Spill dirty pages, and write overflow and free-list runs directly

## Parent Initiative

[[KV-I-0004]]

## Objective

Make `dirty_budget` a hard limit that callers never hit: when the pool runs short, write the least recently touched dirty pages to their final places in the file before the next operation (KV-I-0004 D2–D4), and never hold an overflow run or the free-list run in the pool as a whole (D5, D6).

## Acceptance Criteria

- [x] **The boundary check (D2):** at the start of `put` and `del`, next to `pages_available`, if the pool has fewer free slots than the operation's worst case (`2·depth + 1` for `put`, `depth` for `del`), spill. Nothing spills inside an operation.
- [x] **What is spilled (D3):** each slot records the `mods` value of its last touch; a spill takes the least recently touched quarter of the pool (at least what the operation needs), sorts it by page number and writes it with `pwrite`. `Stats.spills` counts pages spilled.
- [x] **Spilled pages (D4):** kept in a `spilled` set. Reads go through the map. `page_touch` of a spilled page copies it back into a slot under the same page number, with no copy-on-write and no `freed` entry. `page_free` of a spilled page puts it on `loose`. The file is grown before any write past its end (`file_grow` moves out of `commit.odin`).
- [x] **Commit:** writes the remaining dirty slots, then syncs once, which covers the spilled pages. Abort after spills leaves the database and the free list as they were.
- [x] **Overflow runs (D5):** `overflow_write` writes the header page through one slot and the value from the caller's buffer with `pwrite`, and records the run as spilled. A value larger than the pool commits.
- [x] **Free-list run (D6):** `freelist_write` fills and writes one page at a time through one slot. A free list longer than the pool commits.
- [x] The dirty pool never exceeds its budget: asserted after every operation in the tests below.
- [x] Tests with the minimum budget (49 pages):
  - a transaction writing 10× its pool commits; every key reads back before and after commit through `get` and both cursor directions;
  - a spilled page re-touched keeps its page number; a spilled page freed goes to `loose`; `space_check` after every commit;
  - abort after spilling, then commit something else: database, free list and `space_check` as before;
  - a reader holding a snapshot across spilling transactions still reads its data;
  - the randomized model, the isolation test (TSan) and the steady-state tests run with the minimum budget as well as the default (the steady ones on demand, as now).
- [x] Deliberate-bug checks, each failing a test, recorded here: spill inside an operation (for example from `page_alloc`); copy-on-write a spilled page on re-touch; skip `file_grow` before a spill; free a spilled page to `freed`.
- [x] The spill cost per page is measured and recorded.
- [x] `scripts/test.sh` and `scripts/test-linux.sh` (arm64, amd64) pass.

## Implementation Notes

### Technical Approach
- The worst case must count re-touches of spilled pages on the path (each needs a slot), which `2·depth + 1` already covers because a touched path page needs at most one slot either way.
- Spilling to a reused page is safe because pages this transaction allocated are in no snapshot anyone can read (KV-I-0002 D1). A comment at the spill site should say so, since step 7's crash tests rely on it.
- `put`'s rule that `key` and `value` must not point into the transaction's own pages now also covers spilled pages read through the map: they don't move, so no new restriction is expected, but check it.

### Dependencies
KV-T-0020 (the pool).

### Risk Considerations
- Spilling adds writes before the meta page is written; step 7's kill-during-commit harness must cover "killed after a spill, before commit". Note it in the vision when this initiative completes.
- The LRU scan is linear in the pool (1,024 slots at 4 MiB). Fine for a quarter-pool batch; measure if it shows up.

## Status Updates

### 2026-09-24: done

**What was built.**
- **The boundary check (D2):** `pool_make_room(txn, n)` in `kv/pool.odin`, called by `put` (after `pages_available`, with `2·depth + 1`), by `del` (after its search and `pages_available`, with `depth`) and by `txn_commit` (one slot for the free-list run). It replaces `pool_available` and the up-front `Out_Of_Memory`; `put` and `del` no longer return `Out_Of_Memory` because of the pool's size. An overflow value needs no run of slots any more: its header page takes one slot only while the path is touched, before any split, so `2·depth + 1` covers it. Nothing spills inside an operation: `put` and `del` set `Write_State.in_op` around their `_unchecked` bodies, and `pool_make_room` asserts it is clear (see the first deliberate-bug check for why). `page_alloc` never spills.
- **What is spilled (D3):** `spill` (file-private, `kv/pool.odin`) lists every dirty entry with its age (`txn.mods` minus the slot's `touched` stamp) into `Dirty_Pool.spill_list` (one entry per slot, allocated at `pool_init`, so a spill allocates nothing), sorts oldest first (page order among equals), takes entries until a quarter of the pool (or what the operation needs, if more) is free, sorts those by page number, grows the file to the last one, and writes them with `pwrite`, **adjacent pages in adjacent slots in one call**. Each written entry moves from `dirty` to `spilled` and its slots are freed. `Dirty_Pool.spills` (atomic) counts pages spilled over the Env's life, reported as `Stats.spills`. The safety argument is the comment at the write in `spill`.
- **Spilled pages (D4):** `Write_State.spilled: map[Pgno]u32` (first page, length). A page is in `dirty` or `spilled`, never both. `page_ptr` needed no change (a spilled page isn't in `dirty`, so it is read from the map). `page_touch` of a spilled page takes a slot, copies the page from the map, and moves it back to `dirty` under the same number: no copy-on-write, no `freed` entry, the parent untouched. `page_free` of a spilled page or run removes it from `spilled` and puts it on `loose`. `file_grow` moved from `commit.odin` to `env.odin` (`@(private)`, with `FILE_GROWTH_MIN`) and is called by `spill`, `overflow_write` and `txn_commit`.
- **Commit:** builds and places the free list as before, grows the file to `last_pgno`, streams the free-list run (spilling first if no slot is free: no extra writes, since every dirty page is written next anyway), writes the remaining dirty slots in page order, then syncs once. Abort needed no change: `write_state_free` releases the pool, the spilled bytes are in pages nothing refers to, and `Env.free` never changed.
- **Overflow runs (D5):** `overflow_write` takes the run's page numbers with the new `page_take` (loose, reusable, end: page_alloc's sources and order, without slots; `page_take_end` replaces `page_alloc_end`), grows the file, and writes: the first page (header and the start of the value) staged in one slot, the whole pages in between straight from the caller's buffer in one `pwrite`, and the last partial page staged in the slot again, zero-padded (the padding stays zero, as before). The run goes in `spilled`; the slot is freed at once. `overflow_value` lost its dirty branch: a run is never in the pool.
- **Free-list run (D6):** `freelist_place` returns page numbers only (no buffer, no slots). `freelist_write(txn, pgno, pages, state)` fills one slot a page at a time (records run on from offset 16 across pages, so each page starts at a record boundary; the header takes page 0's first record place) and writes each page.
- `Options.dirty_budget`'s, `Error.Out_Of_Memory`'s, `put`'s, `del`'s, `txn_commit`'s, `Stats`'s and the pool's doc comments describe spilling. `page_alloc` with `n > 1` still takes a run of slots (the tests use it); nothing in `kv/` calls it with more than one page now.

**Decisions and deviations.**
- **The D2 rule is asserted, because LRU hides its violation.** The first attempt at the deliberate bug (spilling from `page_alloc`, lazily, with the up-front checks removed) passed the whole suite: every slice an operation holds across `page_alloc` points into a page it touched or allocated in that operation, which carries the newest stamp, so the least recently touched batch never includes it unless the batch is larger than all the older pages, which the minimum pool rules out in practice. The rule is still the only thing that makes it certain, so `Write_State.in_op` enforces it.
- **`Stats.spills` counts pages the pool spilled,** not overflow runs or free-list pages, which are always written directly; otherwise it would mostly measure value sizes. The initiative's D11 only says "pages spilled".
- **Adjacent pages are written in one call**, a small extension of D3's "sorts them by page number and writes them with pwrite".
- **A failed spill (Io) doesn't poison the transaction:** `put`/`del` return the error before changing anything, and every page is either still dirty or fully written and spilled, so the transaction stays consistent and usable. The error is not stored in `txn.err`.
- **The commit writes the free-list run before the remaining dirty pages**, so that if the pool is full, spilling for the run's one slot writes pages that would be written anyway.
- **Skipping `file_grow` before a spill is not a correctness bug on these platforms:** `pwrite` past the end extends the file itself, and the reads of the pages written are then inside it. What breaks is the Env's record of the file (`file_size`, `Stats.file_pages`) and growth in large steps, so the test that catches it (`expect_file_covers_spills`) checks that the file's size, the Env's and `env_stats`' agree, and that every spilled page is inside it. The initiative's D4 wording stands.
- **`put`'s rule on its arguments needed no new restriction:** a slice into a spilled page points into the map, which doesn't move, and the existing rule (no slices into the transaction's own pages) covers it; its doc comment and CLAUDE.md's zero-copy notes say so. A `get` slice from a write transaction into a dirty page can now also end because the next `put`/`del` spilled that page and reused its slot: still "valid until the next put", as documented.
- `pool_available` (and `pool_find`'s `skip`) removed; `page_alloc_end` replaced by `page_take_end`.

**Spill cost** (`test_bench_spill_cost`, `-o:speed`, median of 7; one transaction of 20,000 puts of 100-byte values, 1,188 pages written, against the same transaction with a 64 MiB pool that never spills; "+commit" includes the commit and its sync):

| workload | pool | spilled | puts ms (vs no spill) | µs per spilled page | +commit ms (vs no spill) | µs per spilled page |
|---|---|---|---|---|---|---|
| macOS, append | 196 KiB | 1,152 | 7.59 (6.41) | 1.02 | 16.94 (17.19) | −0.22 |
| macOS, append | 4 MiB | 256 | 6.39 (6.20) | 0.72 | 17.08 (17.16) | −0.32 |
| macOS, random overwrite | 196 KiB | 21,432 | 35.12 (6.77) | 1.32 | 44.88 (16.95) | 1.30 |
| macOS, random overwrite | 4 MiB | 4,608 | 15.15 (6.57) | 1.86 | 24.95 (17.90) | 1.53 |
| Linux arm64, append | 196 KiB | 1,152 | 7.44 (7.64) | −0.18 | 12.69 (14.35) | −1.44 |
| Linux arm64, append | 4 MiB | 256 | 7.64 (7.70) | −0.23 | 13.87 (14.18) | −1.21 |
| Linux arm64, random overwrite | 196 KiB | 21,408 | 40.26 (7.73) | 1.52 | 46.45 (15.01) | 1.47 |
| Linux arm64, random overwrite | 4 MiB | 4,864 | 15.78 (7.74) | 1.65 | 22.70 (14.83) | 1.62 |

So a spilled page costs **about 1–2 µs** (the `pwrite`, the LRU sort, and copying back those touched again), and for a transaction that doesn't come back to its pages (appending) nothing overall: the writes only move from the commit to the puts. Random overwrites of a tree larger than the pool thrash as LRU does: each page is spilled and copied back several times (21,000 spills for 1,188 pages at 49 slots, 4,600 at 1,024), which is the 1.3–1.9 µs per spill above, not extra I/O per commit. Macs: Apple M4, macOS 26.5.2; Linux: OrbStack, kernel 7.0.14.

**Deliberate-bug checks** (each restored):
- **Spill inside an operation:** `pool_make_room` called from `page_alloc` (and from `page_touch`'s spilled path), with the up-front calls in `put` and `del` removed. Without the assertion, the suite passed (see Decisions: LRU spares the operation's pages); with it, 84 tests fail with "spilling inside an operation (KV-I-0004 D2)", including every spill test, both isolation tests and the model.
- **Copy-on-write a spilled page on re-touch** (`page_touch`'s spilled branch disabled): `test_spill_retouch_and_free` fails (the leaf moves from page 17 to 51, `freed` grows by one, `last_pgno` grows, the page is not back in the pool). Nothing else fails: the copy is wasteful but consistent, so it takes the explicit check.
- **Skip `file_grow` before a spill:** `test_spill_retouch_and_free` fails ("the file has 77824 bytes, the Env records 24576"; "spilled page 7 ends past the file's 24576 bytes"). Before `expect_file_covers_spills` was added to that test, nothing failed: in the other spill tests an overflow write had always grown the file past every page spilled.
- **Free a spilled page to `freed`** (`page_free`'s spilled branch leaving the list at `freed`): 6 tests fail, among them `test_spill_retouch_and_free` (the merged spilled leaf and the replaced run's pages pending instead of reusable, and not loose), `test_overflow_overwrite`, `test_freelist_round_trip` and `test_reuse_abort_leaves_free_unchanged`.
