# The I/O hook, KV_NO_SYNC and the journal

## Parent Initiative

[[KV-I-0005]]

## Objective

Give the tests a way to see and steer every write, sync and truncate the store makes, and a way to skip syncs (KV-I-0005 D1, D3). Nothing else in the initiative can start without it.

## Acceptance Criteria

- [x] `IO_HOOK :: #config(KV_IO_HOOK, false)` and `NO_SYNC :: #config(KV_NO_SYNC, false)`, beside `CHUNK_ACCOUNTING`, exported *(in `kv/os_posix.odin`, next to the procedures they change, rather than in `chunks.odin`; same idiom)*, with doc comments saying both are test-only.
- [x] `Io_Op` (kind `Write`/`Sync`/`Truncate`, fd, offset, bytes, size) and `@(thread_local) io_hook: proc(op: Io_Op) -> Error`. `os_pwrite`, `os_sync` (both platforms) and `os_truncate` call the hook first inside `when IO_HOOK`; a non-`.None` return is returned without performing the operation. A build without the define has no branch.
- [x] `os_sync` under `NO_SYNC` returns `.None` after the hook, with no system call, on both platforms.
- [x] `tests/crash.odin`: a journal helper that installs a recording hook, copies each write's bytes, and records syncs and truncates in order; plus `journal_image_kill(baseline, journal, n, path)`, which writes the baseline file with operations 0..n applied. *(n is a count: the first n operations, `0 ..< n`, so n = 0 is the baseline and n = len(ops) the whole journal.)*
- [x] Tests (registered only when `kv.IO_HOOK` is true, and the file compiles either way):
  - the journal of one commit on a committed tree has the expected shape: data-page writes in page order, a sync, one meta-page write into slot `txn_id & 1`, a sync; spills and overflow runs appear before the first sync;
  - the kill image at the last operation is byte-identical to the real file;
  - a hook returning `.Io` at a chosen operation makes that store call return `.Io`;
  - hooks on two threads with two envs see only their own operations.
- [x] A test that `NO_SYNC` really skips the call (a hook-counted sync with a timing or syscall-free check is not possible portably, so: the test documents what it can assert, at minimum that commits succeed and the journal still records the syncs).
  *(Amended 2026-09-25: it can be asserted after all, portably and without timing: `os_sync(-1)` returns `.None` under `NO_SYNC` and `.Io` (EBADF) without it, since only a real system call can fail on a descriptor that isn't open. `test_no_sync_skips_call` asserts exactly that, in every build; the journal-shape and per-thread tests count the recorded syncs.)*
- [x] `scripts/test.sh` gains one configuration with `-define:KV_IO_HOOK=true -define:KV_NO_SYNC=true` (debug), so the hooked build is exercised on every local run; the existing configurations stay as they are, with real syncs.
- [x] Deliberate-bug checks recorded: skip the hook in one of the three procedures (a journal-shape test fails); record a write after performing it with a wrong offset (the image-equals-file test fails).
- [x] `scripts/test.sh` and `scripts/test-linux.sh arm64` pass.

## Implementation Notes

### Technical Approach
- The hook is thread-local because tests run in parallel and each write happens on the thread holding the write transaction; `init_meta_pages` runs on the opening thread.
- The journal copies bytes because a pool slot is reused after the write.
- Baseline: a copy of the file taken while it is fully synced (after a commit returned), or "no file".

### Dependencies
None.

### Risk Considerations
- Any I/O outside the three procedures would be invisible to the journal; grep for `posix.pwrite`, `ftruncate`, `fsync` outside `kv/os_*.odin` as part of the task.

## Status Updates

### 2026-09-25 — implemented and verified

**What was built.**
- `kv/os_posix.odin`: `IO_HOOK`, `NO_SYNC` (both `#config`, doc comment saying test-only and why `NO_SYNC` loses nothing), `Io_Kind` (`Write`/`Sync`/`Truncate`), `Io_Op` (`kind`, `fd`, `offset`, `bytes` — borrowed, `size`) and `@(thread_local) io_hook: proc(op: Io_Op) -> Error`. `os_pwrite` and `os_truncate` call the hook first inside `when IO_HOOK`, and `or_return` its error without performing the operation. `kv/os_darwin.odin`, `kv/os_linux.odin`: `os_sync` the same, then `when NO_SYNC { return .None }` before the system call.
- `tests/crash.odin` (the building blocks KV-T-0027/-0028/-0030 use): `Io_Record` (the journal's copy of an `Io_Op`, owning its bytes), `Journal` (`ops`, `calls`, `fail_at`, `fail_with`, `allocator`), `journal_start(&j)` / `journal_stop()` / `journal_destroy(&j)`, `Baseline` + `baseline_take(path)` (a missing file is `exists = false`) + `baseline_destroy`, `image_init(baseline)`, `image_apply(&img, record)` (a write past the end extends with zeros, a truncate grows with zeros or shrinks, a sync is a no-op), `image_write(path, img)`, `file_remove(path)`, and `journal_image_kill(baseline, journal, n, path)`. A power-loss image (KV-T-0028) is `image_init` + `image_apply` over the records up to the last sync + a subset of the rest, a torn write being an `Io_Record` whose `bytes` are cut to some sectors before `image_apply`.
- `tests/io_hook_test.odin`: `test_journal_commit_shape`, `test_journal_spill_overflow_before_sync`, `test_journal_kill_image_is_file`, `test_io_hook_fails_operation`, `test_io_hook_per_thread` (registered under `kv.IO_HOOK`; the procedures compile in every build, the `KV_BENCH` idiom), and `test_no_sync_skips_call` (every build).
- `scripts/test.sh`: a fourth run, `-debug -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true`, and an extra `odin check tests` per cross target with the same defines (the Linux `os_sync` under `NO_SYNC` is compiled on every run). `scripts/test-linux.sh`: the same hooked run in the container, added beyond the criterion because Linux is production and its `os_sync` is a different file.

**Decisions.**
- The hook runs *before* the operation (so it can refuse it, D7). A write the OS then fails would still be in the journal; no test depends on that and the hooked build never sees a real I/O error.
- `io_hook` is declared in every build (a thread-local pointer, never read without `IO_HOOK`), so test files compile without the define; only the call is under `when`.
- `fail_at` counts hook *calls* (`Journal.calls`), not recorded ops: a failed call is not recorded. A dry run's journal indexes are the calls of an identical run, which is how `test_io_hook_fails_operation` picks each operation of one commit.
- The journal is per thread and per file by convention: it records whatever the thread does, with the fd in each record; `journal_image_kill` applies all of them. A test opens one env on the journal's thread.
- A baseline of no file and an empty file make the same image (an empty file): `env_open` creates a missing file, so the two open alike.
- The commit-shape test identifies the free-list run's pages from the new snapshot (`freelist_pgno`, `freelist_run_len`): the run is written before the dirty pages but usually has the highest page number, so "page order" holds for the dirty pages, and the run is checked whole separately. It also checks each dirty page is written exactly once (`len(txn.write.dirty)` before the commit) and that a meta write is the header and meta only, shorter than a page (`meta_write` writes the prefix).

**Deviations.** The constants live in `os_posix.odin`, not `chunks.odin`. `journal_image_kill`'s `n` is a count (amended above). The `NO_SYNC` criterion was amended: it *is* assertable (above). `test-linux.sh` gained the hooked run too.

**Measured.** The hooked, no-sync debug run is 10.3 s for 167 tests on macOS against 24.2 s for the plain debug run of 162: `F_FULLFSYNC` was most of the suite's time, as D3 said.

**Deliberate-bug checks** (each run: the six tests, `-debug -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true -define:ODIN_TEST_THREADS=2`, under `timeout -s KILL 300`; every one reverted and checked with `cmp` against a saved copy):
1. No hook call in `os_sync` (darwin): `test_journal_commit_shape`, `test_journal_spill_overflow_before_sync` (last op not a Sync), `test_io_hook_per_thread` (0 syncs for 35 commits) fail.
2. No hook call in `os_truncate`: `test_journal_kill_image_is_file` (first op not a Truncate) and `test_io_hook_per_thread` (image differs) fail.
3. No hook call in `os_pwrite`: four tests fail, among them the journal shape ("journal too short") and the image (same size, different bytes).
4. The journal records a write's offset + 1 after it was performed correctly: `test_journal_kill_image_is_file` (image differs from the file), `test_io_hook_per_thread`, `test_journal_commit_shape` fail.
5. `os_pwrite` ignores the hook's error: `test_io_hook_fails_operation` fails (a failed meta write reopened at txn 2).
6. `os_sync` ignores `NO_SYNC`: `test_no_sync_skips_call` fails (`.Io`).
7. `io_hook` not thread-local: four tests fail, two with a segfault from another test's hook.

**Grep for I/O outside the platform layer:** `posix.pwrite`, `posix.write`, `ftruncate`, `fsync`, `fdatasync`, `fcntl` appear in `kv/` only in `os_*.odin`. (`tests/platform_test.odin` writes its own measurement file with `posix.pwrite`/`fsync`; not the store's I/O.)

**Verification.** `scripts/test.sh`: all four runs pass (debug 162, `-o:speed` 162, ASan 162, hooked/no-sync 167 tests) and every cross-target check. `scripts/test-linux.sh arm64`: debug 162, `-o:speed` 162, hooked/no-sync 167, all pass; there `test_no_sync_skips_call` saw `.Io` from `fdatasync(-1)` in the plain runs and `.None` in the hooked one.
