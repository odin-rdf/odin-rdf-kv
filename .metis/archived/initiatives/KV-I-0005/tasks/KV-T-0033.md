Well under 2 s, so **nothing was shrunk or moved**. Under `KV_CRASH` the reuse workload's kill sweep (1,064 cuts) is 7.5 s of the 10.5 on macOS. The fuzz mode and the real-kill test were not rerun (their figures are in KV-T-0031 and -0032).

**Admission and CI.** The default sweep is registered by `KV_IO_HOOK`, so the CI invocation of D9 runs it with no other define; nothing changed in how it is registered. The CI commands (16 cross-target checks, then `odin test tests -vet -strict-style -o:speed -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true`) are in the initiative's Results, ready to paste: checks 1.0 s (macOS) / 1.5 s (Linux arm64); test step about 5 s of build and 2.8–2.9 s of run, 8.1 s wall on macOS at 3 threads and 8.6 s on Linux arm64 at 4.

**Two test failures found by timing the CI invocation, both fixed, neither a store bug:**
1. `test_reader_table_across_threads` failed every time on Linux with `KV_NO_SYNC`, debug and `-o:speed` alone (47–237 read transactions against the required > 300): 300 unsynced commits end before six reader threads get going. It passed in the hooked debug run of `scripts/test-linux.sh` only because the rest of the suite slowed the writer. Now the writer goes on until the readers have begun more than 300 (a shared atomic count, `Table_Reader.total`), up to 30,000 commits, and the test checks the count against the readers' own. After: Linux 370–1,140 commits, macOS 300; TSan clean twice each with and without the hook. Deliberate-bug check: the old fixed loop is the bug, and fails 4 of 4 on Linux.
2. `test_env_stats` failed at about 1% of seeds in every build (3 of 300; seed 6136440337835298 fails in a plain debug build). Two draws of the same key in one 20-key round, both overflow values, free the first run as loose pages, which the commit puts in `ready` directly, against "freed pages pending, none ready". `steady_commit` gained `unique_keys` (`rand.perm`, so still by seed); `test_env_stats` uses it. The three failing seeds pass, and 500 random seeds after. With `unique_keys = false` the seed fails again, which is the check. (`distinct` was the first name tried; it's a keyword, added to the pitfalls.)

`scripts/test-linux.sh` now runs the hooked build at `-o:speed` as well as debug, so the exact CI configuration runs natively on Linux before a push. Its header comment says why.
