# Can a sector write tear? A torn meta write during creation leaves a file that never opens

## Objective

Split from KV-T-0035 (2026-09-25); **a decision for the owner**. KV-T-0035 took its option 1: `init_meta_pages` now syncs after the truncate, so a power loss can no longer keep a meta write while losing the sizing. One class of creation image remains `.Corrupted` under D6 as decided, so the application fails to start until someone deletes the file:

- **Sizing kept, neither meta write whole, at least one torn:** two pages, not all zero (a torn prefix of slot 1's header, or 40 or 95 bytes of either slot), and no valid meta page, so D6 doesn't apply.

Such a file holds no data: creation never finished, so nothing was ever committed. The power-loss creation sweep (`crash_sweep_create_power`) pins these images as `.Corrupted` and asserts that at least one occurs: 14 of its 27 fixed images at each page size (4 KiB and 16 KiB).

## The question

The class comes only from a tear inside the 96-byte meta write, which sits within one 512-byte sector. The power-loss model tears a meta write to a byte prefix, a stricter model than an atomic sector (KV-T-0028).

- **If sector writes are treated as atomic** (LMDB's assumption, and most of the storage stack's), the class cannot happen and every creation image opens. The sweep's fixed torn images would then be outside the model for creation, and the test would say so rather than pin them.
- **If they are not**, no in-place creation avoids it. The choices from KV-T-0029's status update:
  - widen D6 to "no valid meta page, at most two pages at this page size, every nonzero byte inside the two meta-page prefixes": a file of two pages holds no data page, but it is a heuristic over damaged bytes;
  - or create at a temporary path and `rename` it into place, with a directory sync, which the journal doesn't model and which changes how `env_open` treats an existing empty file.
  - or leave it as it is: the file holds nothing, and deleting it is the recovery.

## Acceptance Criteria

- [ ] The owner decides whether the power-loss model's sub-sector tear binds creation.
- [ ] If a change follows: the rule or the creation path changed, `crash_sweep_create_power`'s assertion on `refused_torn` updated to match, and `env_open`'s doc comment amended.
