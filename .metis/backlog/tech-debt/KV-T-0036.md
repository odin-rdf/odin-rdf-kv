# A directed test for overflow value size boundaries

## Objective

Found by KV-T-0031 (2026-09-25). A deliberate off-by-one in `overflow_write` (`len(tail) > 0` changed to `> 1`) drops the last byte of any value that leaves exactly one byte on the last page of its overflow run. `test_model_randomized` and `test_model_randomized_min_pool` catch it at seeds 1–3 and **miss it at seeds 4–6**. Only the on-demand fuzz mode catches it reliably, and that isn't in the default suite or CI. A size boundary like this should be pinned deterministically.

## Acceptance Criteria

- [ ] A test in the ordinary suite that writes, reads back and scans overflow values at every size boundary: the largest inline value and the smallest overflow value; a run of exactly n pages; n pages plus 0, 1 and `page_size − 1` bytes on the last page. Run at 4 KiB and 16 KiB pages.
- [ ] The same sizes overwritten in place, deleted, and read back after a reopen.
- [ ] Deliberate-bug check: the `> 1` change above fails it at any seed.
