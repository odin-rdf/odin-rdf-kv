# Types, platform layer and on-disk structs

## Parent Initiative

[[KV-I-0001]]

## Objective

Lay the foundation of the `kv` package: the shared types, the on-disk struct layouts (page header, leaf and branch node headers, meta page) with the xxHash64 meta checksum, and a small platform layer for macOS and Linux that the rest of the code calls instead of using `core:sys/posix` directly.

## Acceptance Criteria

- [ ] The `kv/` package directory exists and builds with `odin build kv -build-mode:lib` (or `odin check kv`) on macOS.
- [ ] `types.odin` defines:
  - `Pgno :: distinct u64` and `Txn_Id :: distinct u64`;
  - the `Error` enum: `None`, `Not_Found`, `Map_Full`, `Key_Too_Large`, `Corrupted`, `Io`, `Txn_Read_Only`, `Locked`;
  - `MAGIC`, `VERSION`, page flags (`BRANCH`, `LEAF`, `OVERFLOW`, `META`) and node flags (`BIGDATA`).
- [ ] The on-disk structs (`Page_Header`, `Leaf_Node_Header`, `Branch_Node_Header`, `Meta`) use only `u16le`, `u32le` and `u64le` fields. `#assert`s pin their sizes and field offsets.
- [ ] `meta_checksum(^Meta) -> u64` uses `xxhash.XXH64` over every byte before the `checksum` field.
- [ ] The platform layer provides:
  - `os_open(path, create) -> (fd, Error)`, including an exclusive non-blocking `flock`; failure to lock returns `Locked`;
  - `os_close`, `os_file_size`, `os_truncate`, `os_pread`, `os_pwrite`;
  - `os_sync`: `F_FULLFSYNC` on Darwin, falling back to `fsync` if the filesystem returns `ENOTSUP`; `fdatasync` on Linux;
  - `os_map_reserve(fd, map_size) -> (base, Error)`: `PROT_READ`, `MAP_SHARED`;
  - `os_unmap`, and `os_advise_random` (`MADV_RANDOM`).
- [ ] A smoke test in `tests/` maps a temporary file, `pwrite`s a page, and reads the same bytes back through the map. This proves the map stays coherent with `pwrite`.

## Implementation Notes

### Technical Approach
- **Platform split:** use `os_darwin.odin` and `os_linux.odin` with file-name build tags, and a shared `os_posix.odin` for the calls that are identical on both.
- **Missing constants:** where `core:sys/posix` lacks something (`F_FULLFSYNC`, `MADV_RANDOM` versus `POSIX_MADV_RANDOM`), use `core:sys/darwin` or `core:sys/linux`, or declare it locally with a comment.
- **Default page size is 4096 bytes,** whatever the OS page size (Apple Silicon uses 16 KiB OS pages).
  - Valid page sizes are powers of two from 4 KiB to 32 KiB, because slot offsets and `upper` are `u16`.
  - The page size is stored in the meta page, and only the map base needs OS-page alignment.
- **Page header layout:** `pgno: u64le`, `flags: u16le`, `lower: u16le`, `upper: u16le`, 2 bytes of padding (16 bytes in total). Overflow pages reuse the `lower`/`upper` bytes as `overflow_count: u32le`; use a `#raw_union` or accessor procs.
- **Meta:** stored in a page with a `Page_Header` (flags `META`), followed by the `Meta` struct.

### Dependencies
None. This is the first task.

### Risk Considerations
- **`F_FULLFSYNC` availability:** it is only honoured by some filesystems. Fall back to `fsync` and note it in the code.
- **Coherence between `pwrite` and the mmap:** this is assumed by the whole design. The smoke test verifies it early on the development platform.
