# Environment open/close with meta page selection

## Parent Initiative

[[KV-I-0001]]

## Objective

Implement `env_open` and `env_close`. They create a new database file with two initial meta pages, or open an existing one: reserve the read-only map, choose the valid meta page with the highest `txn_id`, and publish it as the environment's current snapshot.

## Acceptance Criteria

- [x] `env_open(path, options) -> (^Env, Error)` takes `Options { map_size, page_size }`. `page_size` is used only when creating a new file.
- [x] **New or empty file:** write meta page 0 and meta page 1 (both `txn_id = 0`, `root = 0`, `depth = 0`, `last_pgno = 1`, `entries = 0`), then sync.
- [x] **Existing file:**
  - Validate magic, version, page size and checksum for each meta page, and use the valid one with the higher `txn_id`. On a tie, use page 0.
  - A meta page whose `last_pgno` lies beyond the file size counts as invalid.
- [x] If both meta pages are invalid, return `Corrupted`. If the file is locked by another handle, return `Locked`. Any I/O failure returns `Io`.
- [x] **`Env` holds:** fd, map base, `map_size`, `page_size`, the current snapshot (`txn_id`, `root`, `depth`, `last_pgno`, `entries`), the snapshot mutex and the writer mutex.
- [x] `os_advise_random` is applied to the map.
- [x] `env_close` unmaps, unlocks and closes. It is safe to call once all transactions have ended; in debug builds, assert that none are active.
- [x] **Tests:**
  - create, close and reopen round-trips the snapshot;
  - corrupting meta page 0's checksum falls back to meta page 1, and the reverse;
  - corrupting both returns `Corrupted`;
  - bad magic returns `Corrupted`;
  - a second `env_open` on the same path returns `Locked`;
  - the highest `txn_id` wins (craft the two meta pages by hand with different `txn_id`s).

## Implementation Notes

### Technical Approach
- **Reserve first, then read:** reserve the map *before* reading the meta pages. This lets them be read through the map, with no `pread` buffers.
- **Page size of the second meta page:** its offset depends on the page size. If meta page 0 is valid, use its page size. Otherwise, try each valid page size (4, 8, 16 and 32 KiB) for page 1.
- **Reading meta safely:** copy each meta page into a local `Meta` value before validating it, so a concurrent writer (not possible yet, but it will be) cannot change it mid-check.
- **Test helper:** keep a `meta_write(env, slot, meta)` helper for the tests; T7 reuses it for commit.

### Dependencies
- KV-T-0001 (types, structs, platform layer).

### Risk Considerations
- **Reading past the end of the file** through the map raises `SIGBUS`. Check the file size before touching page 1, and before trusting `last_pgno`.

## Status Updates

*To be added during implementation*

### 2026-09-24: completed
- **Files:** `kv/env.odin` (new), `tests/env_test.odin` (new, 13 tests), and `Error.Invalid_Argument` added in `kv/types.odin`.
- **API:**
  - `env_open(path, options := Options{}, allocator := context.allocator) -> (^Env, Error)` and `env_close(^Env)`;
  - `env_snapshot(^Env) -> Snapshot`, which copies the snapshot under `snapshot_mutex`;
  - `meta_write(^Env, slot, Meta)`, which fills in the page header and checksum and is meant for reuse in KV-T-0007.
- **Verification:**
  - All 20 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64.
  - `kv` and `tests` type-check for `linux_arm64`, `linux_amd64` and `darwin_amd64`.
  - Two deliberate bugs were each caught by a test: making a tie go to page 1, and restoring the overflow-prone bounds check.
- **Decisions and deviations:**
  - **New error:** `Invalid_Argument` is returned for an invalid `Options.page_size` (not in the original list; the vision's error list is updated).
  - **Map size:** `Options.map_size = 0` means `DEFAULT_MAP_SIZE` (1 GiB of address space). The map is always enlarged to cover the existing file, then rounded up to `MAP_SIZE_GRANULE` (64 KiB). A too-small `map_size` therefore never fails at open.
  - **File creation:** `env_open` always opens with create. A missing or empty file is initialised by `ftruncate`-ing it to 2 pages and writing the two meta pages, then syncing.
  - **What `meta_write` writes:** only the 96-byte header and meta prefix. The rest of the page is left as is (zeros from `ftruncate`).
  - **Extra meta validation** beyond the acceptance criteria:
    - header `pgno == slot` and the `PAGE_META` flag is set;
    - `last_pgno ≥ 1` and `root ≤ last_pgno`;
    - `root == 0` exactly when `depth == 0`;
    - the page-count bound (`last_pgno < file_size / page_size`) avoids the overflow of `(last_pgno + 1) * page_size`.
  - **Choosing the meta page:** page 0 is read at offset 0 with its own `page_size`. If page 0 is invalid, page 1 is probed at 4, 8, 16 and 32 KiB, taking the first valid one whose recorded page size matches the probe.
  - **`Env.active_txns`** is only a counter for now. KV-T-0004 must increment and decrement it in `txn_begin` and `txn_end`; `env_close` asserts it is 0 in debug builds.
- **Known limitations** (acceptable for now):
  - A crash while a new file is being initialised can leave a non-empty file with no valid meta page. The next open then returns `Corrupted` instead of reinitialising.
  - The parent directory isn't synced after the file is created.
- **Note for the build matrix:** in zsh, `$flags` holding "-debug -sanitize:address" is not split into words, so loops over flag sets silently pass a single bogus flag. Use `${=flags}` or run each configuration explicitly.
