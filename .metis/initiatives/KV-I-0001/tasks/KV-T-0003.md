# Slotted page layer

## Parent Initiative

[[KV-I-0001]]

## Objective

Implement the slotted-page operations for branch and leaf pages, as pure procedures on a `[]byte` page buffer. They cover initialisation, node access, binary search, insertion, removal with compaction, free-space accounting and split helpers. Everything above this layer builds on it.

## Acceptance Criteria

- [x] `page_init(buf, pgno, flags)`, `page_num_keys`, `page_free_space`, `page_is_leaf` and `page_is_branch`.
- [x] **Accessors:**
  - `node_key(page, i) -> []byte`;
  - leaf: `leaf_value(page, i) -> ([]byte or overflow Pgno, flags)`;
  - branch: `branch_child(page, i) -> Pgno` and `branch_set_child(page, i, Pgno)`.
- [x] **Search:**
  - `page_search(page, key) -> (idx, exact)`, a binary search in `memcmp` order.
  - On branch pages, slot 0's key is treated as −∞. `branch_find_child(page, key) -> idx` returns the last slot whose key is ≤ `key`.
- [x] **Insert:** `leaf_insert(page, idx, key, val_or_ovpg, flags) -> bool` and `branch_insert(page, idx, key, child) -> bool`. They return `false` when the node doesn't fit, and leave the page unchanged.
- [x] **Remove:** `node_remove(page, idx)` moves node data with `memmove` so free space stays contiguous, and updates the affected slot offsets.
- [x] **Size helpers:** `leaf_node_size(key_len, val_len, bigdata)`, `branch_node_size(key_len)`, `max_key_size(page_size)` and `overflow_threshold(page_size)`, as defined in the initiative.
- [x] **Split helpers:**
  - `split_point(page, insert_idx, insert_size) -> idx` chooses by bytes, so both halves plus the pending node fit;
  - `page_move_upper(src, dst, from_idx)` moves the nodes from `from_idx` onwards to an initialised empty page.
- [x] **Unit tests:**
  - random-order inserts keep keys sorted;
  - fill a page to exactly full, and check the next insert fails;
  - remove then re-insert reuses the space;
  - branch search with slot 0 as −∞;
  - maximum key size fits 4 per branch page;
  - `split_point` balances by bytes for mixed small and large nodes, including an insert at index 0 and at the end.

## Implementation Notes

### Technical Approach
- **Node layout:** exactly as in the initiative. Slots are `u16le` offsets from the page start, stored straight after the 16-byte header.
- **Key comparison:** `bytes.compare`, or a `mem.compare` on slices.
- **No allocation:** every procedure works in place on caller-provided buffers. Tests use stack or temporary-allocator buffers.
- **Alignment:** nodes sit at arbitrary byte offsets (see the initiative's "Byte order and alignment" section).
  - Access node headers only through the `#packed` `Leaf_Node_Header` and `Branch_Node_Header` structs, and read and write their fields by value. Never take the address of a packed field.
  - Read and write the `BIGDATA` overflow page number with a `#packed` wrapper or `intrinsics.unaligned_load`/`unaligned_store`, not by casting to `^u64le`.
  - The `le` types handle byte order only, not alignment.
  - Unit-test page buffers use `Page_Buf` from `tests/helpers.odin`, which is 16-byte aligned.

### Dependencies
- KV-T-0001 (structs and constants). This task can run in parallel with KV-T-0002.

### Risk Considerations
- **Off-by-one errors in split and free-space arithmetic** are the classic bug in this layer. Mitigate with exhaustive boundary tests and a debug-only `page_check(page)` invariant checker: slots sorted, offsets inside the page, no overlap, `lower ≤ upper`. Later tasks will call the checker after every change in debug builds.

### 2026-09-24: completed
- **Files:** the page operations are appended to `kv/page.odin`; tests in `tests/page_test.odin` (12 new tests).
- **Verification:**
  - All 32 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64. `kv` and `tests` type-check for `linux_arm64`, `linux_amd64` and `darwin_amd64`.
  - The randomized tests passed under 25 extra seeds (`-define:ODIN_TEST_RANDOM_SEED=…`).
  - Four deliberate bugs were each caught: `node_remove` not shifting offsets, `node_reserve` rejecting exact fits, branch search including slot 0, and `max_key` using the branch overhead.
- **API differences from the acceptance text:**
  - **Inline vs. overflow insert:** `leaf_insert(page, idx, key, value)` inserts inline values only; overflow nodes use `leaf_insert_overflow(page, idx, key, overflow: Pgno, val_len)`.
  - **Reading values:** `leaf_value(page, i) -> (value, overflow, bigdata)` returns the inline bytes, or the overflow run's first page. `leaf_value_size(page, i)` returns the value length in both cases.
  - **Extra helpers:** `max_node_size`, `leaf_needs_overflow`, `page_used` and `node_bytes`.
- **Corrected limit:** the initiative's `max_key` formula used the branch overhead (10 bytes). An overflow leaf node has 16 bytes of overhead, so with the old formula a page could hold fewer than 4 nodes. It is now `(max_node_size − 16) & ~1`: 1002 bytes at 4 KiB. The initiative and the vision are updated.
- **Split protocol for KV-T-0005:**
  - `split_point(page, insert_idx, insert_size)` returns `s` in `[1, n]` over the *virtual* sequence with the new node inserted.
  - Move real nodes from `move_from = s − 1 if insert_idx < s else s` with `page_move_upper`.
  - Then insert the new node into the left page at `insert_idx`, or into the right page at `insert_idx − s`.
  - `split_and_insert` in `tests/page_test.odin` is a working reference.
  - **Branch splits** also need to:
    - copy the separator key (the node at the split point) *before* moving, because the move rewrites both pages;
    - then give the right page's slot 0 an empty key: `node_remove(right, 0)` followed by `branch_insert(right, 0, nil, child)`.
- **Implementation notes:**
  - **`page_move_upper`** copies the source page into a 32 KiB stack buffer (`Page_Scratch`) and rebuilds both pages in one pass. Removing nodes one at a time would cost O(n × page) in `memmove` work, which is too much for 32 KiB pages full of tiny nodes. The 32 KiB is fine for thread stacks of 512 KiB and up (the macOS pthread default).
  - **Zeroing:** `page_init` zeroes the whole page, and `node_remove` zeroes the bytes it frees, so stale bytes are never written to disk.
  - **`page_check`** runs in O(page size): a 4 KiB stack bitmap detects overlapping nodes. It also enforces `max_node_size`, rejects empty branch pages, and accepts empty leaf pages.
  - **Corrupted pages:** accessors rely on Odin's bounds checks, so a corrupted page causes a panic rather than returning `Corrupted`. KV-T-0004 should at least validate page flags while descending; deeper validation is future work.
- **Lesson from the tests:** a test helper kept `node_key` slices across a split, and they then pointed at rewritten bytes. This is the zero-copy lifetime rule in practice: a slice into a page is invalid once that page is modified. Callers must copy keys (for example the branch separator) before rewriting the page.
