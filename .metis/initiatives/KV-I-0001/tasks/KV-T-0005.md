# Write path: write transactions, copy-on-write touch, insert and splits

## Parent Initiative

[[KV-I-0001]]

## Objective

Implement write transactions up to, but not including, commit: the writer mutex, dirty-page storage behind a small interface, page allocation, top-down copy-on-write touching, and `put` with insert, overwrite, and leaf, branch and root splits.

## Acceptance Criteria

- [ ] **`txn_begin(env, read_only = false)`:** takes the writer mutex and copies the snapshot. `txn_abort` on a write transaction frees the dirty state and releases the mutex.
- [ ] **Dirty storage interface:** `dirty_get(txn, pgno) -> ([]byte, bool)`, `dirty_put(txn, pgno, buf)` and `dirty_reset(txn)`, backed by a `map[Pgno][]byte` plus a per-transaction `virtual.Arena`. No other code touches the map or the arena directly.
- [ ] **`page_ptr` in write transactions** checks `dirty_get` first.
- [ ] **`page_alloc(txn, n) -> (Pgno, Error)`:**
  - returns `last_pgno + 1` and advances `last_pgno` by `n`;
  - returns `Map_Full` if `(last_pgno + n + 1) * page_size > map_size`;
  - the new page is registered as dirty.
- [ ] **`page_touch(txn, path, level)`:**
  - if the page is already dirty, do nothing;
  - otherwise allocate a page number, copy the page, fix up the parent's child pointer (the parent was touched first), and update `path`.
- [ ] **`put(txn, key, val) -> Error`:**
  - returns `Txn_Read_Only` on a read-only transaction and `Key_Too_Large` above `max_key_size`;
  - an empty tree creates the root leaf;
  - an existing key is overwritten, in place if the size is the same, otherwise by remove and insert;
  - a full leaf splits, cascading to branches and to a new root;
  - `entries` is updated;
  - values at or above the overflow threshold return an error until KV-T-0006 lands.
- [ ] **`get` inside a write transaction** sees the transaction's own changes.
- [ ] **Tests (all inside a single write transaction, since commit is KV-T-0007):**
  - 50k ascending, descending and random inserts, then every key read back with `get`;
  - the tree depth grows as expected;
  - overwrites with larger, smaller and equal-size values;
  - maximum-size keys force splits with 4 keys per branch;
  - a zero-length key works;
  - after `txn_abort`, the env snapshot is unchanged and a new read transaction sees the old tree;
  - with a tiny `map_size`, `put` returns `Map_Full`;
  - debug `page_check` passes on every dirty page after each operation.

## Implementation Notes

### Technical Approach
- **Split procedure:**
  1. Allocate the right sibling and choose the split point by bytes (`split_point`).
  2. Move the upper half of the nodes across.
  3. Insert the pending node into whichever half it belongs to.
  4. Insert the separator (the right page's first key) into the parent, and recurse if the parent is full.
  - **Branch split:** the middle node moves up; its child becomes the right page's slot 0, stored with an empty key.
  - **Root split:** allocate a new branch root `[−∞ → left, sep → right]` and increment the depth.
- **Copy-on-write:** pages replaced by copy-on-write are simply abandoned; the free list arrives in step 5. Keep a `freed: [dynamic]Pgno` in the transaction anyway, filled but not yet used, so step 5 only has to consume it.
- **Rule for write-transaction slices:** a slice returned by `get` in a write transaction is invalidated by the next `put`. Document this in the `get` doc comment.

### Dependencies
- KV-T-0004 (`Txn`, `page_ptr`, tree search and `Path`).

### Risk Considerations
- **Splits are the most bug-prone code in the project.** Mitigate with the `page_check` invariant checker after every change, and a debug `tree_check(txn)` that walks the whole tree. It verifies key order across pages, that branch separators bound their subtrees, that all leaves sit at the same depth, and that the `entries` count matches.
