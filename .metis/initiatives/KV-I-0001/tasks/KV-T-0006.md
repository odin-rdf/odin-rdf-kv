# Overflow values

## Parent Initiative

[[KV-I-0001]]

## Objective

Support values larger than the overflow threshold. They are stored in a contiguous run of overflow pages that the leaf node references, and `get` returns a single zero-copy slice covering the whole value.

## Acceptance Criteria

- [ ] **`put` with a large value** (the leaf node would exceed `overflow_threshold`):
  - allocate `n = ceil((header + val_len) / page_size)` contiguous pages with `page_alloc(txn, n)`;
  - write an overflow header (flags `OVERFLOW`, `overflow_count = n`) followed by the value;
  - store a leaf node with the `BIGDATA` flag and the first page number.
- [ ] **The whole run is one dirty buffer** of `n * page_size`, keyed by its first page number. Commit (KV-T-0007) writes it with a single `pwrite`.
- [ ] **`get` on a `BIGDATA` node** returns `page_ptr(first)[header : header + val_len]` as one slice. In read transactions it points into the map; in write transactions, into the dirty buffer.
- [ ] **Overwrite:** replacing a large value with a small one, or the reverse, works. The old run's page numbers go to `txn.freed` and are otherwise abandoned (reuse comes in step 5).
- [ ] **`page_ptr` on an overflow run** is only ever called with the first page number. Assert this in debug builds.
- [ ] **Tests:**
  - values of size threshold − 1, threshold, and threshold + 1;
  - a value exactly filling n pages, and one byte more;
  - a 10 MB value;
  - overwrites in both directions;
  - after commit (once KV-T-0007 exists), the slice lies inside the map and matches byte for byte.

## Implementation Notes

### Technical Approach
- **Dirty storage for runs:** extend the dirty interface with the run length (`dirty_put(txn, pgno, buf)` where `len(buf)` may be `n * page_size`).
- **No `page_touch` for overflow pages:** they are immutable once written. An overwrite always writes a new run.
- **Where the value comes from:** the value is copied from the caller's buffer into the run buffer. Step 6 will switch this to a direct `pwrite` to avoid the heap copy; keep the write in one helper (`overflow_write`) so that change stays local.

### Dependencies
- KV-T-0005 (write path, `page_alloc`, dirty interface). Can run in parallel with KV-T-0007 and KV-T-0008.

### Risk Considerations
- **Very large values** are limited by `map_size` and by the arena memory used until commit. That's acceptable in this initiative; step 6 removes the heap copy.
