# Overflow values

## Parent Initiative

[[KV-I-0001]]

## Objective

Support values larger than the overflow threshold. They are stored in a contiguous run of overflow pages that the leaf node references, and `get` returns a single zero-copy slice covering the whole value.

## Acceptance Criteria

- [x] **`put` with a large value** (the leaf node would exceed `overflow_threshold`):
  - allocate `n = ceil((header + val_len) / page_size)` contiguous pages with `page_alloc(txn, n)`;
  - write an overflow header (flags `OVERFLOW`, `overflow_count = n`) followed by the value;
  - store a leaf node with the `BIGDATA` flag and the first page number.
- [x] **The whole run is one dirty buffer** of `n * page_size`, keyed by its first page number. Commit (KV-T-0007) writes it with a single `pwrite`.
- [x] **`get` on a `BIGDATA` node** returns `page_ptr(first)[header : header + val_len]` as one slice. In read transactions it points into the map; in write transactions, into the dirty buffer.
- [x] **Overwrite:** replacing a large value with a small one, or the reverse, works. The old run's page numbers go to `txn.freed` and are otherwise abandoned (reuse comes in step 5).
- [x] **`page_ptr` on an overflow run** is only ever called with the first page number. Assert this in debug builds.
- [x] **Tests:**
  - values of size threshold − 1, threshold, and threshold + 1;
  - a value exactly filling n pages, and one byte more;
  - a 10 MB value;
  - overwrites in both directions;
  - after commit (once KV-T-0007 exists), the slice lies inside the map and matches byte for byte. *(Moved to KV-T-0007's tests: needs commit.)*

## Implementation Notes

### Technical Approach
- **Dirty storage for runs:** extend the dirty interface with the run length (`dirty_put(txn, pgno, buf)` where `len(buf)` may be `n * page_size`).
- **No `page_touch` for overflow pages:** they are immutable once written. An overwrite always writes a new run.
- **Where the value comes from:** the value is copied from the caller's buffer into the run buffer. Step 6 will switch this to a direct `pwrite` to avoid the heap copy; keep the write in one helper (`overflow_write`) so that change stays local.

### Dependencies
- KV-T-0005 (write path, `page_alloc`, dirty interface). Can run in parallel with KV-T-0007 and KV-T-0008.

### Risk Considerations
- **Very large values** are limited by `map_size` and by the arena memory used until commit. That's acceptable in this initiative; step 6 removes the heap copy.

### 2026-09-24: completed
- **Files:**
  - `kv/overflow.odin` (new): `overflow_write`, `overflow_value`, `overflow_check` and `overflow_free`;
  - `overflow_pages` in `page.odin`;
  - `put` in `write.odin` handles overflow values, `get` in `tree.odin` returns them, and `tree_check` validates runs;
  - `Write_State.loose` added in `txn.odin`;
  - `tests/overflow_test.odin` (7 new tests). The obsolete "overflow rejected" assertion was removed from `test_put_errors`.
- **Verification:**
  - All 56 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64; checks for the other targets are clean.
  - Three deliberate bugs were each caught: a replaced dirty run staying dirty, the run-length check removed, and the up-front map check ignoring overflow pages.
- **Moved to KV-T-0007:** the post-commit check (the overflow slice lies inside the map and matches byte for byte) needs commit.
- **Design decisions and deviations:**
  - **Page size of a run** is `overflow_pages(ps, n) = ceil((16 + n) / ps)`. The first page has a normal `Page_Header` with `flags = PAGE_OVERFLOW` and `overflow_count = n`, followed by the value. The rest of the last page is zeroed.
  - **Values are 16-byte aligned,** as the header is 16 bytes and runs are page-aligned (tested).
  - **Reads go through `overflow_value`, not `page_ptr`,** because `page_ptr` returns a single page. `overflow_value` returns the whole run from the dirty buffer or the map.
    - Instead of the acceptance text's "assert that `page_ptr` is only called with a run's first page", `overflow_check` validates each run before use: the page number is in range; the header records that page number and the `OVERFLOW` flag; `overflow_count` exactly equals `overflow_pages(val_len)`; and the run ends within `last_pgno`. Otherwise the result is `Corrupted`.
  - **Replacing an overflow value** (overwrite in either direction) calls `overflow_free`:
    - a committed run's pages go to `freed`;
    - a run written by this transaction is removed from the dirty map (so commit won't write dead pages) and its pages go to the new `Write_State.loose` list. No reader has ever seen loose pages, so step 5 can reuse them immediately.
  - **Overwrites of overflow values** always write a new run, even at the same size. Runs are immutable once written.
  - **Up-front map check** now also counts the value's run pages (`2 × depth + 1 + overflow_pages`).
  - **Value copying:** the value is still copied from the caller's buffer into an arena buffer. Step 6 will switch this to a direct `pwrite`; the copy is confined to `overflow_write`.
  - **`tree_check`** checks every run (via `overflow_check`), counts its pages as visited so a shared run is detected, and rejects a run whose key and value would have fitted inline.
