# Commit protocol and file growth

## Parent Initiative

[[KV-I-0001]]

## Objective

Make write transactions durable and visible. Implement `txn_commit`: grow the file, write every dirty page, sync, write the alternate meta page, sync, then publish the new snapshot. Handle `Map_Full` and I/O errors so the database always stays at its last committed state.

## Acceptance Criteria

- [x] **`txn_commit(^Txn) -> Error` on a write transaction:**
  1. If the transaction has no dirty pages, release it without changing anything on disk (no `txn_id` bump).
  2. Grow the file with `os_truncate` to at least `(last_pgno + 1) * page_size`. Grow in steps of `max(1 MiB, 1/8 of the file size)`, capped at `map_size`.
  3. `pwrite` every dirty page or run to `pgno * page_size`.
  4. Sync.
  5. Build the new `Meta`: `txn_id + 1`, root, depth, `last_pgno`, entries, free-list fields 0, checksum. `pwrite` it to slot `(txn_id + 1) & 1`.
  6. Sync.
  7. Publish the snapshot to `env` under the snapshot mutex.
  8. `dirty_reset`, then release the writer mutex.
- [x] **On a read-only transaction,** `txn_commit` behaves like `txn_abort` and returns `None`.
- [x] **On any I/O error** before step 5 completes, return `Io` and roll back like `txn_abort`: the snapshot and the on-disk meta pages are unchanged. After an error, `txn_abort` is still safe to call.
- [x] `txn_abort` after `txn_commit` is a no-op.
- [x] **Tests:**
  - put, commit, close, reopen, and `get` returns the values, including overflow values. For overflow values, the slice lies inside the map and matches byte for byte (moved here from KV-T-0006). Also cover replacing a *committed* overflow run, whose pages must go to `freed`;
  - 100 commits alternate between meta pages 0 and 1, and both stay valid;
  - after corrupting the *newer* meta page on disk, reopen falls back to the previous commit's state;
  - `Map_Full` during `put`, then `txn_abort`, then reopen: the database is intact and a later smaller transaction succeeds;
  - an empty commit leaves `txn_id` unchanged.

## Implementation Notes

### Technical Approach
- **Write in page-number order:** sort dirty page numbers before writing. It's cheap, gives sequential I/O, and lets adjacent pages be combined into a single `pwrite` later.
- **Writing the meta page:** reuse `meta_write` from KV-T-0002. The meta page is a full page.
- **Publishing:** assign the snapshot as one struct under the mutex, so readers never see a half-written snapshot.

### Dependencies
- KV-T-0005 (write transactions and dirty storage). Overflow tests require KV-T-0006.

### Risk Considerations
- **Durability depends on the sync order:** data sync, then meta write, then meta sync. Verify by inspection and code comments now; the kill-during-commit harness (step 7) will verify it empirically.
- **Growing the file** after a failed commit may leave the file larger than `last_pgno` requires. That's harmless: open validates `last_pgno ≤ file size`, not equality.

### 2026-09-24: completed
- **Files:**
  - `kv/commit.odin` (new): `txn_commit`, `file_grow`, `FILE_GROWTH_MIN`;
  - `Env.file_size` added in `kv/env.odin` (set at open, changed only by the writer);
  - `tests/commit_test.odin` (10 new tests).
- **Verification:**
  - All 66 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64; checks for the other targets are clean.
  - Two deliberate bugs were each caught: writing the meta page always to slot 0, and an empty commit writing a meta page.
- **Protocol as built:**
  1. Grow the file with `os_truncate` to at least `(last_pgno + 1) × ps`, in steps of `max(1 MiB, file_size / 8)`, capped at `map_size` and rounded up to the page size.
  2. `pwrite` the dirty pages and runs in sorted page order (keys collected into an arena slice and sorted).
  3. `os_sync`.
  4. `txn_id + 1`: `meta_write` to slot `txn_id & 1` (the one the previous commit didn't use).
  5. `os_sync`.
  6. Publish `env.snapshot` under `snapshot_mutex`.
  7. `txn_abort` (via `defer`) frees the write state, releases the writer mutex and decrements `active_txns`.
- **Decisions and deviations:**
  - **`txn_commit` always ends the transaction,** on success or failure, via `defer txn_abort`. `txn_abort` afterwards is a no-op (tested).
  - **Poisoned transactions:** committing one (`txn.err` set) returns that error and changes nothing (tested by setting `txn.err` directly).
  - **No-op commits:** a read-only transaction, or a write transaction with no dirty pages, commits as a no-op (no `txn_id` bump, meta pages untouched; tested).
  - **I/O errors** (tested by swapping `env.fd` for -1) return `Io`, leave the snapshot unchanged, release the writer lock, and the database reopens at the previous commit.
  - **A failed final sync** leaves the on-disk outcome undetermined (the new meta page may or may not be durable). This process keeps the old snapshot, and the next commit writes the same meta slot again, so both views converge. The same trade-off as LMDB; documented on `txn_commit`.
  - **Adjacent pages aren't combined** into one `pwrite`. The buffers aren't contiguous in memory, so that would need `pwritev`; left as a possible optimisation.
  - **`ftruncate` isn't strictly required,** because `pwrite` past the end also extends the file. It is kept so the file grows in large steps and `env.file_size` stays accurate.
- **Tests moved here from KV-T-0006 (both pass):**
  - a committed overflow value comes back after reopen as one slice inside the map, byte for byte equal;
  - replacing a committed overflow run puts its pages on `freed` (not `loose`).
- **Also tested:** snapshot isolation across a commit (an older reader keeps seeing its snapshot; a new reader sees the commit) and the file growth steps.
