# Cursors: first, last, seek, next and prev

## Parent Initiative

[[KV-I-0001]]

## Objective

Provide cursors for ordered traversal and range scans: `first`, `last`, `seek` (first key ≥ k), `next` and `prev`. They return zero-copy key and value slices, and work in both read and write transactions.

## Acceptance Criteria

- [x] **`Cursor`** is a value type holding a `^Txn`, the transaction generation at creation, and the `Path` stack from KV-T-0004 (page numbers and slot indices, `MAX_DEPTH = 24`). No heap allocation.
- [x] `cursor_open(^Txn) -> Cursor` needs no close procedure.
- [x] **`cursor_first`, `cursor_last`, `cursor_seek(key)`, `cursor_next` and `cursor_prev`** each return `(key, val: []byte, err: Error)`.
  - Moving off either end, or any operation on an empty tree, returns `Not_Found`.
  - `BIGDATA` values resolve to the overflow slice.
- [x] **`next` / `prev`:** move within the leaf. At a leaf boundary, pop to the nearest ancestor with a slot in that direction, step to it, then descend to the leftmost or rightmost leaf.
- [x] **`seek`:** tree search to the insertion point. If the point is past the end of the leaf, advance as `next` does.
- [x] **Invalidation rule:** in a write transaction, any `put` invalidates all open cursors of that transaction. `Txn` keeps a modification counter; in debug builds, a cursor asserts that its snapshot of the counter still matches, and that the transaction generation matches (to catch use after the transaction ended).
- [x] **Tests:**
  - a full forward scan equals the sorted key set, and a full backward scan equals it reversed;
  - `seek` for keys that exist, keys between two existing keys, a key before the first, and a key after the last;
  - a range scan `[a, b)` by `seek` and then `next` while the key is < b;
  - alternating `next`/`prev` across leaf boundaries and across two branch levels;
  - cursors in a write transaction see uncommitted changes;
  - cursor operations in a read transaction allocate nothing (tracking allocator).

## Implementation Notes

### Technical Approach
- **Resolve pages on every step:** each step calls `page_ptr` for each page number it needs, rather than caching pointers. This keeps the cursor valid across touches within the rules above, and gives step 6's accounting one hook to observe all accesses.
- **Share code with tree search:** `tree_search` and `cursor_seek` use the same `Path` descent. Factor it so both call one `descend(txn, key, path)`.

### Dependencies
- KV-T-0004 (read path and `Path`). The write-transaction tests need KV-T-0005. Can run in parallel with KV-T-0006 and KV-T-0007.

### Risk Considerations
- **Boundary stepping in `prev`** (going left across multiple levels) is easy to get wrong. The randomized comparison in KV-T-0009 covers it heavily.

## Status Updates

*To be added during implementation*

### 2026-09-24: completed
- **Files:** `kv/cursor.odin` (new); `page_check_header` in `tree.odin` is now package-private (shared with cursors); `tests/cursor_test.odin` (9 new tests).
- **Verification:**
  - All 75 tests pass with `-debug`, `-o:speed` and `-debug -sanitize:address` on macOS arm64; checks for the other targets are clean.
  - Three deliberate bugs were each caught: stepping back descending leftmost, `seek` not advancing past the end of a leaf, and `prev` after the end returning `Not_Found`.
- **API as built:**
  - `Cursor { txn, gen, mods, path: Path, state: Cursor_State }`;
  - `cursor_open(^Txn) -> Cursor`;
  - `cursor_first`, `cursor_last`, `cursor_seek(key)`, `cursor_next` and `cursor_prev` all return `(key, value, Error)`;
  - `cursor_stale(^Cursor) -> bool`, which is new.
- **Decisions beyond the task text:**
  - **Edge states, following LMDB:**
    - a fresh cursor: `next` behaves as `first` and `prev` as `last`;
    - running off the end returns `Not_Found` and keeps the path at the last key (`After_Last`): `next` keeps returning `Not_Found`, while `prev` returns the last key;
    - the start is symmetrical (`Before_First`);
    - `seek` past the last key returns `Not_Found` in `After_Last`.
  - **Invalidation:**
    - `first`, `last` and `seek` refresh the cursor's `gen`/`mods`, so a cursor made stale by a `put` becomes usable again once repositioned;
    - `next` and `prev` assert `!cursor_stale` in debug builds, except on an unpositioned cursor, which they just position;
    - `cursor_stale` is public, so callers and tests can check it.
  - **Stepping** (`cursor_step`): within a leaf only the slot index moves. At a leaf's edge the cursor climbs to the nearest ancestor with a slot in that direction and descends to the leftmost or rightmost leaf. At the edge of the tree it returns false and leaves the path unchanged.
  - **Checks while descending:** `descend_edge` checks every page like `tree_search` does (page number range, header page number, kind and bounds), so a damaged tree gives `Corrupted`.
  - **`tree_search` is shared** (the "factor into one descend" note): `cursor_seek` calls `tree_search`; `descend_edge` is the edge-descent counterpart.
  - **Overflow values** are resolved through `overflow_value` (tested in a write transaction).
- **Odin note:** an `if`/`else` expression can't choose between calls that return several values. Select the procedure first (`move := kv.cursor_next if forward else kv.cursor_prev`), then call it.
