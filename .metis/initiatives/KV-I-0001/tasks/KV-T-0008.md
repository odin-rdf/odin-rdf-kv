# Cursors: first, last, seek, next and prev

## Parent Initiative

[[KV-I-0001]]

## Objective

Provide cursors for ordered traversal and range scans: `first`, `last`, `seek` (first key ≥ k), `next` and `prev`. They return zero-copy key and value slices, and work in both read and write transactions.

## Acceptance Criteria

- [ ] **`Cursor`** is a value type holding a `^Txn`, the transaction generation at creation, and the `Path` stack from KV-T-0004 (page numbers and slot indices, `MAX_DEPTH = 24`). No heap allocation.
- [ ] `cursor_open(^Txn) -> Cursor` needs no close procedure.
- [ ] **`cursor_first`, `cursor_last`, `cursor_seek(key)`, `cursor_next` and `cursor_prev`** each return `(key, val: []byte, err: Error)`.
  - Moving off either end, or any operation on an empty tree, returns `Not_Found`.
  - `BIGDATA` values resolve to the overflow slice.
- [ ] **`next` / `prev`:** move within the leaf. At a leaf boundary, pop to the nearest ancestor with a slot in that direction, step to it, then descend to the leftmost or rightmost leaf.
- [ ] **`seek`:** tree search to the insertion point. If the point is past the end of the leaf, advance as `next` does.
- [ ] **Invalidation rule:** in a write transaction, any `put` invalidates all open cursors of that transaction. `Txn` keeps a modification counter; in debug builds, a cursor asserts that its snapshot of the counter still matches, and that the transaction generation matches (to catch use after the transaction ended).
- [ ] **Tests:**
  - a full forward scan equals the sorted key set, and a full backward scan equals it reversed;
  - `seek` for keys that exist, keys between two existing keys, a key before the first, and a key after the last;
  - a range scan `[a, b)` by `seek` and then `next` while the key is < b;
  - alternating `next`/`prev` across leaf boundaries and across two branch levels;
  - cursors in a write transaction see uncommitted changes;
  - cursor operations in a read transaction allocate nothing (tracking allocator).

## Implementation Notes

### Technical Approach
- **Resolve pages on every step:** each step calls `page_ptr` for each page number it needs, rather than caching pointers. This keeps the cursor valid across touches within the rules above, and gives step 6's accounting one hook to observe all accesses.
- **Share code with tree search:** `tree_search` and `cursor_seek` use the same `Path` descent. Factor it so both call one `descend(txn, key, path)`.

### Dependencies
- KV-T-0004 (read path and `Path`). The write-transaction tests need KV-T-0005. Can run in parallel with KV-T-0006 and KV-T-0007.

### Risk Considerations
- **Boundary stepping in `prev`** (going left across multiple levels) is easy to get wrong. The randomized comparison in KV-T-0009 covers it heavily.
