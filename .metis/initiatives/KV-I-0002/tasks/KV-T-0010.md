# Reader table

## Parent Initiative

[[KV-I-0002]]

## Objective

Track which snapshots live read transactions hold, so a writer can compute the oldest one still in use (KV-I-0002 REQ-001, decision D2). Nothing uses it for reuse yet; KV-T-0012 does.

## Acceptance Criteria

- [ ] `Env.readers` is a sorted `[dynamic]Reader_Slot{txn_id: Txn_Id, count: int}`, guarded by `snapshot_mutex`, with capacity reserved at `env_open` and freed at `env_close`.
- [ ] `txn_begin(ro)` registers under the lock that copies the snapshot. It increments the last slot if it holds the same `txn_id`, and appends a slot otherwise. It asserts that snapshots only increase.
- [ ] `txn_abort` (and so `txn_commit`) of a read transaction deregisters: binary search for the slot, decrement it, and remove it at zero. A write transaction never registers.
- [ ] A private `oldest_reader(env) -> (Txn_Id, bool)` (caller holds the lock) returns `readers[0]`. There's also an exported test hook, or a field that tests can read.
- [ ] In debug builds, `env_close` asserts the table is empty, alongside the existing `active_txns` check.
- [ ] NFR-001: once the table's capacity is reached it allocates nothing more. A tracking-allocator test shows that repeated `txn_begin(ro)`/`txn_abort` pairs allocate nothing.
- [ ] Tests:
  - many readers on one snapshot;
  - readers on several snapshots ended out of order, with `oldest` correct after each step;
  - a threaded test with readers beginning and ending while a writer commits, where the table ends empty and never has a slot at count 0 (run with `-sanitize:thread`).
- [ ] Deliberate-bug check: skip the deregistration, or remove the wrong slot, and a test fails. Record it here.
- [ ] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- The slots use `env.allocator`, not the caller's context allocator, because readers run on arbitrary threads. Reserve 16 at open.
- Removing a slot is `ordered_remove`, and it's O(live snapshots), which is tiny. The common case removes slot 0 or the last slot.
- `Txn` is a value that moves, so deregistration uses `txn.snapshot.txn_id` as its key. It must not store a slot index, because indices shift on removal.
- Update the comment in `txn_begin` that promises this step.

### Dependencies
None. This is the first task of KV-I-0002.

### Risk Considerations
- A read transaction that is never ended pins its slot forever. That's the documented caveat, and `env_close`'s debug assert catches it in tests.
- Growing the array while holding `snapshot_mutex` makes an allocation happen under the lock. It's rare, and acceptable (NFR-002 bounds the work, not allocations).
