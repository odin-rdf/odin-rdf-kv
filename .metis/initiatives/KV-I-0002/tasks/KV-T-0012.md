# Reuse freed pages

## Parent Initiative

[[KV-I-0002]]

## Objective

Allocate from the free list before extending the file, under the reuse horizon, with correct abort semantics and map-full accounting (KV-I-0002 REQ-002, REQ-005, REQ-006, REQ-007, decisions D1, D4, D5, D6).

## Acceptance Criteria

- [x] **Horizon:** `txn_begin(rw)` computes `oldest = min(oldest_reader, S − 1)` under `snapshot_mutex` (D1, D4), and moves `pending` records with `txn_id ≤ oldest` into `ready` (sorted merge, in place).
- [x] **`page_alloc(txn, 1)`** takes a loose page first, then the lowest `ready` page the transaction hasn't taken, and otherwise extends the file.
- [x] **`page_alloc(txn, n > 1)`** takes the lowest run of `n` consecutive untaken `ready` pages (first-fit, D5), and otherwise extends.
- [x] **Taken pages are tracked** in the transaction (an index into `ready` for the front, plus a sorted list for runs taken from the middle). `Env.free` isn't changed until publish, so an abort leaves it exactly as it was (REQ-006).
- [x] **Loose pages** are handed out again within the transaction. A reused page always gets a fresh dirty buffer; its old contents in the map are never read.
- [x] **The commit's free-list run** comes from a contiguous run of reusable pages when one exists (removing its records), and otherwise from extending the file. If neither is possible, commit returns `Map_Full` and the database stays at `S` (D6).
- [x] **`pages_available`:**
  - counts extension room, plus loose pages, plus untaken `ready` pages, as the KV-I-0002 "Map_Full accounting" section describes;
  - `put`'s up-front check uses it, and remains conservative;
  - a database whose file has reached `map_size` keeps accepting overwrites (REQ-007).
- [x] **Tests:**
  - a page freed by `T` is not reused while a reader holds `T − 1`, and is reused by the first write transaction after that reader ends;
  - pages freed by `S` are not reused by `S + 1`, but are reused by `S + 2` (D1);
  - `test_commit_falls_back_when_newest_meta_damaged`, and a new variant with many overwrite commits (heavy reuse) before the damage, both open intact at `S − 1`;
  - an overflow value is placed in a freed run;
  - an abort after heavy allocation leaves `Env.free` equal to its value before;
  - the I/O-error commit test leaves `Env.free` and the file at `S`;
  - overwrites at a full map succeed, and `Map_Full` for the free-list run leaves the database intact;
  - `space_check` after every commit in all of them.
- [x] **Deliberate-bug checks,** each failing a test, recorded here:
  - drop the `S − 1` term;
  - use `<` for `≤` in the horizon (should only delay reuse; confirm no test wrongly fails, and that a test *does* fail for `≤` → `≤ oldest + 1`);
  - release taken pages to `Env.free` before commit;
  - let `page_alloc` return a page from `pending`.
- [x] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- `ready` is sorted, so taking single pages in ascending order is a moving index, which needs no copy of `ready` per transaction. A run taken from the middle goes into a small sorted `taken` list, and both the index scan and the run search skip those pages.
- The first-fit run search is a linear scan for `n` consecutive page numbers, which is O(len(ready)). That's fine at the planned sizes; KV-T-0013 measures it.
- `page_touch` already treats any dirty page as not needing copy-on-write, and a reused page is dirty from the moment it's allocated. So no change is needed there, but add a test that touches a reused page twice.
- `overflow_free` on a run the transaction took from `ready` puts it in `loose` (it's in the dirty map), which is already correct. Verify it.

### Dependencies
- KV-T-0010 (`oldest_reader`).
- KV-T-0011 (`Env.free`, the free-list run, `space_check`).

### Risk Considerations
- **This is the task where a bug corrupts a reader's snapshot, not just the file size.** The isolation evidence is the D1 and reader tests here plus KV-T-0013's held-reader model and threaded tests.
- The mmap is read-only and pages are written with `pwrite`. A reused page is written only at commit, and only when no registered reader and neither meta slot reference it, so there's no torn view for a reader to see.

## Status Updates

### 2026-09-24: implemented

**What was built**
- `kv/txn.odin`:
  - `Write_State` gains `oldest` (the horizon), and the record of what the transaction took from `Env.free.ready`. The record has three parts: `ready_next` (every page before this index was taken as a single page), `taken` (sorted pages taken as runs, in the arena), and `ready_taken` (the count of both).
  - `txn_begin(rw)` computes `oldest` with the private `reuse_horizon`, under the `snapshot_mutex` that copies the snapshot: `min(oldest_reader, S − 1)`, or 0 when S = 0. After unlocking, still under `writer_mutex`, it calls `freelist_release`.
- `kv/freelist.odin`:
  - `freelist_release` moves pending records with `txn_id ≤ oldest` into `ready`. It is a sorted merge from the back, in place; the moved pages are sorted in the arena first. Everything that can fail is allocated before anything changes.
  - `freelist_build` leaves out the taken pages: those before `ready_next`, and those in `taken`. A page taken and then dropped again is in `loose`, so it is still listed exactly once.
  - `freelist_place` allocates the commit's run, from `next.ready` or at the end (see Decisions).
- `kv/write.odin`:
  - `page_alloc(txn, n)` tries three sources in order:
    - `n = 1`: pop a loose page;
    - the lowest untaken run of `n` in `ready` (`ready_run_find`, first-fit, which for `n = 1` is the lowest untaken page), recorded by `ready_take`;
    - otherwise `page_alloc_end` extends the file.
  - The buffer always comes fresh from the arena (`dirty_buf_alloc`) before any state changes, so an `Out_Of_Memory` takes nothing.
  - `ready_is_taken` is shared with `space_check`.
  - `pages_available(txn, singles, run)` replaces the page-count check (see Decisions). `put` passes `2·depth + 1` singles and the overflow run separately.
- `kv/commit.odin`: step 1 is `freelist_place`. The step list and the failure paragraph now describe reused pages and D6.
- `kv/check.odin`: in a write transaction, `space_check` skips records the transaction took from `ready`, since the tree or `loose` owns those pages now.
- Doc comments updated: `page_alloc`, `put`, `txn_commit`, `space_check`, the `Write_State` fields, and `freelist.odin`'s overview.

**Tests** (103 in total, 11 of them new)
- `tests/reuse_test.odin` (new, 7 tests):
  - `waits_for_reader`:
    - A reader holds snapshot 2 while commit 3 frees F (its path pages plus snapshot 2's run), and a second reader holds the latest snapshot.
    - For three more commits, the horizon stays 2. A probe transaction (single `page_alloc` calls until the file extends, then abort) is handed exactly `Env.free.ready`, lowest first and without F. The real overwrite-all commits write no page of F, and F stays pending with tag 3.
    - The held reader then still sees its round, and `space_check` passes on it.
    - After the readers end, the horizon is 5 and the probe includes all of F.
  - `keeps_previous_snapshot` (D1): pages freed by commit 3 are neither offered to nor written by transaction 4, and all of them are offered to transaction 5.
  - `loose_and_touched_pages`:
    - The first put copies the path into the lowest reusable pages (`ready_next == depth`).
    - A second put through the same reused leaf changes no counts: no new dirty page, no new freed page, nothing taken.
    - A replaced overflow run's pages come back from `page_alloc(1)`, each with a new buffer that is neither in the map nor the old run's, and registered in `dirty`.
  - `overflow_value_in_freed_run`: a 4-page value is placed in pages freed two commits earlier, and they are recorded in `taken`.
  - `abort_leaves_free_unchanged`: two heavy transactions (2,000 puts with overflow values, runs taken, loose pages) are aborted. `Env.free` is identical after each abort, and so is the state after beginning again.
  - `failed_commit_keeps_both_snapshots` (crash equivalent): the reused dirty pages are written to the file with `os_pwrite`, then the commit fails with `Io` before its meta page. On reopen the database is at S with round 4. With meta S damaged it falls back to S − 1 with round 3, and tree and space checks pass.
  - `full_map`:
    - A held reader forces overwrites to extend the file to the end of a 256 KiB map. Then 200 overwrite commits succeed on reused pages, writing more than 4× the map's pages, with `space_check` after each.
    - Finally a transaction takes every page left, so its commit returns `Map_Full`. The snapshot, `Env.free` and the writer lock are unchanged, and the reopened database matches its model.
- `tests/commit_test.odin`: `falls_back_after_heavy_reuse` makes 200 commits of 1–50 random overwrites, with `space_check` after each. The peak `last_pgno` is about 37, against more than 600 without reuse. It damages the newest meta page and checks every key against the S − 1 model.
- `tests/freelist_test.odin`:
  - `page_alloc_reuses_lowest_first`: a hand-written list, with an exact sequence of single, run and extension allocations. It checks `taken`, `ready_next` and `ready_taken`, that pending pages 9 and 10 are never handed out, and that `Env.free` is unchanged.
  - `freelist_run_length_fits_its_records`: 100 records place a 1-page run in reusable pages, 256 records give a 1-page run with 255 records, and 257 records have no fitting length and extend by 2. Each database reopens cleanly.
  - `put_needs_a_run_the_path_leaves`: with the map exactly full, an overflow put whose only reusable run the path copy would break is refused up front (`txn.err` stays `None`). The same put with a run above the path's pages succeeds and commits.
  - `open_hand_list` gained `last_pgno`, `root` (a one-leaf tree), `options`, and multi-page runs.
- Existing tests adjusted:
  - `round_trip` models reuse. At begin it releases records tagged below S. At commit it expects `(ready ∪ loose) − pages written − new run`. It also checks that a run placed at or below the old `last_pgno` came from reusable pages, and it requires both reuse and a reused run to have happened.
  - `io_error_leaves_free_unchanged` captures `Env.free` after begin, since the release at begin is the one permitted change, and requires every reusable page to have been taken.
  - `run_map_full` asserts that nothing is reusable, which it relies on under D1.
  - `run_model` fails if a put returns `Map_Full` with `txn.err` set, meaning it failed part-way.
  - `test_model_until_map_full` uses a 5 MiB map instead of 8. With reuse, 2,000 keys never fill 8 MiB. At 5 MiB it fills after about 60 commits and one or two reopens (checked over 14 seeds).

**Decisions and deviations**
- **The commit's run must be exactly as long as its records need.** The design said taking `k` reusable pages removes `k` records, "so `k` pages still suffice". They do suffice, but open validates `overflow_count == pages(count)` exactly.
  - `freelist_place` therefore looks for the `j` with `pages(n − j) = j`. The left side only falls as `j` grows, so at most one `j` fits, and it is at most `k`.
  - It takes that run first-fit from `next.ready`. If there is no such `j` (for example 257 records at 4 KiB) or no free run of that length, it extends by `pages(n)`.
  - This is a closed-form choice with no iteration.
  - The run is placed from the list being built rather than through `page_alloc`, so what it takes leaves that list. That list already includes unused loose pages.
- **`pages_available` accounts for single pages breaking the run.** Singles are taken lowest-first, and a put copies its path before writing its overflow run, so the path can consume the reusable run the check counted on.
  - An overflow put needs `singles + run ≤ end room + loose + untaken`, and one of two things:
    - the run fits at the end of the map, or
    - a reusable run of `run` pages exists after skipping the lowest `min(singles − loose, untaken)` untaken pages.
  - Any allocation order is then covered. Deliberate check 6 below showed that the plain version passed every test while being unsound.
- **Loose pages are popped (last first), not lowest first**, and runs never come from loose pages. That matches the criteria (loose first for single pages) but not D5's "lowest" for them.
- **`txn_begin(rw)` can return `Out_Of_Memory`** if `ready` can't grow for the release. It returns before anything changes and releases the writer lock.
- **`Write_State.ready_taken`** is a counter, so `pages_available` gets the untaken count in O(1). Single-page takes skip pages already in `taken`, so nothing is counted twice.
- **Why the completed-commit fallback tests can't catch a dropped D1:** once commit S + 1 is complete, the fallback is S, not S − 1, and S is protected by the vision's rule alone. D1 protects S − 1 while commit S + 1 is in progress. `failed_commit_keeps_both_snapshots` simulates exactly that, and it is the test that catches the bug (check 1).

1. *Drop the `S − 1` term* (`oldest := s`): 8 tests fail.
   - `failed_commit_keeps_both_snapshots` fails: the fallback reads `r5_0` where it expects round 3, because a page of S − 1 was overwritten.
   - `keeps_previous_snapshot` and `waits_for_reader` fail (horizon 6, expected 5).
   - Also `round_trip`, `io_error`, `run_map_full`, `page_alloc_reuses_lowest_first`, and `space_check_catches_leak_and_double` (which reads `pending[0]` and traps on an empty list).
2. *`<` for `≤` in the release*: 5 tests fail, and every one of them is a reuse-timing assertion:
   - `keeps_previous_snapshot` ("transaction 5 may not reuse pages freed by 3");
   - `waits_for_reader` (nothing reusable while held);
   - `loose_and_touched_pages` and `overflow_value_in_freed_run` (the pages weren't reusable yet);
   - `round_trip`'s expected state.

   No integrity check fails: `space_check`, `tree_check`, the model tests, isolation, both fallback tests, and the held-reader comparisons all pass. So `<` only delays reuse, as expected.
3. *`≤ oldest + 1`* (over-eager): 9 tests fail.
   - `waits_for_reader`: the held reader on snapshot 2 reads `r3_0`, so its snapshot is corrupted.
   - `failed_commit_keeps_both_snapshots`: the fallback reads round 5.
   - `test_snapshot_isolation_across_threads`: a reader never finished a scan.
   - Also `keeps_previous_snapshot`, `round_trip`, `io_error`, `run_map_full`, `page_alloc_reuses_lowest_first` and `space_check_catches`.
4. *Release taken pages to `Env.free` before commit* (`ready_take` removes them from `Env.free.ready`): 12 tests fail.
   - `abort_leaves_free_unchanged`: ready pages changed across attempts.
   - `full_map`'s D6 step, `page_alloc_reuses_lowest_first` and `io_error`.
   - `space_check` reports "owned twice" or "owned by nothing" in `round_trip`, `failed_commit`, `keeps_previous`, `loose`, `overflow` and `waits_for_reader`.
5. *`page_alloc` returns a page from `pending`*:
   - Without removing the record: 17 tests fail, including tree corruption, lost entries in `alternate_meta_pages`, and the isolation test's new reader.
   - Popping the record, so `Env.free` stays self-consistent after commit: 15 tests fail. `space_check` in the write transaction reports "owned twice" in 6 tests; "pending records changed" in `abort`, `full_map`, `page_alloc_reuses_lowest_first` and `run_map_full`; and the isolation test fails.
6. *`pages_available` without the skip* (the run search counts pages the path will take): at first no test failed. The new `put_needs_a_run_the_path_leaves` fails it: the put returns `Map_Full` with `txn.err = Map_Full`, which means it failed part-way.
7. *`freelist_place` without the exact-length rule* (always `j = k`): at first only the model test caught it ("bad free-list run", and only for lists of about 256 records). The new `freelist_run_length_fits_its_records` fails both cases, with `Corrupted` on reopen.
8. *Never place the run in reusable pages*: 5 tests fail:
   - `round_trip` ("no page was reused");
   - `falls_back_after_heavy_reuse` ("pages were not reused");
   - `run_length_fits`;
   - `full_map` (commit `Map_Full` at round 9);
   - `put_needs_a_run`.
9. *`freelist_build` keeps taken pages*: 5 tests fail:
   - `round_trip` (list on disk differs);
   - the model test (get returned a wrong value);
   - `abort` and `overflow_value_in_freed_run` (bad overflow run).

**Open concerns (for KV-T-0013)**
- The costs to measure:
  - `txn_begin(rw)` now does an O(len(ready)) merge whenever records are released, and may allocate with `env.allocator`.
  - `ready_run_find` is linear per run allocation, and `pages_available` calls it for overflow puts once the end of the map is too small.
- By design (D4), a reader that ends mid-transaction isn't noticed until the next write transaction.
- `pages_available` is conservative. With the map full, it can refuse an overflow put that would have fit had the path used other pages.
