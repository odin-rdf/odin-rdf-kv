# Reuse freed pages

## Parent Initiative

[[KV-I-0002]]

## Objective

Allocate from the free list before extending the file, under the reuse horizon, with correct abort semantics and map-full accounting (KV-I-0002 REQ-002, REQ-005, REQ-006, REQ-007, decisions D1, D4, D5, D6).

## Acceptance Criteria

- [ ] **Horizon:** `txn_begin(rw)` computes `oldest = min(oldest_reader, S − 1)` under `snapshot_mutex` (D1, D4), and moves `pending` records with `txn_id ≤ oldest` into `ready` (sorted merge, in place).
- [ ] **`page_alloc(txn, 1)`** takes a loose page first, then the lowest `ready` page the transaction hasn't taken, and otherwise extends the file.
- [ ] **`page_alloc(txn, n > 1)`** takes the lowest run of `n` consecutive untaken `ready` pages (first-fit, D5), and otherwise extends.
- [ ] **Taken pages are tracked** in the transaction (an index into `ready` for the front, plus a sorted list for runs taken from the middle). `Env.free` isn't changed until publish, so an abort leaves it exactly as it was (REQ-006).
- [ ] **Loose pages** are handed out again within the transaction. A reused page always gets a fresh dirty buffer; its old contents in the map are never read.
- [ ] **The commit's free-list run** comes from a contiguous run of reusable pages when one exists (removing its records), and otherwise from extending the file. If neither is possible, commit returns `Map_Full` and the database stays at `S` (D6).
- [ ] **`pages_available`:**
  - counts extension room, plus loose pages, plus untaken `ready` pages, as the KV-I-0002 "Map_Full accounting" section describes;
  - `put`'s up-front check uses it, and remains conservative;
  - a database whose file has reached `map_size` keeps accepting overwrites (REQ-007).
- [ ] **Tests:**
  - a page freed by `T` is not reused while a reader holds `T − 1`, and is reused by the first write transaction after that reader ends;
  - pages freed by `S` are not reused by `S + 1`, but are reused by `S + 2` (D1);
  - `test_commit_falls_back_when_newest_meta_damaged`, and a new variant with many overwrite commits (heavy reuse) before the damage, both open intact at `S − 1`;
  - an overflow value is placed in a freed run;
  - an abort after heavy allocation leaves `Env.free` equal to its value before;
  - the I/O-error commit test leaves `Env.free` and the file at `S`;
  - overwrites at a full map succeed, and `Map_Full` for the free-list run leaves the database intact;
  - `space_check` after every commit in all of them.
- [ ] **Deliberate-bug checks,** each failing a test, recorded here:
  - drop the `S − 1` term;
  - use `<` for `≤` in the horizon (should only delay reuse; confirm no test wrongly fails, and that a test *does* fail for `≤` → `≤ oldest + 1`);
  - release taken pages to `Env.free` before commit;
  - let `page_alloc` return a page from `pending`.
- [ ] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- `ready` is sorted, so taking single pages in ascending order is a moving index, which needs no copy of `ready` per transaction. A run taken from the middle goes into a small sorted `taken` list, and both the index scan and the run search skip those pages.
- The first-fit run search is a linear scan for `n` consecutive page numbers, which is O(len(ready)). That's fine at the planned sizes; KV-T-0013 measures it.
- `page_touch` already treats any dirty page as not needing copy-on-write, and a reused page is dirty from the moment it's allocated. So no change is needed there, but add a test that touches a reused page twice.
- `overflow_free` on a run the transaction took from `ready` puts it in `loose` (it's in the dirty map), which is already correct. Verify it.

### Dependencies
- KV-T-0010 (`oldest_reader`).
- KV-T-0011 (`Env.free`, the free-list run, `space_check`).

### Risk Considerations
- **This is the task where a bug corrupts a reader's snapshot, not just the file size.** The isolation evidence is the D1 and reader tests here plus KV-T-0013's held-reader model and threaded tests.
- The mmap is read-only and pages are written with `pwrite`. A reused page is written only at commit, and only when no registered reader and neither meta slot reference it, so there's no torn view for a reader to see.
