# Page-level merge primitives and page_free

## Parent Initiative

[[KV-I-0003]]

## Objective

Give the page layer what `del` needs to merge and drop pages (KV-I-0003 D2, D4, D6, D8), so that KV-T-0017 only has to decide *when* to merge, not how. Nothing calls these from `del` yet.

## Acceptance Criteria

- [ ] A merge primitive in `page.odin` moves all of `src`'s nodes into `dst`, either after `dst`'s nodes (a right sibling) or before them (a left sibling), and leaves `dst` compacted. `src` is not modified (the caller frees it). It rebuilds through a stack `Page_Scratch`, as `page_move_upper` does, and allocates nothing.
- [ ] For branch pages, the merge takes the separator key for the right-hand page's slot-0 node (−∞ until now), and that node gets the key on the way (D6). The caller passes a copy of the key, not a slice into the parent.
- [ ] A procedure makes a branch page's slot 0 −∞ after its first node was removed: the new first node keeps its child and loses its key.
- [ ] `page_underfull(page)`: `page_used < (page_size − PAGE_HEADER_SIZE) / 4` (D4).
- [ ] A fit test: whether two pages (plus the separator a branch merge brings down) fit in one page, exact at the boundary. The merge asserts it.
- [ ] `page_free(txn, pgno)` (D8): a dirty page leaves `dirty` and goes to `loose`, any other goes to `freed`. `overflow_free` uses the same rule through it, or a shared helper, and its behaviour doesn't change.
- [ ] Tests in `tests/page_test.odin`, each followed by `page_check`:
  - leaf merge from the right and from the left, keys in order, values intact (inline and `BIGDATA` nodes);
  - branch merge from the right and from the left, with the separator brought down onto the right page's first node and the children intact;
  - making slot 0 −∞;
  - the fit test one byte either side of the boundary, for leaves and branches;
  - `page_underfull` either side of the threshold.
- [ ] Deliberate-bug check: bring no separator down in a branch merge, or skip clearing slot 0's key, and a test fails. Record it here.
- [ ] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- The merged sequence is `left ++ right` in both directions. Only which buffer is the destination differs, so one procedure with a side flag (or two thin wrappers) over a shared rebuild should do.
- A branch's slot-0 node is stored with an empty key, so bringing the separator down changes that node's size: rebuild it with `branch_insert` semantics rather than copying its raw bytes.
- Clearing slot 0: `node_remove` then `branch_insert(page, 0, nil, child)`, as the split code already does for the right page.
- Whether `del` lives in `write.odin` or a new `delete.odin` is decided in KV-T-0017; these primitives belong in `page.odin` (the page ones) and next to `page_alloc` (`page_free`).

### Dependencies
None. First task of KV-I-0003.

### Risk Considerations
- Clone before modifying: the separator is a key in the parent, and the parent changes right after the merge. The primitive takes a caller-owned copy.
- The fit test must count the separator's full node size (`branch_node_size(len(sep)) − branch_node_size(0)`), not just its bytes, or a merge could overflow the page.
