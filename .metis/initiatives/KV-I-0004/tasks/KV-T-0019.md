# Measure eviction and residency on macOS and Linux

## Parent Initiative

[[KV-I-0004]]

## Objective

Find out, on the real platforms, what the memory budget's mechanisms actually do before anything is built on them (KV-I-0004 D12). The vision says macOS eviction and `mincore` semantics *need to be verified empirically*, and review found that `core:mem/virtual`'s `decommit` uses the lazy `MADV_FREE`. The results decide the eviction method (D9), the OS check (D10) and how the dirty pool releases memory (D1).

## Acceptance Criteria

- [ ] A test-only measurement (under `tests/`, registered only with a define such as `-define:KV_PLATFORM=true`), not code in `kv/`.
- [ ] **File mapping, read-only `MAP_SHARED`, `MADV_RANDOM`:** touch ranges, then evict with each candidate, and record the process's resident size and what each method reports after each step:
  - macOS: `MADV_DONTNEED`, `MAP_FIXED` remap of the same file range, `msync(MS_INVALIDATE)` if it has any effect;
  - Linux: `MADV_DONTNEED` (and, for the record, `MADV_PAGEOUT`).
- [ ] **What each residency source reports** for the same ranges: `mincore`, `/proc/self/pagemap` present bits (Linux), the per-region resident count (`mach_vm_region` on macOS, `/proc/self/smaps` on Linux) and process RSS. In particular whether macOS `mincore` counts page-cache pages that aren't mapped into the process (the vision expects it to overcount).
- [ ] **Remap under load (macOS):** reader threads read the range continuously while another remaps it with `MAP_FIXED`, for long enough to trust: no fault, no wrong byte, and addresses stay valid. Run under TSan too.
- [ ] **Anonymous memory release (D1):** resident size after committing and writing a 4 MiB region, then `MADV_FREE`, `MADV_DONTNEED`, `MADV_FREE_REUSABLE` (macOS) and an anonymous `MAP_FIXED` remap. Which drop the resident size at once.
- [ ] The cost of each eviction and release call per chunk (256 KiB and 64 KiB), and of a refault from the page cache.
- [ ] Results recorded in this task's Status Updates, with platform and OS versions. D1, D9 and D10 in KV-I-0004 are amended if they disagree, with a note saying what moved.
- [ ] Run on macOS arm64 and in the Linux containers (arm64, amd64). Note where container results may differ from bare metal.

## Implementation Notes

### Technical Approach
- A standalone test file with its own small `mmap`/`madvise` wrappers; `kv/os_*.odin` doesn't change in this task.
- Resident size: macOS `task_info(TASK_VM_INFO)` (`resident_size`, and `phys_footprint` for the anonymous case); Linux `/proc/self/statm` or `smaps_rollup`, and the mapping's own entry in `/proc/self/smaps` for a per-range figure.
- Use a file of about 64 MiB so the numbers stand out from noise, and read it once first so it's in the page cache.

### Dependencies
None. First task of KV-I-0004, and it can run alongside KV-T-0020.

### Risk Considerations
- If no macOS method lowers the resident size of a shared file mapping, eviction on macOS falls back to the least bad method and the budget is Linux-only in practice. Production is Linux; macOS is the development platform. Record that plainly if it happens.
- Container results on Linux can differ from bare metal (cgroup accounting). The present bits and RSS are per process, so they should not.
