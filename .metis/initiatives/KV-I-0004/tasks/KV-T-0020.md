# Dirty-page pool with a fixed budget

## Parent Initiative

[[KV-I-0004]]

## Objective

Replace the write transaction's per-transaction arena for dirty pages with a pool of page slots, fixed at open and owned by the `Env` (KV-I-0004 D1). This task gives the pool and its limit; spilling (KV-T-0021) makes the limit invisible to callers. Until then, a transaction needing more slots than the pool has returns `Out_Of_Memory`.

## Acceptance Criteria

- [ ] `Options.dirty_budget` in bytes: 0 means the default, `DEFAULT_DIRTY_BUDGET` = 4 MiB. Rounded up to whole pages. Less than `(2 × MAX_DEPTH + 1)` pages returns `Invalid_Argument` from `env_open`.
- [ ] `env_open` reserves the pool's address space once (no physical memory); `env_close` releases it.
- [ ] A slot is committed when first used. When the write transaction ends (commit or abort), every committed slot is released with the method KV-T-0019 found to drop the resident size at once (expected: `MADV_DONTNEED` on Linux; on macOS an anonymous `MAP_FIXED` remap or `MADV_FREE_REUSABLE`). Not `virtual.decommit`, which uses the lazy `MADV_FREE`.
- [ ] `Write_State.dirty` maps a page number to a slot. An overflow run (still a dirty buffer until KV-T-0021) takes consecutive slots, so the pool hands out contiguous ranges.
- [ ] `page_ptr`, `page_touch`, `page_alloc`, `page_free`, `overflow_value` and `txn_commit` work through slots; behaviour is otherwise unchanged. `Write_State.arena` keeps the page lists (`freed`, `loose`, `taken`) and the dirty map.
- [ ] Pages stay page-aligned (16-aligned at least), as the overflow alignment guarantee needs.
- [ ] `Stats` gains `dirty_budget`, `dirty_pages` (slots in use by the current writer) and `dirty_committed` (bytes committed), live atomics readable during a write transaction. The `Stats` doc comment is updated for that exception.
- [ ] Tests: the budget's validation and rounding; `dirty_pages` rises during a transaction and is 0 after commit and after abort; the resident size of the pool drops after the transaction (checked with the OS figure from KV-T-0019's measurement where available); a transaction exceeding the pool returns `Out_Of_Memory` and can be aborted cleanly; the whole existing suite passes with the default budget.
- [ ] Deliberate-bug check: skip releasing the slots at transaction end, and a test fails. Record it here.
- [ ] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- The pool is `dirty_budget / page_size` slots with a bitmap or free stack of slot indices; contiguous ranges for overflow runs can be found by a linear scan (runs go away from the pool in KV-T-0021, so this is temporary).
- Committed/uncommitted tracking per slot, so a slot is committed once per transaction and released at the end in one call per contiguous committed range.
- The pool belongs to the `Env` and is used only with `writer_mutex` held.

### Dependencies
None in code. KV-T-0019 decides the release method; if it isn't done yet, use `MADV_DONTNEED` on Linux and leave the macOS method behind one procedure so it can change.

### Risk Considerations
- Every place that holds a `[]byte` into a dirty buffer today must keep working with slot-backed buffers; since slots don't move within a transaction, this should be a local change.
- A per-commit release adds page faults to the next transaction; measure it in passing (expected: microseconds against a synced commit's milliseconds).
