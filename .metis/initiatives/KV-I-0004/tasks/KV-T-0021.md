# Spill dirty pages, and write overflow and free-list runs directly

## Parent Initiative

[[KV-I-0004]]

## Objective

Make `dirty_budget` a hard limit that callers never hit: when the pool runs short, write the least recently touched dirty pages to their final places in the file before the next operation (KV-I-0004 D2–D4), and never hold an overflow run or the free-list run in the pool as a whole (D5, D6).

## Acceptance Criteria

- [ ] **The boundary check (D2):** at the start of `put` and `del`, next to `pages_available`, if the pool has fewer free slots than the operation's worst case (`2·depth + 1` for `put`, `depth` for `del`), spill. Nothing spills inside an operation.
- [ ] **What is spilled (D3):** each slot records the `mods` value of its last touch; a spill takes the least recently touched quarter of the pool (at least what the operation needs), sorts it by page number and writes it with `pwrite`. `Stats.spills` counts pages spilled.
- [ ] **Spilled pages (D4):** kept in a `spilled` set. Reads go through the map. `page_touch` of a spilled page copies it back into a slot under the same page number, with no copy-on-write and no `freed` entry. `page_free` of a spilled page puts it on `loose`. The file is grown before any write past its end (`file_grow` moves out of `commit.odin`).
- [ ] **Commit:** writes the remaining dirty slots, then syncs once, which covers the spilled pages. Abort after spills leaves the database and the free list as they were.
- [ ] **Overflow runs (D5):** `overflow_write` writes the header page through one slot and the value from the caller's buffer with `pwrite`, and records the run as spilled. A value larger than the pool commits.
- [ ] **Free-list run (D6):** `freelist_write` fills and writes one page at a time through one slot. A free list longer than the pool commits.
- [ ] The dirty pool never exceeds its budget: asserted after every operation in the tests below.
- [ ] Tests with the minimum budget (49 pages):
  - a transaction writing 10× its pool commits; every key reads back before and after commit through `get` and both cursor directions;
  - a spilled page re-touched keeps its page number; a spilled page freed goes to `loose`; `space_check` after every commit;
  - abort after spilling, then commit something else: database, free list and `space_check` as before;
  - a reader holding a snapshot across spilling transactions still reads its data;
  - the randomized model, the isolation test (TSan) and the steady-state tests run with the minimum budget as well as the default (the steady ones on demand, as now).
- [ ] Deliberate-bug checks, each failing a test, recorded here: spill inside an operation (for example from `page_alloc`); copy-on-write a spilled page on re-touch; skip `file_grow` before a spill; free a spilled page to `freed`.
- [ ] The spill cost per page is measured and recorded.
- [ ] `scripts/test.sh` and `scripts/test-linux.sh` (arm64, amd64) pass.

## Implementation Notes

### Technical Approach
- The worst case must count re-touches of spilled pages on the path (each needs a slot), which `2·depth + 1` already covers because a touched path page needs at most one slot either way.
- Spilling to a reused page is safe because pages this transaction allocated are in no snapshot anyone can read (KV-I-0002 D1). A comment at the spill site should say so, since step 7's crash tests rely on it.
- `put`'s rule that `key` and `value` must not point into the transaction's own pages now also covers spilled pages read through the map: they don't move, so no new restriction is expected, but check it.

### Dependencies
KV-T-0020 (the pool).

### Risk Considerations
- Spilling adds writes before the meta page is written; step 7's kill-during-commit harness must cover "killed after a spill, before commit". Note it in the vision when this initiative completes.
- The LRU scan is linear in the pool (1,024 slots at 4 MiB). Fine for a quarter-pool batch; measure if it shows up.
