# Chunk accounting for mapped pages

## Parent Initiative

[[KV-I-0004]]

## Objective

Keep the store's own estimate of how much of the map is resident, in chunks, on every page access (KV-I-0004 D7, D11). No eviction yet: this task makes the estimate exist and cheap, and reports it.

## Acceptance Criteria

- [x] `Options.chunk_size`: 0 means 256 KiB; otherwise a power of two, at least 64 KiB and at least the page size, else `Invalid_Argument`. `map_size` is rounded up to whole chunks.
- [x] `Options.mapped_budget` in bytes, 0 meaning no budget (accounting on, no eviction). Stored for KV-T-0023.
- [x] A chunk table of one byte per chunk with two bits, `resident` and `referenced`, updated atomically, and an atomic `resident_chunks`.
- [x] `page_ptr` for a page read from the map: an atomic load of the chunk's byte; set `referenced` if clear; if `resident` is clear, set it with a CAS and, if this thread won, increment `resident_chunks` and call an out-of-line hook (the watermark check in KV-T-0023; a no-op here). Dirty-page reads don't count.
- [x] `overflow_value` marks every chunk of the run. `freelist_load` marks the chunks it read.
- [x] `Stats` gains `mapped_budget`, `chunk_size`, `resident_chunks` and `chunk_faults` (cumulative chunk transitions to resident), plus `free_list_bytes` (the RAM `Env.free` holds).
- [x] Tests: reads crossing a chunk boundary mark both chunks once; an overflow value spanning chunks marks them all; concurrent readers on the same chunk count it once (threads, TSan); `chunk_faults` equals `resident_chunks` before any eviction; option validation.
- [x] **Read throughput with accounting on and off** (a define that compiles it out, for the measurement only), on the existing read benchmarks, recorded here (NFR-002: target under 5%).
- [x] Deliberate-bug check: increment the count without the CAS (plain store), and the concurrent test fails under TSan or by count. Record it here.
- [x] `scripts/test.sh` passes.

## Implementation Notes

### Technical Approach
- `page_ptr` is `#force_inline`; keep the fast path (bits already set) to a shift and one atomic load, and put everything else out of line.
- Avoid writing the byte when `referenced` is already set, so hot chunks shared between reader threads don't bounce a cache line.
- The chunk table's size is `map_size / chunk_size` bytes: 4 KiB for the default 1 GiB map at 256 KiB.

### Dependencies
None in code; it can be built before or after the spilling tasks. KV-T-0023 builds on it.

### Risk Considerations
- Pages faulted in through a held slice after an eviction aren't seen (a known limit, KV-I-0004 Q4); nothing to do here.

## Status Updates

### 2026-09-24: done

**What was built.**
- `kv/chunks.odin` (new): `Chunk_Table` in the `Env` (`env.chunks`): `bits`, one byte per chunk holding `CHUNK_RESIDENT` and `CHUNK_REFERENCED`; `size` and `shift`; `budget` (`Options.mapped_budget`, stored for KV-T-0023); the atomic counters `resident` and `faults`. `DEFAULT_CHUNK_SIZE` (256 KiB), `MIN_CHUNK_SIZE` (64 KiB, with `#assert(MIN_CHUNK_SIZE >= MAX_PAGE_SIZE)`), `chunk_size_valid`, `chunks_init`/`chunks_destroy`.
- **The fast path**, `chunk_touch(env, off)` (`#force_inline`, called by `page_ptr` for a page from the map only; the dirty branch returns before it): `bits[off >> shift]` loaded atomically (relaxed) and compared with both flags; when equal nothing else happens, so a hot chunk's byte is never written. On arm64 `-o:speed` it compiles to `ldr shift; asr; ldr bits; ldrb; cmp; b.ne` (checked in the disassembly of `cursor_current`). The shift is masked with `& 63` so the compiler drops Odin's over-shift check (two instructions), and `page_ptr` reads `map_base` before the accounting so it isn't reloaded after the out-of-line call's merge point.
- **The slow path**, `chunk_mark` (`#force_no_inline`): while `CHUNK_RESIDENT` is clear, a CAS sets both flags; the thread whose CAS wins adds 1 to `resident` and `faults` and calls `chunk_resident_added(env)`, the out-of-line hook for KV-T-0023's watermark check (empty here). Otherwise, if `CHUNK_REFERENCED` is clear, an atomic OR sets it.
- `chunks_touch_range(env, off, n)`: every chunk of a byte range, each through the same check. Called by `overflow_value` (the whole run, since the caller may read all of it), `freelist_load` (the run it read) and `space_check` (the free-list run it reads; tests only).
- `Options.chunk_size` (0 → 256 KiB; else a power of two ≥ 64 KiB, else `Invalid_Argument`) and `Options.mapped_budget` (bytes, 0 = no budget; negative is `Invalid_Argument`). `map_size` is rounded up to whole chunks, which replaces the rounding to `MAP_SIZE_GRANULE` (removed: a chunk is a multiple of it).
- `Stats`: `mapped_budget`, `chunk_size`, `resident_chunks` and `chunk_faults` (live, atomic loads), and `free_list_bytes` (the capacity of `Env.free`'s two arrays in bytes, kept with the other free-list figures by the new `stats_set_free`, now also used by the commit). The `Stats` and `env_stats` doc comments list the estimate among the live figures.
- `env_open` was reordered: the `Env` is allocated and the chunk table built right after the map is reserved, before anything is read from it, so the open's own reads are accounted: chunk 0 for the meta pages (both are in it at every page size `meta_choose` tries), and the free-list run's chunks. `freelist_load` takes the `Env` (`freelist_load(env, snap)`) instead of the base, page size and allocator.
- `-define:KV_NO_CHUNK_ACCOUNTING=true` (`CHUNK_ACCOUNTING`) compiles `chunk_touch` and `chunks_touch_range` to nothing, for the measurement only.

**Tests.** 149 (143 + 6), in `tests/chunk_test.odin`, all checking `expect_chunks_consistent` (the count equals the chunks flagged resident, `chunk_faults` equals `resident_chunks`, no chunk past the end of the file is resident):
- `test_chunk_options`: defaults (256 KiB, no budget, the map rounded up to whole chunks, a 4 KiB table for the default 1 GiB map, only chunk 0 resident after open); 64 KiB, 128 KiB and 1 MiB accepted, with the budget reported as given; 32 KiB, 4 KiB (the page size), 96 KiB, 768 KiB, a negative size and a negative budget refused; 32 KiB pages in 64 KiB chunks.
- `test_chunk_reads_cross_boundary` (64 KiB chunks, a ~1,000-page database reopened): the last page of chunk 1 and the first of chunk 2 mark one chunk each, with both flags; reading every page of both again adds nothing; a cleared `referenced` flag comes back without a second count; a full cursor scan marks exactly the chunks up to the last page.
- `test_chunk_dirty_reads_not_counted`: a page allocated in a write transaction, in a chunk nothing has read, is returned from the pool and marks nothing.
- `test_chunk_overflow_value_marks_run`: a 300 KiB value in a reopened database marks every chunk of its run (≥ 5) on one `get`; a second `get` adds nothing.
- `test_chunk_freelist_load_marks_run`: after an overwrite with a reader held, the free-list run lies past chunk 0; right after `env_open` the resident chunks are exactly chunk 0 and the run's chunks.
- `test_chunk_concurrent_readers`: 8 threads, 200 rounds; each round all threads start together (a barrier) and walk the same ~93 chunks (half upwards, half downwards), then the main thread checks each chunk was counted once and `chunk_faults == resident_chunks`, and clears the table for the next round, so every round races again.
- Changed: `test_env_stats` expects the new fields after open (`chunk_size`, 1 resident chunk, 1 fault) and checks `free_list_bytes` against `Env.free`; the two tests that open a 64 KiB map to reach `Map_Full` (`test_overflow_map_full`, `test_map_full_leaves_txn_usable`) now pass `chunk_size = MIN_CHUNK_SIZE`, since the default chunk would round their map up to 256 KiB; `test_env_map_covers_file` checks the map is a multiple of the chunk size.
- `tests/read_bench_test.odin`: `test_bench_read` (only with `-define:KV_BENCH=true`), the read benchmark this task needed; none existed.

**Decisions and deviations.**
- **"At least the page size" needs no check of its own:** `MIN_CHUNK_SIZE` (64 KiB) is above `MAX_PAGE_SIZE` (32 KiB), asserted at compile time, so a page never spans two chunks and the rule holds for any database, whose page size is only known after the map is read. It also covers the OS page size (16 KiB on Apple Silicon) and Linux's 64 KiB fault-around window (KV-T-0019), the reason for the minimum.
- **No upper bound on `chunk_size`,** as specified: a huge one makes the map huge, which fails where a huge `map_size` does.
- **A negative `mapped_budget` is `Invalid_Argument`** (the criterion only says what 0 means).
- **The CAS sets both flags at once,** so a chunk becoming resident is also referenced (a CLOCK sweep spares it once), in one write. All the chunk atomics are relaxed: no data is published through them, only counted.
- **The meta pages are accounted** (chunk 0 at open), and so is `space_check`'s read of the free-list run; neither was in the criteria, but both read the map, and leaving them out would make the estimate an undercount from the first open.
- **The hook is `chunk_resident_added(env)`**, taking the `Env`, since KV-T-0023's inline eviction needs the map. That is why `freelist_load` now takes the `Env`, and `env_open` builds it before reading anything.
- **`free_list_bytes` is the arrays' capacity,** the RAM held, not their length.

**Read throughput** (`test_bench_read`, `-o:speed`; a 200,000-key database of 100-byte values plus 5,000 values of 8 KiB, in the page cache; each workload warmed up once, so with accounting on every chunk is resident and referenced and `page_ptr` takes its fast path; 9 runs per process, the median; then the median over processes run alternately, on vs off). ns per operation:

| workload | macOS on | macOS off | Δ | Linux arm64 on | Linux arm64 off | Δ |
|---|---|---|---|---|---|---|
| random `get`, all keys | 385.1 | 389.4 | −1.1% | 415.4 | 414.4 | +0.2% |
| random `get`, 1,000 hot keys | 225.9 | 227.4 | −0.7% | 226.2 | 225.2 | +0.4% |
| cursor scan, per entry | 16.6 | 15.2 | **+9.2%** | 17.6 | 16.1 | **+9.3%** |
| random `get` of 8 KiB overflow values | 259.0 | 260.8 | −0.7% | 265.6 | 256.7 | +3.5% |
| random `get`, 4 threads (per get, all threads) | 110.3 | 109.9 | +0.4% | 112.0 | 111.3 | +0.6% |

macOS: 7 processes each, Apple M4, macOS 26.5.2. Linux: 5 each, OrbStack (kernel 7.0.14-orbstack), arm64. Run-to-run spread within a configuration is 2–5% for the gets and under 1 ns for the scan.

So **gets are within noise of no accounting, including four threads sharing hot chunks** (no write on the fast path), and overflow gets within 0–4%. **The cursor scan is ~9% slower, above NFR-002's 5% target:** about 1.4–1.5 ns per entry, from the two `page_ptr` calls a step makes (`cursor_step` and `cursor_current`, both on the same leaf), in a loop that does only 15 ns of work per entry. The fast path is already the minimum (a shift, two field loads, a byte load, a compare and a predicted branch); three variants were measured and none moved the scan: `intrinsics.expect` on the branch (kept, harmless), indexing by page number instead of byte offset (dropped), and reading `map_base` before the accounting (kept). What would move it is accounting the leaf once per cursor step instead of twice, which changes where accounting happens (not only in `page_ptr`) and so was not done here; see the open question below. The target is reported, not asserted.

**Deliberate-bug checks** (each restored):
- **The count without the CAS** (`chunk_mark` storing both flags with a plain atomic store and counting whenever it saw `CHUNK_RESIDENT` clear): `test_chunk_concurrent_readers` fails by count in every run: 164–169 of 200 rounds miscounted in debug (round 0: 96–98 chunks counted for 94 read), 126–132 in `-o:speed`, 117 under `-sanitize:thread`. TSan itself reports nothing (the store is atomic, so it is a logic race, not a data race); the count catches it.
- **Skipping `overflow_value`'s range marking:** `test_chunk_overflow_value_marks_run` fails ("chunk 5 of the run not marked").
- **Skipping `freelist_load`'s marking:** `test_chunk_freelist_load_marks_run` fails ("resident chunks [0], expected [0, 189]").

**Verification.**
- `scripts/test.sh`: 149 tests pass in debug, `-o:speed` and `-sanitize:address`; `odin check` passes for darwin/linux × arm64/amd64. `kv` also checks with `-vet -strict-style -define:KV_NO_CHUNK_ACCOUNTING=true`.
- `scripts/test-linux.sh arm64` and `amd64`: 149 pass, debug and `-o:speed`.
- `-sanitize:thread` on macOS arm64, three runs before the fast-path tuning and two after: `test_chunk_concurrent_readers`, `test_snapshot_isolation_across_threads`, `test_snapshot_isolation_min_pool` and `test_reader_table_across_threads` pass with no report.
- **The steady-state tests were not run** (at the owner's request); this task changes neither commit nor allocation.

**Open question for the owner (NFR-002).** Accept the ~9% on a tight cursor scan (gets are unaffected), or have the cursor account its leaf once per step: `cursor_step` and `cursor_current` read the same leaf, so one of them could use an unaccounted read. The cost is a narrow exception to "`page_ptr` accounts every read": if an eviction (KV-T-0023) lands between the two calls, the second read faults the page back in uncounted, the same undercount Q4 accepts for held slices, until the next step's accounted read. Not done here because it changes where accounting happens.


### 2026-09-24: scan cost accepted

The user accepted the ~9% cost on tight cursor scans (about 1.5 ns per entry) and kept counting every read in `page_ptr`: for the first deployment (a few hundred entries a day, behind HTTP requests) it is invisible, and the rule that every read of the map is counted stays simple. Counting the leaf once per cursor step was declined. NFR-002 stays missed for scans by this margin, recorded here and not revisited unless a workload shows it.
