# Eviction, env_sweep and the hard watermark

## Parent Initiative

[[KV-I-0004]]

## Objective

Keep the resident estimate under `mapped_budget` by evicting chunks, driven by the application through `env_sweep`, with inline eviction as the backstop (KV-I-0004 D8, D9). The store starts no thread (Q3).

## Acceptance Criteria

- [ ] **Platform eviction** in `kv/os_*.odin`, with the methods KV-T-0019 confirmed: Linux `MADV_DONTNEED`; macOS a `MAP_FIXED` remap of the same file range followed by `MADV_RANDOM` (unless the measurement chose otherwise). Every address stays valid.
- [ ] **Eviction order:** clear `resident` (and decrement the count) before evicting the range, so a racing reader can only cause an overestimate.
- [ ] **`env_sweep(env, target := -1) -> (evicted: int)`:** CLOCK over the chunk table under `evict_mutex`, clearing `referenced` on chunks it passes and evicting those without it. With the default target: nothing at or below the budget B (one atomic load), otherwise evict down to 7/8 B. An explicit target in bytes, 0 allowed, trims to it. Uses `try_lock`: a concurrent call returns 0 at once. Safe from any thread, with or without a transaction open. Without a budget, only an explicit target evicts.
- [ ] **Inline eviction (D8):** a `page_ptr` whose CAS takes the count past B + 2 chunks evicts, through the same code with `try_lock`, back down to B.
- [ ] Chunks past the end of the file are never marked resident and are skipped.
- [ ] `Stats` gains `evictions` (chunks), `sweeps` (calls that evicted something) and `inline_evictions`.
- [ ] Tests:
  - readers hold slices across evictions (by `env_sweep` and inline) and compare the bytes afterwards;
  - a threaded stress where reader threads call `env_sweep` concurrently, as request handlers would, under TSan, repeated;
  - a store that never sweeps stays within B + 2 chunks through inline eviction alone;
  - `env_sweep(env, 0)` leaves an estimate of 0, and the next reads fault back in and count again;
  - the default target is a no-op within budget;
  - write transactions and commits work across evictions (the writer's reads through the map included).
- [ ] Deliberate-bug checks, each failing a test, recorded here: evict before clearing `resident`; skip the `referenced` check (evict everything the hand passes); forget to re-apply `MADV_RANDOM` after a macOS remap (if a test can see it; otherwise note why not).
- [ ] `scripts/test.sh` and `scripts/test-linux.sh` (arm64, amd64) pass.

## Implementation Notes

### Technical Approach
- `evict_mutex` guards the CLOCK hand only; readers never take it, only `env_sweep` and the inline path.
- Evict contiguous runs of chosen chunks with one call where possible.
- `env_sweep(env, 0)` is the sleep path for an idle store (KV-I-0004 D9); its doc comment says so, and says that held slices stay valid.

### Dependencies
KV-T-0022 (the chunk table) and KV-T-0019 (the methods).

### Risk Considerations
- A macOS remap racing a writer's `pwrite` to the same range: the page cache is shared and `pwrite` doesn't go through the mapping, so it should be safe; the TSan stress includes a writer.
- If macOS eviction doesn't lower the resident size (KV-T-0019), the macOS tests assert the estimate only, and the OS-level assertions run on Linux.
