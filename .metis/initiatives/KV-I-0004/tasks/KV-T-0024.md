# OS residency check and the memory-budget criterion

## Parent Initiative

[[KV-I-0004]]

## Objective

Check the estimate against the OS (KV-I-0004 D10) and show the vision's success criterion: with a database of about 100 MB and a 20 MB budget, the resident footprint stays within about 1–2 chunks of the budget under mixed load, on macOS and Linux. Then close the initiative: measurements, vision, `CLAUDE.md` and Results.

## Acceptance Criteria

- [ ] **`env_resident_check(env) -> (resident_bytes: int, err: Error)`:** counts the map's pages present in the process over the file's extent. Linux: `/proc/self/pagemap` present bits, never `mincore`. macOS: the source KV-T-0019 found trustworthy (`mincore` if it only overcounts, otherwise the per-region resident count). It doesn't change the estimate (Q4).
- [ ] Tests: after reads, the check is at most the estimate plus a small tolerance; after `env_sweep(env, 0)`, it is near 0.
- [ ] **The criterion test**, on demand (a define, like the steady tests): a database of about 100 MB; `mapped_budget` about 15 MB and the default 4 MiB dirty pool; reader, scanner and writer threads, each calling `env_sweep` after every simulated request. Sample `env_resident_check` plus `dirty_committed` throughout and assert they stay within 2 chunks of the total budget. Run on macOS and Linux (arm64, amd64); if macOS eviction proved ineffective in KV-T-0019, the macOS run reports rather than asserts, and that is recorded.
- [ ] The drift between the estimate and the OS figure is reported (Q4 decides nothing is corrected unless it's large).
- [ ] **Measurements, recorded in this task and the initiative's Results:** the time `env_sweep` adds to a request (nothing to do; evicting); the memory left after `env_sweep(env, 0)` against after `env_close`; the time `env_open` takes to wake a store, with a short and a long free list.
- [ ] `scripts/test.sh --steady` passes, and the full matrix on macOS and Linux.
- [ ] Documentation:
  - the vision's Current State, and its memory-budget section amended: no sweeper thread, the application calls `env_sweep` (a dated note, the old text standing);
  - step 7's scope gains "killed after a spill, before commit";
  - `CLAUDE.md`: the new options, `env_sweep`, the test defines, and the code map;
  - KV-I-0004's Results: the exit-criteria table, deviations and known limitations, as KV-I-0003 has.

## Implementation Notes

### Technical Approach
- Read `/proc/self/pagemap` in batches over the file's pages only (8 bytes a page: 200 KiB for a 100 MB file).
- The 100 MB database is built once per run in a temporary directory with the bulk of values in the few-hundred-byte range and some overflow values, like conversation messages.

### Dependencies
KV-T-0021, KV-T-0022 and KV-T-0023. Last task of KV-I-0004.

### Risk Considerations
- The criterion test is timing-dependent; it asserts on samples of the resident figure, not on throughput, so a slow CI machine only makes it slower.
