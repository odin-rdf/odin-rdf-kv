# The I/O hook, KV_NO_SYNC and the journal

## Parent Initiative

[[KV-I-0005]]

## Objective

Give the tests a way to see and steer every write, sync and truncate the store makes, and a way to skip syncs (KV-I-0005 D1, D3). Nothing else in the initiative can start without it.

## Acceptance Criteria

- [ ] `IO_HOOK :: #config(KV_IO_HOOK, false)` and `NO_SYNC :: #config(KV_NO_SYNC, false)`, beside `CHUNK_ACCOUNTING`, exported, with doc comments saying both are test-only.
- [ ] `Io_Op` (kind `Write`/`Sync`/`Truncate`, fd, offset, bytes, size) and `@(thread_local) io_hook: proc(op: Io_Op) -> Error`. `os_pwrite`, `os_sync` (both platforms) and `os_truncate` call the hook first inside `when IO_HOOK`; a non-`.None` return is returned without performing the operation. A build without the define has no branch.
- [ ] `os_sync` under `NO_SYNC` returns `.None` after the hook, with no system call, on both platforms.
- [ ] `tests/crash.odin`: a journal helper that installs a recording hook, copies each write's bytes, and records syncs and truncates in order; plus `journal_image_kill(baseline, journal, n, path)`, which writes the baseline file with operations 0..n applied.
- [ ] Tests (registered only when `kv.IO_HOOK` is true, and the file compiles either way):
  - the journal of one commit on a committed tree has the expected shape: data-page writes in page order, a sync, one meta-page write into slot `txn_id & 1`, a sync; spills and overflow runs appear before the first sync;
  - the kill image at the last operation is byte-identical to the real file;
  - a hook returning `.Io` at a chosen operation makes that store call return `.Io`;
  - hooks on two threads with two envs see only their own operations.
- [ ] A test that `NO_SYNC` really skips the call (a hook-counted sync with a timing or syscall-free check is not possible portably, so: the test documents what it can assert, at minimum that commits succeed and the journal still records the syncs).
- [ ] `scripts/test.sh` gains one configuration with `-define:KV_IO_HOOK=true -define:KV_NO_SYNC=true` (debug), so the hooked build is exercised on every local run; the existing configurations stay as they are, with real syncs.
- [ ] Deliberate-bug checks recorded: skip the hook in one of the three procedures (a journal-shape test fails); record a write after performing it with a wrong offset (the image-equals-file test fails).
- [ ] `scripts/test.sh` and `scripts/test-linux.sh arm64` pass.

## Implementation Notes

### Technical Approach
- The hook is thread-local because tests run in parallel and each write happens on the thread holding the write transaction; `init_meta_pages` runs on the opening thread.
- The journal copies bytes because a pool slot is reused after the write.
- Baseline: a copy of the file taken while it is fully synced (after a commit returned), or "no file".

### Dependencies
None.

### Risk Considerations
- Any I/O outside the three procedures would be invisible to the journal; grep for `posix.pwrite`, `ftruncate`, `fsync` outside `kv/os_*.odin` as part of the task.
