# Kill-image crash sweep over the commit workloads

## Parent Initiative

[[KV-I-0005]]

## Objective

Show the vision's crash-safety criterion for a process kill: at every I/O cut point of a commit, the database reopens at exactly the last committed state, including commits that spilled, wrote overflow runs or streamed the free list first (KV-I-0005 D1, design *The journal and crash images* and *The workloads swept*).

## Acceptance Criteria

- [x] A sweep driver in `tests/crash.odin`: given a workload that records a baseline, a journal and the committed model after each commit, it builds the kill image for every cut `n` and checks it.
- [x] Per image: `env_open` succeeds; the state is the successor commit's if and only if its meta-page write precedes the cut, else the last fully committed one (`model_compare`); `tree_check` and `space_check` pass; one more commit succeeds, and a reopen is at it.
- [x] Workloads 1–4 of the design: a few puts on a committed tree; a commit with `MIN_DIRTY_BUDGET` that spills, with overflow values and a multi-page free-list run; deletes that merge and collapse the root; three commits in a row with page reuse. Each asserts it actually exercised what it names (spills > 0, a free-list run of more than one page, reused pages > 0, a merge).
- [x] A cut right after `file_grow`'s truncate is included and opens cleanly (KV-I-0005 D8).
- [x] Sizes small enough that all four together take about a second with `KV_NO_SYNC`; `KV_CRASH=true` selects larger trees. Registered only when `kv.IO_HOOK` is true.
- [x] Deliberate-bug checks recorded, each failing the sweep: write the meta page before the first sync; drop the first sync; write the meta page into slot `txn_id & 1` of the *old* id (overwriting the current meta); let `page_alloc` hand out a page freed by the previous commit while a reader-less horizon says it is still referenced (or the equivalent reuse-horizon break). *(Amended 2026-09-25: three of the four bugs named here are **invisible to a kill image by construction**, and the sweep confirmed it. A kill loses nothing a write handed to the OS, so a sync never shows (drop the first sync); both meta slots are always whole, so `meta_choose` always takes the higher `txn_id` and the slot a commit writes into never shows (write into the current slot); and the pages of snapshot S − 1 are referenced by no state a kill can open at, so reusing them never shows (horizon S instead of S − 1). They are power-loss or bit-rot properties and are KV-T-0028's to catch. The kill-visible equivalents were checked instead, and each fails the sweep: the meta page written **before the data pages**, and a copy-on-write that frees the committed page as **loose**, so the transaction reuses a page of the durable snapshot before its meta page. See the status update.)*
- [x] `scripts/test.sh` passes (the hooked configuration runs the sweep) and `scripts/test-linux.sh arm64`.

## Implementation Notes

### Technical Approach
- One temporary image file per test, rewritten per cut; images are opened with the ordinary `env_open` and default options.
- The expected state per cut comes from the journal: find the last meta-page write at or before `n` and map its `txn_id` to the workload's committed models.

### Dependencies
KV-T-0026.

### Risk Considerations
- If a cut finds a real bug, the task records it and fixes it in the same commit, with a test that pins it.

## Status Updates

### 2026-09-25 — implemented and verified

**What was built.**
- `tests/crash.odin`, the sweep driver, reusable by KV-T-0028: `Crash_Run` (name, key space, working `model`, `base` baseline, `journal`, `base_txn`, `states[i]` = the committed model of txn `base_txn + i`, `commits: [dynamic]Crash_Commit` with each commit's journal range `[first, end)`, `prev_last` and `spills`, `value_buf`); `crash_run_init`/`crash_run_destroy`; `crash_put`/`crash_del` (change the store and the model together, the model only on success); `crash_baseline` (takes the baseline of the open env's file, records `base_txn`, starts the journal); `crash_commit` (commits, checks the txn id, appends the state); `crash_finish` (closes the env, stops the journal). Expected state: `crash_kill_txn(run, n)` (the `txn_id` of the last meta-page write among the first `n` operations, else the baseline's) and, for KV-T-0028, `crash_synced_txn(run, n)` (the last meta-page write followed by a sync). `crash_image_check(t, run, path, allowed, what)` opens an image, requires one of `allowed`, then `model_diff` (entry count, `get` of every key, both scans, `tree_check`) and `space_check`, one more commit (key 0 rewritten), a reopen at `txn_id + 1` and the same diff against the model that commit made. `crash_sweep_kill(t, run, path) -> (Crash_Sweep, ok)` builds each kill image incrementally (`image_apply` of one more operation per cut), stops at the first failing cut, and counts cuts, cuts right after a truncate and cuts at a workload commit. `record_meta_txn_id` moved here from `io_hook_test.odin` and is now exact: a meta write is exactly header + `Meta` long, every other write is whole pages.
- `tests/crash_sweep_test.odin`: `test_crash_kill_puts`, `_spill`, `_deletes`, `_reuse` (registered under `kv.IO_HOOK`), `Crash_Workload`, `crash_kill` (runs a workload, sweeps, logs the counts and time), `CRASH :: #config(KV_CRASH, false)`.

**Workloads and their proofs.** 1 *puts*: `key_space_make(300)` (short, medium and maximum-length keys), 7/8 of them committed in one baseline commit (depth ≥ 2 asserted), then 8 puts spread over the leaves; asserts the commit wrote ≥ 3 pages. 2 *spill*: `MIN_DIRTY_BUDGET`, a baseline that puts a 260-page overflow value and deletes it in its last commit (so its pages stay pending through the workload: horizon S − 1), then 280 puts of 1000 bytes with an overflow value every 25; asserts spills > 0, an overflow value, and a free-list run of > 1 page (a page holds 255 records). 3 *deletes*: 60 u64 keys of 200 bytes; every leaf loses all but its first key, so none empties; asserts fewer leaves after (a merge) and a smaller depth (root collapse). 4 *reuse*: `key_space_make(150)`, three baseline commits, then three commits overwriting a third of the keys, moving a few and deleting some; asserts every one of the three wrote into a page at or below the `last_pgno` it began from.

**D8, the cut after the truncate.** The file grows in steps of at least 1 MiB, so a small workload never grew it. The spill workload builds its baseline with `map_size` of 320 pages (`file_grow` caps a step at the map), then reopens with the default map: the file has < 70 pages of room (asserted) and the transaction grows it while spilling. `test_crash_kill_spill` asserts at least one cut right after a truncate; it opens cleanly.

**Measured** (`-debug -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true`, macOS arm64, inside the full suite): deletes 6 cuts 9 ms, puts 17 cuts 102 ms, reuse 50 cuts over 3 commits 138 ms, spill 99 cuts (1 after a truncate) 234 ms: **172 cuts, about 0.48 s** of test time, on two runner threads 0.23 s wall. Linux arm64 container: 0.72 s of test time. The fixed cost is about 2–3 ms per cut in a debug build (two opens, a commit, `space_check` over the file); the maximum-length keys make *puts* the dearest per cut. `-define:KV_CRASH=true` (3000-key trees, 2000 spilled puts), `-o:speed`: 24 + 74 + 605 + 1064 cuts, 8.1 s; deletes then collapse depth 3 → 2 and grow the file too.

**Decisions.**
- The image check opens with default options, as the task says; the page size comes from the meta page.
- The extra commit rewrites key 0 with a fixed value, so the reopen can be diffed in full against a known model rather than just read.
- The sweep stops at the first failing cut: one message naming the run, the cut, the operation before it and the difference.
- Each cut runs under `runtime.DEFAULT_TEMP_ALLOCATOR_TEMP_GUARD()`, so the temporary allocator doesn't grow with the number of cuts.
- The sweep logs one info line per workload; KV-T-0033 can read the time from it.

**Deviations.** The deliberate-bug criterion is amended (above): three of its four bugs cannot show in a kill image, and were replaced by kill-visible ones. No store bug was found.

**Deliberate-bug checks** (the four sweep tests, `-debug -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true -define:ODIN_TEST_THREADS=2`, under `timeout -s KILL 300`; each reverted from a saved copy and `git diff kv/` checked empty):
1. Meta page written before the dirty pages (the loop moved after `meta_write`): **all four fail**, e.g. puts "kill at cut 4 of 16, after Write of 96 bytes at 0: txn 2: get returned a wrong value"; spill at cut 57 of 98.
2. `page_touch` records the committed page it copied in `loose` instead of `freed` (the transaction reuses pages of the durable snapshot): **all four fail**, spill at cut 14, while still spilling, before the commit.
3. `page_free` puts committed pages in `loose`: the deletes sweep fails (cut 1), and spill's free-list-run proof. (Copy-on-write frees through `page_touch`, not `page_free`, hence bug 2.)
4. Drop the first sync: all pass, as expected (a kill can't see a sync). `test_journal_commit_shape` catches it; KV-T-0028's power-loss sweep must.
5. Meta page into the current slot (`(txn_id − 1) & 1`): all pass, as expected (both slots are always whole, the higher id wins). For KV-T-0028: a torn meta page then falls back to a stale slot.
6. Reuse horizon S instead of S − 1: the sweeps pass, as expected (no kill state references S − 1's pages); only the spill workload's free-list-run proof fails, because the pages it keeps pending become reusable. For KV-T-0028 or a meta-corruption test.

**Verification.** `scripts/test.sh`: debug 162, `-o:speed` 162, ASan 162, hooked/no-sync 171 tests, all pass, and every cross-target check. `scripts/test-linux.sh arm64`: debug 162, `-o:speed` 162, hooked/no-sync 171, all pass.
