# Kill-image crash sweep over the commit workloads

## Parent Initiative

[[KV-I-0005]]

## Objective

Show the vision's crash-safety criterion for a process kill: at every I/O cut point of a commit, the database reopens at exactly the last committed state, including commits that spilled, wrote overflow runs or streamed the free list first (KV-I-0005 D1, design *The journal and crash images* and *The workloads swept*).

## Acceptance Criteria

- [ ] A sweep driver in `tests/crash.odin`: given a workload that records a baseline, a journal and the committed model after each commit, it builds the kill image for every cut `n` and checks it.
- [ ] Per image: `env_open` succeeds; the state is the successor commit's if and only if its meta-page write precedes the cut, else the last fully committed one (`model_compare`); `tree_check` and `space_check` pass; one more commit succeeds, and a reopen is at it.
- [ ] Workloads 1–4 of the design: a few puts on a committed tree; a commit with `MIN_DIRTY_BUDGET` that spills, with overflow values and a multi-page free-list run; deletes that merge and collapse the root; three commits in a row with page reuse. Each asserts it actually exercised what it names (spills > 0, a free-list run of more than one page, reused pages > 0, a merge).
- [ ] A cut right after `file_grow`'s truncate is included and opens cleanly (KV-I-0005 D8).
- [ ] Sizes small enough that all four together take about a second with `KV_NO_SYNC`; `KV_CRASH=true` selects larger trees. Registered only when `kv.IO_HOOK` is true.
- [ ] Deliberate-bug checks recorded, each failing the sweep: write the meta page before the first sync; drop the first sync; write the meta page into slot `txn_id & 1` of the *old* id (overwriting the current meta); let `page_alloc` hand out a page freed by the previous commit while a reader-less horizon says it is still referenced (or the equivalent reuse-horizon break).
- [ ] `scripts/test.sh` passes (the hooked configuration runs the sweep) and `scripts/test-linux.sh arm64`.

## Implementation Notes

### Technical Approach
- One temporary image file per test, rewritten per cut; images are opened with the ordinary `env_open` and default options.
- The expected state per cut comes from the journal: find the last meta-page write at or before `n` and map its `txn_id` to the workload's committed models.

### Dependencies
KV-T-0026.

### Risk Considerations
- If a cut finds a real bug, the task records it and fixes it in the same commit, with a test that pins it.
