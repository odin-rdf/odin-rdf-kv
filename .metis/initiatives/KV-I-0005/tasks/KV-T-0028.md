# Power-loss images: lost, torn and reordered writes

## Parent Initiative

[[KV-I-0005]]

## Objective

Show the stronger claim, crash safety from ordering and checksums: after a power loss, when writes since the last sync may be lost, torn or reordered, the database still reopens at a state it is allowed to be in (KV-I-0005 D2).

## Acceptance Criteria

- [x] `journal_image_power(baseline, journal, n, subset, tears, path)`: the baseline, every operation up to the last sync before `n`, then only the chosen later operations, each write whole or torn to a subset of its 512-byte sectors; a truncate outside the subset leaves the size as it was.
- [x] Per cut, fixed images: none of the later operations; all of them; only the meta-page write; the meta-page write torn. Then `KV_CRASH_SUBSETS` random subsets with random tears (default 4), from the test's seed, which failure messages carry with the cut and the subset. *(Amended 2026-09-25: **per window, not per cut, and 16 subsets by default.** A power loss after operation n can leave exactly the images a power loss just before the next sync can — the same synced prefix, and a subset of fewer unsynced operations is a subset of more — and must open at the same state, so the sweep cuts only before each sync and at the end of the journal. The images an intermediate cut would build are a subset of those, so the time goes into more random subsets per window instead. Messages carry the seed, the cut, the image's name, the subset (as journal index ranges) and every tear's kept byte ranges.)*
- [x] Allowed states: the last commit whose second sync precedes the cut, or the successor's if its meta-page write is in the image whole. A torn meta page must be rejected by its checksum and the other slot used. Every image also passes `tree_check`, `space_check`, one more commit and a reopen.
- [x] Run over workloads 1–4 from KV-T-0027.
- [x] Deliberate-bug checks recorded, each failing: skip the meta checksum check in `meta_choose`; drop the first sync (now visible as a durable meta page over lost data pages, where the kill sweep may not see it); take the meta page with the *lower* `txn_id`. *(Note from KV-T-0027, 2026-09-25: two more of the bugs KV-T-0027 was given turned out to be invisible to a kill image and belong here: writing the meta page into the **current** slot (`(txn_id − 1) & 1`), which a torn meta write should expose as a fall-back to a stale slot; and a reuse horizon of S instead of S − 1, which only matters when the newest meta page is unreadable, and may need a meta-corruption image rather than a power-loss one to show.)* *(Amended 2026-09-25: `(txn_id − 1) & 1` after `txn_commit` has incremented `snap.txn_id` still alternates, one parity shifted, and every sweep passes, correctly; the bug as meant — the slot the previous commit used — is checked as a fixed slot, `meta_write(env, 1, meta)`. The horizon bug needed the meta-corruption image; see the status update.)*
- [x] `scripts/test.sh` and `scripts/test-linux.sh arm64` pass.

## Implementation Notes

### Technical Approach
- Reordering needs no separate model: a subset of unsynced writes applied in any order produces the same bytes unless two writes overlap, so overlapping writes are applied in journal order and the subset choice covers reordering.
- The simulation assumes a sync that returned made everything before it durable, the contract the store is written against (KV-I-0005 non-goals).

### Dependencies
KV-T-0027.

## Status Updates

### 2026-09-25 — implemented and verified

**What was built.**
- `tests/crash.odin`: `Io_Tear` (`op`, `keep`: byte ranges of the write that reached the disk), `journal_synced(j, n)` (the operations up to and including the last sync among the first `n`), `image_power(b, j, n, subset, tears)` and `journal_image_power(b, j, n, subset, tears, path)` (the criterion's signature: the synced prefix, then only `subset` — ascending journal indexes in the unsynced window, applied in journal order — each whole unless `tears` names it; a truncate outside the subset leaves the size as it was), `CRASH_SUBSETS :: #config(KV_CRASH_SUBSETS, 16)`, and `crash_sweep_power(t, run, path)` beside `crash_sweep_kill`. `Crash_Sweep` gained `windows`, `images`, `corrupt`. `Crash_Run` gained `pre` (the state of `base_txn − 1`) with `crash_pre_baseline(run)`, and `crash_state` answers for it.
- `tests/crash_sweep_test.odin`: `test_crash_power_puts`, `_spill`, `_deletes`, `_reuse`, over the same four workload builders as the kill sweep (not copied): `crash_kill` and the new `crash_power` share a file-private `crash_sweep(t, workload, run, sweeper)`. Each workload calls `crash_pre_baseline` before its last baseline commit.

**How an image's allowed state is derived.** Exactly one txn per image: `crash_synced_txn(run, n)` (S), or S + 1 if and only if the successor's meta-page record is in the built image byte for byte (`image_has`). Comparing the image rather than the subset makes the rule exact even for a random prefix tear that happens to keep every byte that differs. There is at most one meta write per window (each is followed by a sync), and the sweep asserts it is S + 1's.

**Tears.** Whole-page writes tear at 512-byte sectors (a random half, merged into ranges). A meta write (96 bytes) is shorter than a sector, so a sector tear cannot split it; it is torn to a byte prefix instead — stricter than an atomic sector, and the model that shows the checksum. The fixed torn image keeps the header and the meta up to and including the new `txn_id` (40 bytes): it claims the newer txn over the old tree and old checksum. Random subsets keep each operation with a probability drawn per subset (sparse and dense subsets both), and tear a kept write with probability 1/4. Each random subset has its own generator, `rand.create(t.seed ~ n << 20 ~ k)`, so it reproduces from the seed, cut and number alone (`-define:ODIN_TEST_RANDOM_SEED=`).

**Meta-corruption image — in this task.** Cheap (one image per cut, ~12 in all) and the only way to show the S − 1 horizon. At each sweep cut where no meta page beyond S has been written, the kill image with S's meta checksum flipped must open at S − 1 and pass `crash_image_check`. **This goes beyond the power-loss model** (a synced meta page can't be damaged by a power loss under the store's sync contract) **and beyond the initiative's non-goals** (no recovery from corruption in general): it is in scope only because the fallback to the other meta slot, and keeping S − 1 intact for it (KV-I-0002 D1), are the store's own design. It is labelled "meta corruption" in every message, and is taken only where the run knows S − 1's state (hence `pre`).

**Measured** (debug, `KV_IO_HOOK` + `KV_NO_SYNC`, macOS arm64, inside the full `scripts/test.sh` run): deletes 3 cuts, 2 windows, 37 images + 2 corrupt, 56 ms; spill 37 + 2, 147 ms; puts 37 + 2, 206 ms; reuse 7 cuts, 6 windows, 111 + 4, 284 ms. **222 power images + 10 meta-corruption images, about 0.69 s** of test time (0.29 s standalone at 8 subsets). Linux arm64 container: 1.1 s. `-o:speed -define:KV_CRASH_SUBSETS=200`: 2430 images, all pass, 1.8 s. `-o:speed -define:KV_CRASH=true -define:KV_CRASH_SUBSETS=32`: 414 images, all pass, 3.6 s.

**Decisions.**
- Cuts at sync points only (the amendment above). Empty windows (at a completed sync) are the kill image there and are skipped; the meta-corruption image is still taken at them.
- "Only the meta page" is taken when the window has other operations too; in a correct store it never does (the meta write is alone between the two syncs), so that image is the one that shows a missing first sync.
- The fixed torn image keeps every other window operation whole.
