# Poison the env after a failed sync or meta-page write

## Parent Initiative

[[KV-I-0005]]

## Objective

After a commit's meta-page write or either sync fails, the new meta page may be durable while the env keeps the previous state; a further write transaction could then overwrite the failed commit's pages and leave a durable meta page pointing at them. Refuse further writes until the env is reopened (KV-I-0005 D7).

## Acceptance Criteria

- [ ] `Error.Poisoned`, with a doc comment. `Env.poisoned` (atomic), set in `txn_commit` when `meta_write` or either `os_sync` fails.
- [ ] `txn_begin(rw)` returns `.Poisoned` while it is set. Read transactions, `env_stats`, `env_sweep` and `env_close` are unaffected. `Stats.poisoned` reports it.
- [ ] `txn_commit`'s doc comment describes the failure cases and the poisoning.
- [ ] Tests (hooked build), failure injected at each of: the first sync, the meta-page write, the second sync:
  - `txn_commit` returns the error and the next `txn_begin(rw)` returns `.Poisoned`;
  - a reader begun afterwards sees the previous commit;
  - a reopen yields either the previous or the failed commit, passing the checks, and takes a commit.
- [ ] **The deliberate-bug test:** with the flag disabled, a scripted sequence (final sync fails with the meta page in the file; a second write transaction reuses the failed commit's pages and is cut by a kill image before its meta write) opens as corrupted or fails `tree_check`/`space_check`; with the flag, the second transaction is refused. Recorded in the status update.
- [ ] `scripts/test.sh` and `scripts/test-linux.sh arm64` pass.

## Implementation Notes

### Technical Approach
- The failure is sticky for the env's lifetime; nothing clears it but `env_close`.
- LMDB's equivalent is `MDB_PANIC`.

### Dependencies
KV-T-0026 (fault injection) and KV-T-0027 (kill images for the scripted test).
