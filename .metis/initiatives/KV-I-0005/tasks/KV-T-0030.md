# Poison the env after a failed sync or meta-page write

## Parent Initiative

[[KV-I-0005]]

## Objective

After a commit's meta-page write or either sync fails, the new meta page may be durable while the env keeps the previous state; a further write transaction could then overwrite the failed commit's pages and leave a durable meta page pointing at them. Refuse further writes until the env is reopened (KV-I-0005 D7).

## Acceptance Criteria

- [x] `Error.Poisoned`, with a doc comment. `Env.poisoned` (atomic), set in `txn_commit` when `meta_write` or either `os_sync` fails.
- [x] `txn_begin(rw)` returns `.Poisoned` while it is set. Read transactions, `env_stats`, `env_sweep` and `env_close` are unaffected. `Stats.poisoned` reports it.
- [x] `txn_commit`'s doc comment describes the failure cases and the poisoning.
- [x] Tests (hooked build), failure injected at each of: the first sync, the meta-page write, the second sync:
  - `txn_commit` returns the error and the next `txn_begin(rw)` returns `.Poisoned`;
  - a reader begun afterwards sees the previous commit;
  - a reopen yields either the previous or the failed commit, passing the checks, and takes a commit. *(2026-09-25: asserted exactly per point, since the hook fails an operation whole: the previous commit after a failed first sync or meta write, the failed one after a failed final sync. Plus: a failure at every operation before the first sync does not poison.)*
- [x] **The deliberate-bug test:** with the flag disabled, a scripted sequence (final sync fails with the meta page in the file; a second write transaction reuses the failed commit's pages and is cut by a kill image before its meta write) opens as corrupted or fails `tree_check`/`space_check`; with the flag, the second transaction is refused. Recorded in the status update.
- [x] `scripts/test.sh` and `scripts/test-linux.sh arm64` pass.

## Implementation Notes

### Technical Approach
- The failure is sticky for the env's lifetime; nothing clears it but `env_close`.
- LMDB's equivalent is `MDB_PANIC`.

### Dependencies
KV-T-0026 (fault injection) and KV-T-0027 (kill images for the scripted test).

## Status Updates

### 2026-09-25 — implemented and verified

**What was built.**
- `kv/types.odin`: `Error.Poisoned`, documented as what a commit failing at or after its first sync leaves, and how to recover (`env_close` + `env_open`).
- `kv/env.odin`: `Env.poisoned` (a bool written with `sync.atomic_store` under `writer_mutex`, read atomically), `Stats.poisoned` (live, read in `env_stats` like the other live figures; the `Stats` doc comment says so).
- `kv/commit.odin`: `commit_poison(env, err)` (file-private), called when the first `os_sync`, `meta_write` or the final `os_sync` fails, and nowhere else. `txn_commit`'s doc comment now separates the two failure classes: before the first sync (file growth, the free-list run, a data page — only unreferenced pages written, the env commits on as if aborted) and from the first sync on (poisoned, with the reason for each: a meta page that may be durable and points at pages the process still counts as free; after a failed fsync, pages the kernel may have dropped). It also says reads carry on at the previous commit and that a reopen sees the failed commit iff its meta page is durable and whole.
- `kv/txn.odin`: `txn_begin(rw)` returns `.Poisoned` **after taking `writer_mutex`** (a writer that was blocked on the failing commit must see the flag), unlocking before it returns; doc comment added. Read transactions, `env_stats`, `env_sweep`, `env_close` untouched.
- `tests/poison_test.odin` (registered under `kv.IO_HOOK`): `test_poison_first_sync`, `_meta_write`, `_final_sync`, and `test_poison_not_before_sync`. A baseline of three commits (so `env.free.ready` has pages as well as the end of the file), a dry run to find the call indexes (`fail_at` counts hook calls), then the failing run: `txn_commit` returns `.Io`; `env_snapshot` is still the previous txn; `Stats.poisoned` as expected; a reader begun afterwards is at the previous commit and passes `model_diff` against its model; `env_sweep(env, 0)` evicts to 0; `txn_begin(rw)` is `.Poisoned`, twice; then `env_close` and `crash_image_check` on the real file (opens, `model_diff`, `space_check`, one more commit, reopen at it). `test_poison_not_before_sync` fails **every** operation of the commit before its first sync in turn (the free-list run write and each data page; overflow values written at put are before the commit and not counted) and checks the env is *not* poisoned and takes the next commit, which a reopen finds.
- `CLAUDE.md`: one invariant line, and `commit_poison` in the code map.

**Where the flag is set, and why exactly there.** After a failure of the first sync, of `meta_write` (any error from it, so a partial `pwrite` too: the loop in `os_pwrite` returns `.Io` with part of the 96 bytes written), and of the final sync. Not before the first sync: every page written by then is a new page, a reusable page of the previous commit, or past its last page, so no meta page in the file refers to it — the env's `snapshot` and `free` are unchanged and the next transaction may rewrite those pages. On the error path, `txn_commit`'s `defer` frees `next` and `txn_abort` releases the pool and the writer lock; `env.snapshot`, `env.free` and the stats are untouched (they only change after the second sync), so readers stay consistent, and the only writer state left is the flag. `env.file_size` may have grown, which is harmless.

**Deviation (criterion 4).** "A reopen yields either the previous or the failed commit" is asserted **exactly** per point, which is stronger: the hooked build fails an operation without performing it, so after a failed first sync or meta write the file has no new meta page (reopen at the previous commit), and after a failed final sync it has it whole (reopen at the failed commit, state checked against the failed commit's model). A partial meta write is not simulated by the hook; its outcome is either state, which KV-T-0028's torn-meta images already cover.

**The deliberate-bug test — D7's hazard reproduces.** The test itself carries the scripted sequence: if `txn_begin(rw)` is *not* refused after a failed final sync, it goes on as an unpoisoned store would — a second transaction with different changes (other keys, other sizes, deletes) commits, and the kill image cut just before its meta-page write must open at the failed commit's state (its meta page is the newest whole one in the file, `crash_kill_txn` = previous + 1). With `atomic_store` commented out in `commit_poison`:
- `test_poison_final_sync`: logs "poison at Final_Sync, unpoisoned: the next transaction wrote 16 pages, 14 of them written by the failed commit (of 14)", then fails **"poison at Final_Sync, killed before the next commit's meta page, unpoisoned: env_open: Corrupted"**. Every page the failed commit wrote was rewritten; the meta page of txn 4 is valid (whole, checksum good), so the `.Corrupted` is `freelist_load` refusing the free-list run it names, which is now some other page — the only `.Corrupted` return in `env_open` after `meta_choose` found a meta page. A durable meta page pointing at overwritten pages, exactly as D7 said.
- `test_poison_first_sync`, `test_poison_meta_write`: "txn_begin(rw) after the failure returned None, want Poisoned" (and `Stats.poisoned is false`). The test does not script corruption for these: in the hooked build no new meta page is in the file, and their hazard (pages the kernel dropped after a failed fsync) is not something any image here models. Recorded as the reason, not faked.
With the flag, the second `txn_begin(rw)` returns `.Poisoned` and the file reopens cleanly at the failed commit.

**Deliberate-bug checks** (the four poison tests, `-debug -define:KV_IO_HOOK=true -define:KV_NO_SYNC=true -define:ODIN_TEST_THREADS=2`, under `timeout -s KILL 300`; `kv/` restored from a saved copy with `cmp` after each):
1. The flag never set: three tests fail, as above (the final-sync one on the reproduced corruption).
2. `txn_begin` ignores the flag (`if false && …`): the same three fail, the same messages (`Stats.poisoned` then true, so only the refusal and the corruption fail).
3. A failed data-page write poisons too: `test_poison_not_before_sync` fails, "poison at Before_Sync (operation 2): Stats.poisoned is true", "expected nerr to be None, got Poisoned". (Before the test looped over every pre-sync operation it failed only operation 0, the free-list run, and this bug passed — hence the loop.)
4. A failed free-list run write poisons: the same test fails at operation 1.
5. The final sync doesn't poison (`or_return`): `test_poison_final_sync` fails on the reproduced corruption, "env_open: Corrupted".

**Verification.** `scripts/test.sh`: debug 164, `-o:speed` 164, ASan 164, hooked/no-sync 183 tests, all pass, and every cross-target check (1 min 31 s). `scripts/test-linux.sh arm64`: debug 164, `-o:speed` 164, hooked/no-sync 183, all pass. The four poison tests take about 0.15 s together (debug, hooked).

**Not done here, for the backlog.** (a) Whether `put`/`del` should refuse on a poisoned env is moot: the only write transaction that exists when the flag is set is the one failing, and it ends. (b) The hook can't simulate a *partial* meta write (the hook refuses a write whole); a test of a torn meta write followed by a poisoned env would need a hook return that performs part of the write. KV-T-0028's torn images cover what the file then holds, so this is only worth it if the fault-injection hook grows that ability anyway.
