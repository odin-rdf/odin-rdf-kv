# Seeded fuzz mode over the model

## Parent Initiative

[[KV-I-0005]]

## Objective

The correctness half of step 7: long, seed-reproducible runs of the existing model, on demand and cheap in CPU and CI minutes (KV-I-0005 D4, D5).

## Acceptance Criteria

- [ ] `-define:KV_FUZZ=true` registers `test_fuzz_model`: `run_model` for `KV_FUZZ_OPS` operations (default 10⁶) over `KV_FUZZ_SEEDS` consecutive seeds (default 1) from the runner's seed, alternating the default pool and `MIN_DIRTY_BUDGET`, and varying the key count per seed.
- [ ] `KV_FUZZ_CHECK_EVERY=k` (default 1) reaches `run_model`: the full `model_compare` and `space_check` run every *k* commits and before every reopen and on the last commit. The ordinary model tests keep `k = 1`.
- [ ] The test logs whether `kv.NO_SYNC` is set and recommends it; the doc comment and `CLAUDE.md`'s build section give the command, with `ODIN_TEST_THREADS`.
- [ ] Each failure message carries the seed and the operation, as the model already does; a failing seed from a multi-seed run reproduces alone.
- [ ] Measured and recorded: operations per second with and without `KV_NO_SYNC`, and with `k = 1` and `k = 10`, on macOS arm64.
- [ ] Deliberate-bug check recorded: a bug the ordinary model test at its seed does not hit but the fuzz run does (or, if none is found, a bug both hit, and a note that the fuzz run found it within N operations).
- [ ] `scripts/test.sh` passes.

## Implementation Notes

### Dependencies
