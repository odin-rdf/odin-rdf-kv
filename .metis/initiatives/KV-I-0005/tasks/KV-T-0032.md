# Real-kill test with a helper process

## Parent Initiative

[[KV-I-0005]]

## Objective

The vision's own words, a process killed during commit, with real syncs: one small test on demand, never in CI (KV-I-0005 D1).

## Acceptance Criteria

- [ ] `tests/killer/`, its own package: opens a database, commits numbered values in a loop (each commit writes its number under a fixed key and a few others, sometimes with overflow values), and prints each commit's number to stdout after `txn_commit` returns.
- [ ] `-define:KV_KILL=true` registers one test that builds the helper, runs it, sends `SIGKILL` after a random delay from its seed, and repeats a number of times (default 20) on the same file. After each kill: `env_open`, the committed number is the last printed or the one after, `tree_check` and `space_check` pass.
- [ ] Not `fork()`: the test runner is multithreaded. The helper is a separate binary started with `core:os` process APIs.
- [ ] Runs on macOS arm64 and in the Linux container; not in CI.
- [ ] Deliberate-bug check recorded: write the meta page before the first sync; state whether the kill test detects it within the default repeats (it may not, which is why the sweep exists) and record the finding either way.

## Implementation Notes

### Dependencies
None beyond the store; ordered after the sweep because it is the weaker test.
