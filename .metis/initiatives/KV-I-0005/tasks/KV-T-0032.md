# Real-kill test with a helper process

## Parent Initiative

[[KV-I-0005]]

## Objective

The vision's own words, a process killed during commit, with real syncs: one small test on demand, never in CI (KV-I-0005 D1).

## Acceptance Criteria

- [x] `tests/killer/`, its own package: opens a database, commits numbered values in a loop (each commit writes its number under a fixed key and a few others, sometimes with overflow values), and prints each commit's number to stdout after `txn_commit` returns.
- [x] `-define:KV_KILL=true` registers one test that builds the helper, runs it, sends `SIGKILL` after a random delay from its seed, and repeats a number of times (default 20) on the same file. After each kill: `env_open`, the committed number is the last printed or the one after, `tree_check` and `space_check` pass.
- [x] Not `fork()`: the test runner is multithreaded. The helper is a separate binary started with `core:os` process APIs.
- [x] Runs on macOS arm64 and in the Linux container; not in CI.
- [x] Deliberate-bug check recorded: write the meta page before the first sync; state whether the kill test detects it within the default repeats (it may not, which is why the sweep exists) and record the finding either way.

## Implementation Notes

### Dependencies
None beyond the store; ordered after the sweep because it is the weaker test.

## Status Updates

### 2026-09-25 — implemented and verified

**What was built.**
- `tests/killer/killer.odin` (package `killer`, a `main`): `killer <database> <dirty_budget>` opens the database, reads the last commit's number under `"n"` (0 if absent) and commits the next ones forever, printing each number on its own line to stdout after `txn_commit` returns (one unbuffered `write` per line). Any error exits with status 1 and a message on stderr; it refuses to run if built with `KV_NO_SYNC`.
- `tests/killer/workload/` (package `killer_workload`), imported by both the helper and the test: commit `c` writes `c` under `"n"` and changes slots `s0000`–`s1999` chosen by a hash of `c` alone: 1–8 changes, one commit in twelve 80 (which spills with the smallest pool), one change in six a delete, one put in ten an overflow value of 5,000–30,000 bytes, the rest 16–300 bytes. Every value starts with its commit and slot and continues with a pattern of both, so `replay(N)` gives the exact expected state after commit N. A separate package so the test need not import a `main` package.
- `tests/kill_test.odin`: `test_kill_real`, registered only with `-define:KV_KILL=true`; `KV_KILL_REPEATS` (default 20) and `KV_KILL_MAX_DELAY_MS` (default 250). It fails at once under `KV_NO_SYNC`. It builds the helper with `odin build #directory/killer -o:speed -vet -strict-style` into a temporary directory, then per run: `os.pipe`, `os.process_start` (stdout to the pipe, stderr inherited), polls the pipe until a delay drawn from the test's seed (0–250 ms), `os.process_kill` (SIGKILL), `os.process_wait`, drains the pipe to EOF. It requires the helper to have died of signal 9 (an exit of its own is a failure) and the printed numbers to count up from the last committed one. Then `env_open` with default options: the counter N must be the last printed or one more; a cursor scan must hold exactly `"n"` and the replayed slots, byte for byte; `tree_check` and `space_check`. Odd runs start the helper with `MIN_DIRTY_BUDGET`. The next run resumes on the same file.
- `scripts/test.sh` checks `tests/killer` for each of the four targets (`-vet -strict-style`), so the helper keeps compiling; the kill test itself is not run there. `CLAUDE.md` has the command lines.

**Outcomes.** macOS arm64 (debug test build, helper `-o:speed`): helper build 1.5–2 s, 20 kills in 2.0–3.5 s, about 5 s in all; 211–607 commits over the 20 runs depending on the seed (about 12 ms a commit with `F_FULLFSYNC`). **Most kills land inside a commit**: 12, 17, 16 and 17 of 20 (seeds default, 1, 2, 3) opened at *last printed + 1*, that is after the meta-page write and before the number was printed — the final `F_FULLFSYNC` of the meta page is where the helper spends most of its time; 1–4 per run were killed before printing anything (during start-up or `env_open`, the file resumed as it was). Kills landing in the first sync cannot be told apart from ones between commits (both open at *last printed*). Linux arm64 container: helper build and 20 kills in 5.9 s, 1,487 commits (the container's sync is cheaper), 9 of 20 after the meta-page write. Every run passed on both.

**Deliberate-bug checks** (under `timeout -s KILL 300`, `kv/commit.odin` restored from a copy each time, `git diff kv/` empty afterwards, `pgrep -f killer` empty):
1. **The criterion's bug, meta page written before the first sync** (the first sync moved after `meta_write`): **not detected** — three seeds (1, 2, 3) at the default 20 kills, all pass. As expected: a process kill loses nothing a `pwrite` handed to the OS, so the order of writes relative to a sync is invisible to it (D3's argument). This is what KV-T-0028's power-loss sweep is for: its check of the equivalent bug (the first sync dropped, leaving data pages and meta page in one unsynced window) fails all four power tests on the "only the meta page" image.
2. Dirty pages written after the meta page, both before the final sync (the loop moved after `meta_write`): **not detected** in two seeds. The window between the meta write and the last data page is a few `pwrite`s, microseconds against a 12 ms commit; a kill almost never lands there. KV-T-0027's kill sweep catches it at every workload.
3. To show the checks can fail at all, the same bug with a real window: meta page, **sync**, then the dirty pages. **Detected at run 3 in both seeds**: "commit 21: tree_check: entry count does not match the snapshot" and "get counter: Corrupted".

So the real-kill test is a smoke test of the real path (process death, page cache, mmap, flock release), not a detector of ordering bugs; the sweeps are.

**Decisions.**
- A shared workload subpackage rather than a helper that checks itself: the test does all the checking, with the store's own checks, in the test process.
- The test refuses (fails) under `KV_NO_SYNC` rather than skipping, so a misconfigured run can't pass silently. The helper is built by the test without any `-define`, so it always has real syncs whatever the test binary was built with; it also refuses on its own.
- The helper is built with `-vet -strict-style` by the test, and checked by `scripts/test.sh` on every target.

**Deviations.** None from the criteria. Not through `scripts/test-linux.sh`: its third configuration sets `KV_NO_SYNC`, which the test refuses, so on Linux it is run with a direct `docker run` of the same image (in `CLAUDE.md`).

**Verification.** `scripts/test.sh`: debug 164, `-o:speed` 164, ASan 164, hooked/no-sync 183 tests, all pass (the kill test is not registered), and every cross-target check including `tests/killer`. `odin check tests -no-entry-point -vet -strict-style` with and without `-define:KV_KILL=true`. The kill test on macOS arm64 (four seeds) and in the Linux arm64 container, as above. No store bug found.
